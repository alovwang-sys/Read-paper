# Codex 原生连续对话

2026-10-19 开发增量，替代此前“每轮独立进程、必要时自动 fork”的 Codex 聊天策略。实现与证据见[本轮验收](../verification/native-continuity/README.md)。Claude Code、OpenCode、模型直连及整理卡片等独立任务继续沿用各自协议，不据此宣称具有相同能力。

## 对话与执行身份

一条 Papertrail Codex 对话固定绑定一个原生 `threadId`。现有字段 `nativeSessionId` 保存的就是这个线程 ID；进程或观察连接重新建立不代表新建线程。用户明确新建对话才开始独立上下文；普通追问、再次回答、改变本轮设置或移除待发送材料都不暗中换线程。外部 writer 占用时明确拒绝，保留输入和绑定，不自动 fork、抢占或重发。

| 身份 | 作用 |
| --- | --- |
| 工作区、研究、对话、连接 | 服务端联合计算 `managedKey`，隔离运行进程、映射和事件 |
| `requestId` | 本次提交及其持久运行记录；同 ID 重连只观察，不重复调用模型 |
| `nativeSessionId` / `threadId` | 原生整条聊天，跨轮保持 |
| `nativeTurnId` | 原生本轮执行，收到确认后保存到运行记录及研究请求归档 |
| `inputId` | “补充本轮”的稳定提交身份；映射到原生 `clientUserMessageId`，读回时保留 `clientId` / `clientUserMessageId` |
| `item.id` | 本轮文字、工具、计划和压缩活动的合并依据，避免重连重复显示 |

原生线程中的历史由 Codex 管理。正常续聊只编译新问题与新增或变化的材料，不重放已有历史正文；当前明确材料仍保存不可变快照。应用用 `historyRequestIds` 保留本地问答关联，避免每轮再嵌套保存全部历史。材料的证据 ID、内容版本、文档 hash 和页索引继续接受现有校验。

移除当前材料只改变后续提交，不能撤回原生线程已经看过的文字、工具结果或技能指令。Codex 输入区不再提供会造成隐式重建的历史范围选择；需要排除旧内容时明确新建干净对话。“再回答一次”和失败后的明确重试是在原线程继续一轮，旧回答及卡片来源仍保留。结果未知时先恢复核对，不开放盲目重发。

## 本机运行与观察连接

`server/codex-runtime.mjs` 持有每条活跃聊天的 App Server client，一次初始化后在同一线程启动多个 turn。正常结束保留 client；默认空闲十分钟回收自有进程，下次根据已保存的线程身份 resume。技能、模型、权限与交互回调逐轮重新绑定，不能把上一研究的授权回调带到下一请求。服务关闭会统一清理自己持有的 client。

`server/managed-runs.mjs` 保存提交意图、累计正文、item、交互、补充输入和终态。状态先落盘再发布。`POST /api/ai/agents/run` 的 `managed: true` 仅适用于 Codex 聊天；返回完整 snapshot 后继续发送带 `seq` 的事件。HTTP 断开只解除观察，不停止运行。

前端重连调用 `POST /api/ai/agents/observe`，先接收当前完整 snapshot，再消费后续事件；按序号与原生 item ID 合并。刷新、切换研究、切换面板或收起小窗不重新提交原问题。确认前断线也先核对原 `requestId`；无法确定是否接收时保存为 `unknown`，保留文字和输入，不能自动重发。重复观察数量与状态文件大小有保护上限。

恢复边界分开处理：

- 本机服务和原生进程仍活着：重新观察同一运行，等待中的审批或提问继续有效，已填写但未提交的答复与下一问草稿保留。
- 本机服务重启或意外失联：原活动记录转为待核对，通过原生 thread/turn、请求身份和研究归档对账。读到可信终态后恢复结果；不能确认则保持 `unknown`，不会重新执行问题或工具。
- 正常退出应用：沿用停止生成、等待原生确认及资料保存的关闭流程。没有新增常驻后台服务，也不承诺退出应用后继续生成。

Codex managed 聊天取消了旧的三分钟整轮计时；协议请求、连接检测和停止确认仍有各自超时及容量保护。其他助手与独立整理任务的超时规则不随之改变。

## 本轮补充与停止

生成期间可继续编辑下一问草稿；点击“补充本轮”才将当前文字发送到原生 `turn/steer`。它绑定确认过的 `expectedTurnId` 和稳定 `inputId`，使用本轮已提交的材料、模型、技能及权限，不把刚勾选的新材料一并发送，也不另开 turn。

服务先保存补充意图，再等待原生确认，确认后发布 `user-input`。同 ID 的已确认补充只返回确认；接收结果未知先读回原生 `clientUserMessageId` 对账，不重复追加。明确拒绝时保留草稿；等待确认期间新写的输入不被旧回执清空。读原生历史时，同一 turn 的后续 user message 归入该轮补充，不能伪装成另一条新请求。

停止先显示“正在停止”，由运行时请求 `turn/interrupt`，等待原生 `turn/completed` 的终态。原生确认 `interrupted` 后才显示已停止；完成与停止竞态以实际终态为准。默认五秒仍不能确认时返回 `stop_unconfirmed`，结束失联的自有连接并保留未知状态，不能声称已经停止。尚未发送 turn 的准备阶段可以直接取消；turn/start 已发出但响应丢失时按接收或停止未知处理。

## 消息、引用与历史

文字、命令、文件变更、已连接工具、网页搜索、计划与 `contextCompaction` 按原生顺序显示；审批、提问及补充输入记录在对应活动之后。item 完成事件校正增量文字，最终正文优先使用 `final_answer`，兼容无 phase 的旧模型，允许合法的无文字完成。原始 reasoning、stderr 和未知字段不进入页面；工具输出继续脱敏并限长。

连接状态与执行状态分开；连接重试不等同于模型失败。原生执行完成和论文来源校验也分开：引用暂不可验证时保留完整回答并提示，不能把已经完成的 turn 改成需重复运行。外部原生回答中的普通 Markdown 编号及链接不自动视作 Papertrail 证据，只有匹配真实材料才提供论文定位。

原生历史按 turn 读取并保留 turn ID、item ID、执行终态和用户请求身份。页面提供“加载更早对话”，通过服务端不透明 cursor 读取并按原生身份合并；不会因加载历史触发模型。显示容量保护优先保留同轮问题与回答的关联，截断明确标识；它不是完整原生日志备份，也不保证压缩前所有附件都能恢复。

原文旁小窗可以沿用研究当前选择的 Codex；“在右侧继续”继续同一产品对话及原生线程。Pi 对话仍为 Pi，切换连接不会把它伪装成既有 Codex 线程。新增动态工具是否能用于旧线程受实际注册能力限制，不能靠静默换线程规避。

## 本轮范围与后续

本轮仍启动用户已安装并登录的 Codex，使用现有原生登录、配置与会话存储；没有把 Codex 二进制加入安装包，没有独立账号授权界面，也没有复制用户的凭据目录。已只读核验官方 0.162.1 分平台 App Server package 及校验来源，实际捆绑、配套许可证、三平台签名与安装验收列为后续。

原生自动压缩事件已经接入状态与时间线；运行时另有手动 `thread/compact/start` 能力，但本轮没有向可恢复 HTTP 控制入口或用户界面开放手动压缩。真实验证覆盖直接调用运行时手动压缩后继续同一线程，不代表已触发或验证模型上下文阈值引起的自动压缩。

仍未完成：独立 Codex 桌面客户端双向交接、跨设备原生身份恢复、长时间多客户端共写、自动阈值压缩实测，以及完整原生客户端菜单复刻。来源草稿和知识入库继续要求人工确认。

协议依据：[官方 Codex App Server](https://learn.chatgpt.com/docs/app-server)。实际行为以本机 0.162.1 协议 schema、代码和本轮验收为准。

# Word 引用方案核对（2026-10-24，仅规划）

本轮实施 PDF 跨页选择与三项界面修复；Word 引用加载项不在本轮代码范围内。没有安装加载项，也没有进行 Windows／Mac Word 实机兼容测试。

## 现状与可行性

`PaperDocument` 已有稳定资料 ID、题名、作者字符串、年份字符串及 DOI／arXiv／URL；还缺结构化作者、文献类型、期刊／会议、卷期页码等完整引用字段。现有应用内证据编号用于回查 PDF，不能直接替代文稿级文献引用编号。仓库尚无 Office 加载项、CSL 处理器、RIS／BibTeX 导出。

Microsoft 官方提供 [Word 加载项引用管理示例](https://learn.microsoft.com/en-us/office/dev/add-ins/word/citation-management)，证明在光标处插入文献及随文档保留加载项状态的路线可行。该示例使用尾注，不等于已完成本项目所需的自动编号、去重和格式切换。CSL 官方列出了 [citeproc-js 等处理器](https://citationstyles.org/developers/)，可避免自写格式规则；实施前应固定实际采用的 CSL 样式、语言包、处理器版本并检查对应许可证。

## 最小完整闭环

1. **先补文献数据。** 作者保留姓名各部分及机构作者；题名、年份、类型、容器题名、卷期页码、DOI 可人工校对，保留来源。新字段兼容旧资料。去重合并保留旧文献 ID 的映射，已写进 Word 的标识不能因合并失效。
2. **建立窄的本机文献接口。** Word 加载项不能直接共享 Electron 的 IndexedDB，需显式连接 Papertrail 的文献库。只提供选择研究、搜索与读取文献所需的接口；沿用来源校验与授权，不为连接加载项放开任意跨域或文件读取。HTTPS、宿主网络限制和离线行为先做两平台探针。
3. **引用作为可更新的文档对象。** 使用经实际版本验证的 Word 内容控件／文档存储能力，区分文献 ID、每次引用 ID 与同一处引用的多个文献。随文件保存所需的 CSL 文献快照、页码等定位信息、格式、语言和记录版本；不保存登录凭据。打开文档时从文档内记录恢复，文献库离线仍可识别已有引用。
4. **按文档顺序刷新。** 枚举当前文档仍存在的引用，再一次性交给处理器更新编号及参考文献表；不能按引用创建时间或数据库顺序编号。同篇多次引用只列一条参考文献，页码属于本次引用。删除、移动和复制引用后可检测并刷新，遇到重复控件标识先修复身份，避免覆盖错误位置。
5. **完成第一版验收后再扩展交换格式。** GB/T 7714、APA、IEEE 用固定文献样例验证；RIS／BibTeX 作为单独导出能力，不能以按钮占位宣称完成。已有 Zotero 引用保留原状，迁移另做识别、备份和兼容测试。

## 验收门槛

用同一份测试文档分别在 Windows 与 Mac 的明确 Word 版本执行：搜索→同篇重复插入→多文献引用→添加页码→生成参考文献表→增删／移动／复制后刷新→三种格式切换→保存关闭→重新打开继续编辑。验证离线重开、文献合并后旧标识、文献库断开、正文中的手工改动及刷新失败后的恢复。API 能否使用按 [Word 官方平台文档](https://learn.microsoft.com/en-us/office/dev/add-ins/word/) 与实际 requirement sets 检测，不能从“支持 Word 加载项”推断全部版本一致。

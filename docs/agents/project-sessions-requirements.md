# 研究项目与原生会话互通需求

2026-10-17，第一版实现需求与后续验收边界。适用于 Read-paper、Codex、OpenCode 和 Claude Code。配套 [交互设计](project-sessions-ux.md)、[交互原型](project-sessions-prototype.html)和[实施计划](project-sessions-plan.md)。

研究者应当能围绕同一个本机研究目录，在阅读工作台和对应 Agent 的原生客户端中找到并继续同一段对话。研究项目提供资料、会话和产出的共同归属；切换软件时保留历史和来源，不必重新解释背景或复制聊天内容。

## 第一版交付与剩余目标

| 用户要完成的事 | 第一版已实现 | 仍需完成或实机验收 |

## 产品规则

### 研究目录

一个研究绑定一个本机根目录；绑定后聊天自动使用当前研究，用户无需在每次提问时再选项目。新研究可先开始整理，首次使用原生助手时补选目录。选择现有目录不移动、覆盖或扫描提交其中的全部文件。

服务端识别目录真实路径及稳定项目标识；显示名称变化不改变归属。首轮阻止同一目录重复绑定到两个研究，并在错误中说明已有归属；直接“打开已有研究”的快捷动作待补充。不同根目录下同名研究互不混淆；嵌套目录、Git worktree 不默认并入父项目，关联时展示实际范围。

目录暂时不可用时，已保存内容仍可查看、输入仍可编辑；暂停需要目录的发送与接续，提供“重新连接目录”。改绑另一目录不是修复失联；应创建新的归属，不偷偷迁移既有原生会话。

### 原生会话身份

每段会话绑定一个 Agent 和一个原生会话身份。Read-paper 内创建、原生端创建、外部新增消息均按该身份归并，列表中的标题相同不代表会话相同。用户点击历史只打开记录，不自动发送请求。

同一研究下允许 Codex、OpenCode、Claude Code 的多段会话。切换助手恢复该助手在当前研究的最近对话；首次使用进入新对话。原生会话不转换成其他 Agent 的会话，也不自动向另一家重放历史；跨助手引用材料沿用显式上下文入口。

已有模型直连和演示模式继续保留，其对话属于软件记录，不标记为 Codex 或其他 Agent 的原生会话，不承诺在对应原生客户端中继续。

只有用户明确新建、分支，或请求范围发生需要新原生上下文的改变时，才建立新的原生身份。范围改变须说明“将从所选范围开始新会话”，保留原记录与分支关系。卡片整理等内部任务不占据用户的阅读对话列表，其存储和可见性单独核验。

### 双向发现与继续

Read-paper 创建的会话需要在对应原生客户端中可定位、可继续。在运行时实际可发现的范围内，原生客户端在已绑定研究范围内创建的会话应进入本研究的“对话记录”，不要求逐条导入；提供来源、所属助手、最近更新时间和运行状态。Claude Code 首版读取其已知项目目录的本地记录；Desktop 独立列表与显式交接尚待实机验证，不显示已交接承诺。

打开“对话记录”和窗口重新获得焦点时刷新项目列表；当前会话在切入、重新获得焦点及本轮结束时读回，另有可见的“刷新记录”入口。只访问已绑定项目及当前会话，不遍历无关项目；不因刷新而触发模型或重执行工具。没有新内容时不弹通知、不跳滚动。

原生端可能采用独立的会话列表或需要显式交接。产品必须区分“本机记录已发现”“原生端可定位”“同一会话可继续”，逐项验收。未证明的能力显示具体状态，不以“已同步”概括。

### 历史与模型上下文

原生记录是原始对话历史的依据，Read-paper 保存显示缓存、来源关联和归档副本。拉取外部消息不制造第二条用户提交，也不再次执行其中的工具调用。消息使用原生标识去重，保留发生顺序、来源和不完整状态。

完整可查看历史与模型当前有效上下文分开表达。接续外部会话时，说明“包含原有对话上下文”，提供查看范围入口；不能因当前材料为空而宣称原生模型没有旧上下文。缺失的附件、压缩前记录或不支持的工具项原位说明，保留可恢复信息，不伪造原文和引用。

项目绑定只确定归属，不代表每次自动上传全目录。Read-paper 新增材料仍显式选择并冻结到请求快照。项目指令、技能、模型与权限按实际连接能力说明；改变工作目录后，需重新核实加载范围，不能继续沿用“只读临时材料”的旧声明。

### 原文与知识产出

本次发送材料有稳定文件、摘录、文档 ID/hash 和页索引记录，原生端能够找到该轮的材料说明。Read-paper 可识别的引用在中央 PDF 定位，右侧对话、输入和草稿保留；不能映射的外部引用保持可读并说明来源未关联。

论文、证据、卡片、白板和结论继续使用既有共享实体。外部对话可整理成独立卡片草稿，人工确认后入库；不自动覆盖已有卡片或结论。旧卡片依赖的对话与材料快照独立保存，不能因原生会话不可达而失去来源。

### 同时运行与异常恢复

会话在其他客户端运行时，可查看已获得的内容并保留输入；暂停本软件发送，说明“正在原生应用中运行”。切回空闲后先刷新，再允许续接。未知状态不标成空闲。Codex 经本机验证存在原生排他 writer 锁，可尝试原子 resume，锁被占用就拒绝发送；外部 OpenCode 和 Claude Code 的 unknown 会话保持只读。本软件创建并映射的会话保留已有续接能力，遇到已知 busy 一律禁发；这不代表已经证明其他独立进程空闲。

本软件的“停止”只作用于自己启动的当前请求。无法可靠确认跨客户端占用时，降级为“查看记录”和明确的新会话入口；不抢占原生任务，不自动排队或重复付费发送。停止无法确认时持久标记只读，刷新不会偷偷解除；保留记录和输入，用户可明确新建另一会话。请求超时而结果未知时先核对原生历史，再允许用户明确重发。

离线、未认证、版本不兼容、目录失联、历史加载失败各有就近原因与恢复动作。保留已经看到的消息、输入、草稿和阅读位置。操作失败不自动切换供应商。

### 保存与备份

第一版保留厂商原生存储方式：项目目录下 `.read-paper/project.json` 保存研究标识，`materials/<请求摘要>/` 保存每轮 `manifest.json` 与 `materials.md`，`request-*.json` 保存请求及完成结果，`conversation-*.json` 保存实际读取到的原生历史归档。请求/会话 JSON 采用临时文件加 rename 写入；归档失败会单独说明，不把读取成功冒充备份成功。认证仍由原生客户端或本机环境管理，不写入项目归档。

论文、区域图片、卡片、白板和结论仍以浏览器 IndexedDB 为业务数据来源，localStorage 仅作恢复缓冲；绑定目录不会自动搬动这些实体。原生会话与项目的索引 registry 仍在 `AI_AGENT_STATE_DIR` 下，未设置时沿用本机临时状态目录。因此只有 `.read-paper` 还不能恢复整个研究或全部原生映射。

后续完整备份须显式包含依赖的 PDF/图片资产、业务实体及索引恢复信息，列出缺失文件，并实际验证清理缓存后的恢复；P08 本轮未实现。可读归档能够保留所读取的文字与来源快照，不等于厂商原生恢复点，也不承诺换电脑后继续相同原生身份。

## 体验验收

| 编号 | 可观察的通过条件 |
| --- | --- |
| P01 | 绑定目录后，下次打开同一研究能恢复绑定；同名异目录及重复绑定可辨认，取消绑定操作不产生文件写入 |
| P02 | 在 Read-paper 发起对话，在对应原生客户端定位并继续；回到 Read-paper 看到外部新增内容，保持同一原生身份 |
| P03 | 在原生客户端为该研究新建会话，Read-paper 刷新后发现；重复刷新不产生重复会话或消息 |
| P04 | 切换 Agent、研究或对话后再返回，恢复各自输入、材料、历史与草稿；迟到响应归原会话 |
| P05 | 外部运行中不能从本软件抢发或停止；占用状态不可靠时可读但不能误标可接续 |
| P06 | 点击有效引用中央定位；历史与目录操作不替换论文、不清空未发送输入 |
| P07 | 目录失联、未登录和历史失败均可恢复；旧临时会话只读可查，没有被自动移动或删除 |
| P08 | 实际完成包含资料与可读历史的备份和恢复；分别报告原生恢复成功、只可查看或缺失内容 |

P02、P03、P05 必须对三种 Agent 分别实机验证。界面一致不等于能力已通过；未通过的连接按功能单独标记。

## 首轮范围与协议依据

首轮以本机单用户为边界，先打通目录归属、发现、读取、接续与来源保留，再完善备份和原生应用交接入口。跨设备实时同步、跨 Agent 会话转换、批量搬动原生记录和自动知识写入不在首轮。

[Codex App Server](https://learn.chatgpt.com/docs/app-server)提供按目录列出、读取和恢复原生线程的基础；[OpenCode V2 API](https://opencode.ai/v2/docs/api)提供会话发现、分页消息和同会话 prompt；[Claude Code 会话接口](https://code.claude.com/docs/en/agent-sdk/sessions)与[Desktop 交接](https://code.claude.com/docs/en/desktop#coming-from-the-cli)提供会话发现或续接基础。Claude Code 的 Desktop 与 CLI 列表有独立规则，不能据此承诺创建后所有列表自动出现。这里的 Claude 指 Claude Code 及支持其交接的 Code 视图，不包含普通 Claude 网页聊天记录。

以上协议依据与本轮探针一起界定可实现范围；真实模型回复及桌面客户端往返仍未完整验收。研究归属、底层记录物理位置和跨设备恢复是三个独立验收项。

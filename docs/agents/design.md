# 阅读工作台中的 AI 助手

2026-10-16，issue [#1](https://github.com/alovwang-sys/Read-paper/issues/1)。以 `origin/main` 的浏览器工作台为基线；桌面安装分支的功能不包含在本次开发中。

2026-10-17 已接入[研究项目与原生会话第一版](project-sessions-plan.md)：聊天 cwd 使用研究目录，每轮显式材料保存在项目内不可变快照；同一右栏读取三类助手原生历史。Codex 的接续由实测原生 writer 锁保护；OpenCode／Claude Code 外部未知占用记录只读，本软件已管理会话保留续接。目录、显示缓存和来源保全已有回归，真实问答与桌面列表的未验收项见[验证记录](../verification/project-sessions/README.md)。完整产品目标和后续范围见[需求](project-sessions-requirements.md)与[UX 设计](project-sessions-ux.md)。

## 产品决策

研究问题和证据是稳定的工作中心。AI 面板在输入区提供一个“切换 AI 助手”入口，列出 Codex、Claude Code、OpenCode，以及已有的模型直连和演示模式。列表显示安装/认证/就绪/错误、版本与实际能力。未连接也能选中查看原因，发送前必须就绪；连接失败不会自动换供应商。

根据用户最新修正，采用桌面应用的对话布局：用户消息靠右、助手完整 Markdown 回答靠左，工具过程以可展开的活动卡呈现，底部固定输入区和助手选择器。Codex 使用 App Server 的原生事件与会话；Claude Code、OpenCode 使用各自程序化运行协议。页面展示真实回复、工具命令、状态及有界输出，不将命令窗口作为聊天界面。

OpenCode 的模型选择延续用户本机配置或 TUI 最近选择；`OPENCODE_MODEL` 作为可选覆盖，解析到模型后显式传给非交互 `run`，避免其自行选择其他默认模型。继承范围只包含模型与 provider 连接配置，工具、MCP 和 agents 配置仍由工作台控制。探测不以 `auth list` 的人类标签匹配作为认证门槛，本地、环境凭据和自定义 provider 的可用性由实际请求确认。已有原生会话保留创建时的模型；改变本机默认选择后，新建干净对话才采用新模型。

这是阅读工作台内的统一桌面对话界面，没有嵌入各厂商的桌面窗口，也不承诺复刻它们全部菜单、权限和功能。未安装时提供对应运行组件的官方安装说明；已安装桌面应用不代表程序化运行组件已可用。应用不自动执行安装、登录或切换供应商。

AI 的回答引用、材料详情、草稿论文依据和相关对话引用，统一在中央最大 PDF 阅读区定位。右侧保留当前 AI 回答、输入、草稿和滚动位置，用于同屏对照；主区返回恢复原先的结论/白板。

中央资源标签与左栏共用 `Session.openItems / active / pinnedIds`，提供关闭、固定、拖动排序、方向键切换与 Alt+方向键排序。同一论文的不同证据复用标签及阅读器；返回已关闭的历史资源会恢复其标签。外部网页链接继续在浏览器打开；当前没有任意网页 iframe 或多窗格浏览器。

Codex 输入区从本机 App Server 读取模型与技能目录；`$` 搜索技能，选择后以芯片明确附加，最多四个。`/new`、`/skills`、`/model`、`/plan`、`/status` 是工作台动作，分别调用已实现的会话、目录、模型、原生 collaborationMode 和状态能力；没有实现的厂商命令不伪装执行。发送时冻结技能与模型/模式，重试沿用原快照；收缩技能范围开启新原生会话，避免旧技能指令留在历史。技能路径仅在服务端解析与重检，页面使用不透明 ID。纯本地插件技能通过连接级 `skills/extraRoots/set` 独立加载，不打开插件工具；依赖未接入外部工具或 MCP 的技能标明不可用。

TikHub 是已接入的外部技能：发现本机启用的 `tikhub` 及其 `scripts/tikhub.py` 后，检查 Python 3 和凭据是否可用。菜单不再因正文含 MCP 就禁用它；刷新能力按钮可重新检查本机状态。选中后，在原生 App Server 注册 `read_paper_tikhub` 动态工具，由服务端复用技能脚本，保留其 16 个平台、真实工具发现与输入 schema。默认不向模型开放凭据目录；动态工具不接受自定义服务 URL 或任意脚本。该脚本自己处理认证，参数经 stdin 传入，不修改全局 MCP 配置。

`platforms / check / tools / schema` 不触发数据调用审批；`call` 必须先在本回合获取精确工具 schema，再验证参数并在授权卡展示完整平台、工具及参数，批准后执行一次。当前每次数据调用均需授权，尚未按自然语言意图免除普通查询审批。每回合最多 8 次工具操作，服务错误后停止后续请求，取消等待自有进程退出；超大结果明确截断，未支持的复杂 schema 明确拒绝。原生 `dynamicToolCall` 输出进入活动卡而非回答正文；重复原生 callId 只执行一次。所选技能集合变化（包括新增）开启新原生会话，以正确注册工具，历史按原明确范围重放。其他未接入的外部技能仍显示具体限制。

切换随时可用。每个研究中的每段对话绑定一个助手，切到另一助手时恢复其最近未归档对话，没有时新建。原对话的历史、输入、材料、生成任务和草稿保留。首次切换只复制用户当前明确选择的材料，不重放旧问答、不自动发送；恢复已有对话使用它自己的材料与输入。需要对照不同助手时可在历史中返回各自记录。多 agent 自主协作和自动派单不在本次范围。

生成中可以切换助手，原回答继续记录在原研究/会话，历史标示运行中。停止在任务原会话执行。一个原生 session 同时只执行一个请求；冲突返回明确状态，不自动排队收费。新建干净对话保留当前助手，清空本次材料与历史。关闭面板或切换研究不改变任务归属。

## 材料、历史与能力

发送前显示本轮材料，折叠的“对话范围”摘要显示前序轮数及原生累计材料数；展开后设置范围并核查历史全文。移除本轮材料不会抹去原生历史。选择“仅当前材料”、缩小原生累计材料范围、重试或重新生成时，服务开启新的原生 session，仅编译本次明确范围。旧 session 与来源记录保留，不宣称模型已遗忘。

当前接入以文字研究为切片：将明确的证据和允许的问答编译为 UTF-8 材料与 manifest，不把整库、PDF、密钥或其他项目目录交给 agent。区域图片继续通过已有支持图片的模型直连处理，本机助手入口提示能力限制。

默认只读权限由运行时的实际策略实施。普通工作目录和快照文件不构成操作系统沙箱。Codex 聊天仅默认读取材料和明确选择的技能目录；原生命令/文件审批、额外权限和结构化问题显示交互卡，由用户单次答复后继续。额外权限最细为原生 `turn` 范围，界面明确说明；不提供持久授权。未支持或不能完整展示的请求拒绝。等待用户时暂停生成超时；回应绑定原请求全部身份，只接受一次；停止、断连或刷新后旧交互失效。卡片整理和修订维持无交互的独立只读任务。Claude/OpenCode 继续只对话，工具与授权关闭。不同运行时能力及限制见验收记录。

执行状态与正文分开：工具和权限事件进入可展开的进度记录，stderr 不进入回答。回答继续经过应用引用校验；无效引用可读但不能作为有效来源存卡。整理和修订使用独立的原生任务，模型只生成草稿，人工确认后由共享服务幂等建卡。卡片保留原论文、原对话及助手身份。

## 项目范围契约（需求 #2 的 B0 最小前置）

| 标识 | 含义与归属 |
| --- | --- |
| `agentWorkspaceId` | 当前浏览器工作区首次使用本机助手时创建的稳定随机 ID，避免不同浏览器样例 ID 相同而复用原生历史 |
| `researchId` | 项目归属；全局库与其他研究必须经共享资料关联后显式选择 |
| `conversationId` | 应用会话；绑定一个 `connectionId`，保存输入、历史范围及材料 |
| `connectionId` | `model / demo / codex / claude / opencode`；安装与凭据全局管理，不属于研究资料 |
| `requestId` | 单次尝试，冻结提交时的证据与历史；重试另建 ID 并保留 `retryOf` |
| `nativeSessionId` | 由本机服务创建和恢复；映射按工作区、研究、会话、连接隔离；不接受页面指定任意原生 session |
| `ContextSnapshot` | 沿用证据 ID、文档 ID/hash、0 起始页索引、摘录；仅可引用本次存在且版本匹配的证据 |

权威知识仍在 IndexedDB。新增身份、会话映射和事件均为 schema 2 的可选增量字段，旧记录按既有模型/演示语义读取；不重建资料或删除编辑缓冲。未知连接导致明确的恢复错误，保留原数据。服务端映射和快照不充当第二份知识库；服务重启恢复本服务保存的映射，不能接管其他桌面窗口中的任务。

## 交互与布局验收

沿用统一三栏、单一右侧面板，助手选择器在输入区上方展开且支持键盘与 Escape。菜单不遮断发送状态；未连接说明提供重新检测入口。1440×900、1280×800、1024×800 均检查中央 PDF＋右侧 AI 并列；从 1024px 开始右栏参与布局，避免覆盖论文，低于 1024px 才使用覆盖抽屉。桌面 AI 面板默认至少约 420px，中央保留至少约 560px；用户仍可调整面板宽度。结论＋AI 和白板＋原文继续复用现有宿主。

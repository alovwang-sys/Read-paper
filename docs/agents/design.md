2026-10-19 的[原生连续对话增量](native-continuity.md)已接入：同产品对话保持同一 Codex thread，本机服务持有运行，页面断流或刷新只恢复观察。当前开发分支尚未发布，仍使用用户已安装并登录的 CLI，未捆绑运行时或接入独立登录。真实三轮同线程、断流观察恢复与直接运行时手动压缩后记忆保持见[本轮验收](../verification/native-continuity/README.md)；自动阈值压缩和独立客户端双向交接未验收。

## 产品决策

研究问题和证据是稳定的工作中心。AI 面板在输入区提供一个“切换 AI 助手”入口，列出 Codex、Claude Code、OpenCode，以及已有的模型直连和演示模式。列表显示安装/认证/就绪/错误、版本与实际能力。未连接也能选中查看原因，发送前必须就绪；连接失败不会自动换供应商。

根据用户最新修正，采用桌面应用的对话布局：用户消息靠右、助手完整 Markdown 回答靠左，工具过程以可展开的活动卡呈现，底部固定输入区和助手选择器。Codex 使用 App Server 的原生事件与会话；Claude Code、OpenCode 使用各自程序化运行协议。页面展示真实回复、工具命令、状态及有界输出，不将命令窗口作为聊天界面。

输入区保留材料“＋”、访问权限、技能、Chat/Plan、模型、推理强度、麦克风和发送／停止，420px 右栏按两行排列；截图中带黄点的额外图标按用户要求暂不添加。添加材料沿用研究证据和 PDF 导入，显式选取后才加入本轮；不自动提交或读取整个目录。

模型及推理档位使用本机 `model/list` 的返回值，切换模型采用新模型默认档位，不保留不支持的 Ultra。只读与完全访问按原生权限能力显示；完全访问必须明确确认，仅作用于当前对话后续提交，不修改用户全局配置。请求冻结实际模型、effort、模式与权限，重试保留原快照。项目内写入因尚未验证材料与技能目录的保护边界，暂不展示。完全访问允许原生 Agent 在项目外修改文件及联网，界面持续显示当前范围。

麦克风目前提供系统听写说明并聚焦草稿，不自动发送；没有接入内置录音转写，不用 Electron 的不可靠 Web Speech 或会触发对话的 Codex realtime 冒充听写。文件更改汇总来自本轮原生 diff 事件，可展开脱敏节选；它不是整个工作树的 Git 扫描。完整桌面宿主功能与原生客户端全部菜单仍按能力分别验证。

OpenCode 的模型选择延续用户本机配置或 TUI 最近选择；`OPENCODE_MODEL` 作为可选覆盖，解析到模型后显式传给非交互 `run`，避免其自行选择其他默认模型。继承范围只包含模型与 provider 连接配置，工具、MCP 和 agents 配置仍由工作台控制。探测不以 `auth list` 的人类标签匹配作为认证门槛，本地、环境凭据和自定义 provider 的可用性由实际请求确认。已有原生会话保留创建时的模型；改变本机默认选择后，新建干净对话才采用新模型。

这是阅读工作台内的统一桌面对话界面，没有嵌入各厂商的桌面窗口，也不承诺复刻它们全部菜单、权限和功能。未安装时提供对应运行组件的官方安装说明；已安装桌面应用不代表程序化运行组件已可用。应用不自动执行安装、登录或切换供应商。

AI 的回答引用、材料详情、草稿论文依据和相关对话引用，统一在中央最大 PDF 阅读区定位。右侧保留当前 AI 回答、输入、草稿和滚动位置，用于同屏对照；主区返回恢复原先的结论/白板。

中央资源标签与左栏共用 `Session.openItems / active / pinnedIds`，提供关闭、固定、拖动排序、方向键切换与 Alt+方向键排序。同一论文的不同证据复用标签及阅读器；返回已关闭的历史资源会恢复其标签。外部网页链接继续在浏览器打开；当前没有任意网页 iframe 或多窗格浏览器。

Codex 输入区从本机 App Server 读取模型与技能目录；`$` 搜索技能，选择后以芯片明确附加，最多四个。`/new`、`/skills`、`/model`、`/plan`、`/status` 是工作台动作，分别调用已实现的会话、目录、模型、原生 collaborationMode 和状态能力；没有实现的厂商命令不伪装执行。提交冻结技能与模型/模式；后续改变设置仍续接同一线程，不能声称收缩技能就能删除原生历史中的旧指令。需要独立范围时明确新建对话。技能路径仅在服务端解析与重检，页面使用不透明 ID。纯本地插件技能通过连接级 `skills/extraRoots/set` 独立加载，不打开插件工具；动态工具受线程注册能力限制，未连接外部工具或 MCP 的技能标明不可用。

TikHub 是已接入的外部技能：发现本机启用的 `tikhub` 及其 `scripts/tikhub.py` 后，检查 Python 3 和凭据是否可用。菜单不再因正文含 MCP 就禁用它；刷新能力按钮可重新检查本机状态。选中后，在原生 App Server 注册 `read_paper_tikhub` 动态工具，由服务端复用技能脚本，保留其 16 个平台、真实工具发现与输入 schema。默认不向模型开放凭据目录；动态工具不接受自定义服务 URL 或任意脚本。该脚本自己处理认证，参数经 stdin 传入，不修改全局 MCP 配置。

`platforms / check / tools / schema` 不触发数据调用审批；`call` 必须先在本回合获取精确工具 schema，再验证参数并在授权卡展示完整平台、工具及参数，批准后执行一次。当前每次数据调用均需授权，尚未按自然语言意图免除普通查询审批。每回合最多 8 次工具操作，服务错误后停止后续请求，取消等待自有进程退出；超大结果明确截断，未支持的复杂 schema 明确拒绝。原生 `dynamicToolCall` 输出进入活动卡而非回答正文；重复原生 callId 只执行一次。工具只在所选技能和本轮回调明确允许时执行，不能因改变技能而静默换线程；旧线程新增动态工具的支持范围须按实际原生注册能力验证。其他未接入的外部技能仍显示具体限制。

切换随时可用。每个研究中的每段对话绑定一个助手，切到另一助手时恢复其最近未归档对话，没有时新建。原对话的历史、输入、材料、生成任务和草稿保留。首次切换只复制用户当前明确选择的材料，不重放旧问答、不自动发送；恢复已有对话使用它自己的材料与输入。需要对照不同助手时可在历史中返回各自记录。多 agent 自主协作和自动派单不在本次范围。

生成中可以切换助手，原回答继续记录在原研究/会话，历史标示运行中。Codex 的执行由本机服务管理，刷新、断流或关闭面板只解除观察；恢复时订阅同一运行记录。停止在任务原会话执行并等待原生确认；结果未知保持核对状态。一个原生线程同时只执行一个请求；占用不自动 fork、排队或收费重发。新建干净对话保留当前助手，清空本次材料与历史。关闭面板或切换研究不改变任务归属。

## 材料、历史与能力

发送前显示本轮材料和原生累计材料说明。Codex 始终续接同一线程；正常续聊只发送新问题与新增或变化的材料，移除本轮材料不会抹去原生历史。Codex “再回答一次”及明确重试是在原线程新增一轮，不再以“仅当前材料”或历史范围选择隐式创建另一条原生线程；要排除旧历史须新建干净对话。其他连接继续保留原有显式范围选择，旧记录与来源保留。

明确选择的文字证据编译为 UTF-8 材料与 manifest，保留证据、文档和页索引；没有自动提交整库、密钥或其他研究目录。Codex 另支持已明确提供图像能力的模型接收 PDF 区域图片；其他本机助手仍按各自实际图像能力提示，不把文字描述当作图片已发送。

默认只读权限由运行时的实际策略实施。普通工作目录和快照文件不构成操作系统沙箱。Codex 默认可读取已授权的研究根目录、本轮材料与所选技能目录；材料发送仍须显式选择，不能把目录可读说成已经上传整个目录。原生命令/文件审批、额外权限和结构化问题显示交互卡，由用户单次答复后继续。额外权限最细为原生 turn 范围，不提供持久授权；未支持或不能完整展示的请求拒绝。Codex managed 回合的审批及问题由服务保留，页面断流或刷新后重新观察并继续答复；停止、原生终态或服务重启后的失效交互不重放。其他连接与独立任务沿用原有交互/超时规则。卡片整理和修订维持无交互的独立只读任务。Claude/OpenCode 继续只对话，工具与授权关闭。

执行状态、连接状态与来源有效性分开：文字、工具、计划、压缩、审批和提问按原生顺序进入时间线，stderr 与原始 reasoning 不进入回答；完成 item 校正增量正文，最终正文优先 final_answer，允许合法无文字完成。已完成 turn 的引用暂不可验证时保留回答并提示，不改成生成失败或要求重做；外部普通编号不自动当论文引用。整理和修订使用独立原生任务，模型只生成草稿，人工确认后由共享服务幂等建卡。卡片保留原论文、原对话、补充本轮文字及助手身份。

## 项目范围契约（需求 #2 的 B0 最小前置）

| 标识 | 含义与归属 |
| --- | --- |
| `agentWorkspaceId` | 当前浏览器工作区首次使用本机助手时创建的稳定随机 ID，避免不同浏览器样例 ID 相同而复用原生历史 |
| `researchId` | 项目归属；全局库与其他研究必须经共享资料关联后显式选择 |
| `conversationId` | 应用会话；绑定一个 `connectionId`，保存输入、历史范围及材料 |
| `connectionId` | `model / demo / codex / claude / opencode`；安装与凭据全局管理，不属于研究资料 |
| `requestId` | 单次尝试，冻结提交时的证据与设置；Codex managed 持久记录及重复观察复用此 ID，明确重试另建 ID 并保留 `retryOf` |
| `nativeSessionId` | 由本机服务创建和恢复；Codex 保存固定 threadId，映射按工作区、研究、会话、连接隔离；不接受页面指定任意原生线程 |
| `nativeTurnId` / `inputId` | 原生一次执行及其本轮补充身份；停止、交互、steer 与恢复均核对对应身份 |
| `ContextSnapshot` | 沿用证据 ID、文档 ID/hash、0 起始页索引、摘录；仅可引用本次存在且版本匹配的证据 |

权威知识仍在 IndexedDB。新增身份、会话映射及 nativeRun 均沿用现有 schema 的可选增量字段，旧记录迁移保留内容与草稿，不重建资料。Codex 新请求使用本地 historyRequestIds 关联而非嵌套复制全部旧正文；旧快照仍供显示与溯源。服务端映射、持久运行记录和材料快照不充当第二份知识库；服务重启先读原生终态对账，无法确认时保留 unknown，不接管其他桌面窗口中的任务，不自动重发。

## 交互与布局验收

沿用统一三栏、单一右侧面板，助手选择器在输入区上方展开且支持键盘与 Escape。菜单不遮断发送状态；未连接说明提供重新检测入口。1440×900、1280×800、1024×800 均检查中央 PDF＋右侧 AI 并列；从 1024px 开始右栏参与布局，避免覆盖论文，低于 1024px 才使用覆盖抽屉。桌面 AI 面板默认至少约 420px，中央保留至少约 560px；用户仍可调整面板宽度。结论＋AI 和白板＋原文继续复用现有宿主。

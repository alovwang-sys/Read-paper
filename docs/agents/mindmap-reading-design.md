# 阅读、摘录与研究导图：MarginNote 参考方案

2026-10-20。状态：首轮源码实现已接通，安装版仍保留 0.1.10 基线。依据 MarginNote 4 官方手册、当前代码和 0.1.10 验收截图形成；没有把文档研究当作原生 MarginNote 实机验收。

## 要解决的问题

设计基线中的白板已支持曲线、人工移动、编辑、来源定位和历史恢复，但卡片主要以同等大小的正文块呈现。摆放只有坐标和分组，连线没有独立的父子结构，因此用户仍难快速辨认主问题、子主题、材料与跨主题关系。仅增加曲率、颜色或不同图标不足以解决这个问题。

下一步围绕一条完整路径设计：阅读原文 → 保留摘录 → 写下自己的理解 → 放入研究分支 → 调整顺序或归属 → 按需查看细节和原文。人工操作先完整成立，再让 Agent 提供结构建议。

## 用户补充：先证明 AI 能形成这些内容

2026-10-20 用户明确质疑：AI 是否只会整理已有资料，示意里的“方法整理”“评估计划”等主题能否由 AI 实际产生；复杂图是否真能完成。后续设计必须保留这项要求，不能用手工写好的原型节点代替生成能力证据。

- AI 整理包括提炼主题、概括方法、提出比较维度、建议评估步骤、发现材料缺口和形成待验证问题；不局限于移动资料或换分组名。
- “方法整理”“评估计划”是上轮示意的例子，不是每张研究图的必选模板。应依据用户目标和已选材料决定结构；不足时允许提出有用的方案或问题，并标明建议，不能杜撰实验、文献和结论。
- 材料明确说明、基于材料的推断、尚待验证的建议须可区分。有出处不等于整个节点的推断都获得原文支持；新增建议可以没有引用，不能装成资料事实。
- Skill 告诉助手如何理解任务和输出方案；页面实际支持的对象、关系和操作由代码实现。把 Skill 交给 Agent 不会自动增加父子层级、折叠或任意复杂排版。
- 在投入更多视觉功能前，先用真实 AI 完成一次有分支、跨主题关系、方法和验证建议的测试；保存实际输入、原始输出、模型和回合、解析结果、页面回放以及发现的缺口。测试图不得预先手工填写成答案。
- 分开验收“新建内容”和“补充已有图”。原基线中新建可起草新卡，既有图整理只准引用已有对象；本轮通过显式补卡授权扩展，不能仅改提示词绕过代码限制。
- 不以短的整轮计时判定生成失败。等待原生回合结束；连接状态不明时报告待核对，不能冒充模型能力失败或自动重复请求。

这项能力验证应先于下面 M1–M3 的扩展实施；M3 指产品中的结构提案集成，不意味着到最后才验证 AI 能否生成有意义的研究内容。

同日[真实生成与页面回放](../verification/board-reasoning/README.md)已完成：一次 Codex 请求在 167.561 秒完成 18 张卡片、27 条连线，确实提出方法比较与具体评估计划；生产解析、引用范围及人工内容复核通过。复杂展示未通过，存在分组重叠、关系穿卡、总览文字过小。该结果支持继续建设结构与布局能力，不代表已有图补卡或普通短句下的自适应整理已验证。

## 一个用户可以自己完成的过程

1. 在 PDF 选中原文，先保存为摘录。菜单提供“添加到白板…”；只有用户明确选择白板及分支后才放入。不把每次高亮自动铺满画布，不自动送入 AI。
2. 添加时显示可辨认的对象：原文摘录保留引文和出处，自己的理解写在卡片正文。需要纯结构标题时先复用普通卡片，避免另建一套内容实体。
3. 选中一个分支后，通过“添加子节点”加入新的理解；通过“添加同级节点”继续列要点。长正文在右侧写，画布保留标题、短摘要和来源入口。
4. 在大纲中上移或下移，同一分支在图上的顺序同步；也能把一整枝移动到另一父节点。跨支语义关系不随排版被改写。
5. 点分支旁的折叠控件，显示隐藏节点数；展开恢复。选中父节点不等于默认选中整枝，整枝操作须有明确命令和选区反馈。
6. 点卡片来源在右侧定位原文；多来源先列可选出处，不静默选择第一条。关闭参考后保留图的位置与选择。无来源的自写观点显示“未关联原文”，不用空页码伪装证据。
7. 用户要求 AI 整理时，展示拟改的父级、顺序和新增关系；确认后应用。普通问答不自动换成画图，生成结果在消息内有预览和打开入口。

## 层级和视觉规则

| 对象 | 展示与行为 |
| --- | --- |
| 研究主问题 | 一份清晰标题，适度强调字号与留白；不重复展示与所有节点相同的类型栏和空来源栏 |
| 主题分支 | 分支名、展开/收起控件和子节点数；共同的对齐、间距和少量稳定色彩帮助识别归属 |
| 具体卡片 | 总览仅标题及必要状态；摘要最多两三行。长标题可换行，完整文本通过详情可见，不靠缩小字号塞下全文 |
| 父子线 | 细的连续曲线，通常无箭头和重复“包含”标签；从真实节点边缘出发，子节点围绕父级有一致方向和间距 |
| 跨分支关联 | 与父子线可辨别的线型、明确标签，必要时显示方向。可暂时隐藏，选中节点时突出相关关系；颜色不单独承担含义 |
| 来源和批注 | 原文摘录用引文语义，个人观点用笔记语义，待查问题用问题语义。图标表达类别，同类保持一致；不要每张卡随机换一个图标 |
| 选中状态 | 只突出当前节点及其相关结构，避免每张卡都有强边框、完整工具条和高饱和背景 |

分支颜色表示组织归属，不表示论点已被证实。AI 草稿、待核查与原文来源状态必须独立表达。正文既含摘录又含想法时保留两者的边界，不能凭图标把整张卡误称为原始证据。

总览、摘要是用户主动切换的阅读密度。首轮不在滚轮缩放时自动更改卡片高度，以免节点跳动打断查找。后续只有在焦点和视口稳定性验证后才考虑随缩放切换细节。

## 手动操作优先的约定

- 自由布局中拖卡始终只改坐标；靠近另一张卡不能自动变成子节点。
- 层级整理中拖分支重排，必须显示“排在某项之前/之后”或“移入某分支”。父级变化有明确目标提示；菜单可完成同等操作。
- 不采用“再次拖到一起就合并正文”。正文合并若以后建设，必须为独立动作，并说明共享影响。
- 移出父节点时默认只移出当前摆放，子节点提升到原父节点下并保留相对顺序；明确选择“移出整枝”才移出后代。影响数量先可见，布局历史可恢复；两者都保留共享卡片。
- 不允许节点移入自己的后代；显示无法放置原因，不产生部分改动。
- 折叠是查看状态，不删除后代，不生成正文/结构版本，也不使生成中的内容提案过期。隐藏节点有跨枝关系时显示数量入口；不能把这些关系静默改接父节点。
- 搜索命中隐藏节点时，展开其祖先并定位。离开及刷新恢复当前白板的展开状态、选择与视口。
- 普通整理保留人工选择；需要重新排版已有布局时先预览。迟到提案不得覆盖用户后续调整。

## 与现有模型衔接

继续保留 `Evidence → Card → BoardPlacement`。证据保存文档、页码与摘录，卡片正文可复用，同一卡片在不同白板上的归属、顺序与坐标各自独立。

建议在 `BoardPlacement` 加可选 `parentPlacementId` 与同级 `order`，根节点也有顺序；父子线由这个结构派生。`BoardEdge` 保留跨节点关系和自由说明，第一阶段不因视觉需求扩展成庞大关系类型系统。大纲不存第二份树。

旧白板缺少这些字段时继续自由布局，不通过旧连线、相邻坐标或 group 文本猜测父子结构。层级整理使用独立的明确入口，在预览确认后保存。树的排版只读取父子结构，不能复用目前把所有语义边都参与拓扑分层的 flow 行为来猜分类。

改动必须同时覆盖共享写入、导入、导出、备份、快照、版本比较、恢复副本和 AI 方案解析。父节点须存在且属于同一白板，无自身引用或祖先环；副本恢复重映射父节点 ID。顺序校验及确定性兜底由共享服务负责。折叠复用现有窗格 `viewState`。

## 最小交付顺序与验收

| 批次 | 完整用户路径 | 必须验证 |
| --- | --- | --- |
| M1 人工层级 | 建父子分支 → 大纲调序 → 整枝换父级 → 折叠 → 刷新恢复 | 共享卡片不复制；无祖先环；旧自由白板保持原样；多白板/研究隔离；操作失败不丢内容；版本和备份能往返 |
| M2 表达和回源 | 层级曲线与紧凑节点 → 关联按需显示 → 多来源选择 → 右侧原文 → 返回 | 1440×900、1280×800、1024 抽屉；真实尺寸与变长标题；第三节点避障；隐藏关联计数；键盘可操作；原文和图位置保持 |
| M3 Agent 建议 | 请求整理 → 预览父级/顺序差异 → 确认应用 → 人工修改 → 恢复 | 任一旧结构变化须确认；迟到结果拒绝覆盖；折叠不造成假冲突；只使用显式材料；真实调用与模拟分开记录 |

首轮不纳入十种样式、手写引擎、多层子脑图、跨研究知识图谱和自动合并正文。先完成一条人工可控的研究整理路径。

## 2026-10-20 首轮实现

用户确认实施后，先以 `7f55041` 提交此前完成的代码，再实现以下路径。下文“本轮交付边界”保留为原调研阶段说明；当前实现以本节和[实际验收](../verification/tree-board/README.md)为准。

- M1：显式转换预览后进入层级整理；大纲调序、调整父级、提升一级、添加子/同级节点、整枝选择与移出。普通移出提升子节点；共享卡片保留，撤销恢复完整布局。树中通过大纲控件调整，尚未建设拖放分支手势。
- M2：标题/摘要两档密度、根与分支强调、无箭头的父子曲线、可切换的语义关系及第三卡避障。点击节点只选择，编辑打开现有右侧卡片；多来源先选择。折叠、搜索展开、选择与视口按窗格保存；1024px 大纲使用抽屉。
- 当前图标只表示实际对象及结构角色：根主题、分支主题、具体卡片、原始文献；待核查单独标注。不从正文首句“依据”推断整张卡已证实。原文摘录等更细类别需明确数据支持后再展示。
- M3：已有图明确允许补卡时，AI 可生成方法、计划和待验证问题；原文引用仍只取本轮显式材料，旧卡正文不改。父级、顺序、标题、布局或新增草稿须确认；折叠不造成版本冲突。历史副本重映射父节点，导入/备份拒绝非法父级与循环。
- 真实 Codex 单次既有图补充请求在 157.309 秒完成：3 旧卡保留身份、父级、顺序与分组，增加 8 草稿，得到 11 节点、10 父子关系、6 语义关系。自然短句未规定节点数或布局；单一合成案例不等于通用可靠性。

未实现手写、节点附属批注、PDF 摘录直接选择目标分支、跟随选中项自动回源或任意复杂图的自动排版。旧自由图不自动转为树；重叠分组背景改为节点标签以免误标，坐标保留。

## 原调研阶段交付边界

此前调研轮提供官方行为调研、现有模型缺口分析和可交互的方案示意。示意中的内容与来源均为演示数据；分支收起、大纲调序、来源切换及关联显示是原型交互，不代表安装版已经拥有这些能力。生产源码、真实研究数据和安装包不在当时改动范围内；本次源码交付以[树形白板验收](../verification/tree-board/README.md)为准。

原型已通过本地交互检查：折叠/展开、节点选择、查看原文及返回、大纲同级调序后导图同步、关联线开关。检查了 1024、736、320px 和深色外观，未发现节点重叠、横向溢出或运行错误；桌面和窄屏截图已人工查看。这些结果仅针对方案示意，不替代 M1–M3 的产品验收。

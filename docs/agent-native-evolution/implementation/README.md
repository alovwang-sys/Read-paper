## 已接入的路径

- 左侧以研究、最近内容和资料浏览为主；全局查找覆盖论文、卡片、白板与文稿。
- 研究主区复用现有 PDF、卡片、白板和文稿编辑器；中间默认显示当前会话的完整多轮过程，底部只有一个明确绑定当前会话的输入，右侧按需打开会话列表。打开共享成果或原文后，可从顶栏返回会话。新研究直接进入输入，不要求先关联文件夹。
- 一句委托后，Codex 自行调用资料目录、逐页阅读、提交研究成果三个应用工具。通过校验的成果自动保存为现有文稿实体，引用保存为现有证据实体，可直接编辑、核查来源和导出 Markdown。
- 显式“围绕这里追问”确定局部对象；浏览原文不改变已准备的问题。修改现有文稿先提出建议，采用时检查原版本；撤销保护采用后的人工修改。
- 停止、失败和页面刷新保留已有内容。完成结果归提交时的研究和会话，切换研究、话题或阅读原文时不抢主区；新成果通过对应轮次的入口打开。

经典工作台继续提供原有导入、题录与资料库、摘录、卡片、两种白板、局部文献搜索与收录、文稿导出、完整原生会话和连接设置。新旧界面读写同一批实体，没有复制新库或删除旧功能。旧 PDF 的“加入当前对话／解释这段”、旧白板局部研究、文献搜索和对话来源仍由经典 AI 面板承接；从新版触发这些动作时会明确切到经典工作台并保留原局部材料，不把未桥接的动作显示成已经由新研究输入处理。

## 能连接什么

| 连接 | 第一版新增研究工具 | 现有路径 |
| --- | --- | --- |
| 本机 Codex | 已接目录、读页、引用草稿；需本机 CLI 已安装且登录就绪 | 经典工作台保留原生会话续接、模型、技能、Plan 和已有审批 |

| OpenCode | 尚未接应用研究工具 | 原有连接继续保留 |
| 模型直连 | 尚未接这套工具 | 原有模型问答和证据卡片流程保留 |

资料与保存由应用负责，工具循环由实际运行时负责。项目不要求使用独占的“自家 Agent”；其他运行时要接入相同资料工具并逐项验证，不能只更换模型名称就宣称能力相同。

Codex 使用官方 app-server，复用真实运行时的工具循环与流式输出。这符合官方建议的嵌入方式，但页面属于 Papertrail；不是将 Codex 桌面端 UI、所有插件和设置原样嵌入。[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Codex as a platform](https://developers.openai.com/blog/codex-as-a-platform)

每轮研究创建临时、隔离的原生线程；连续性来自应用显式附送的已完成研究历史，不能称为续接用户在 Codex 客户端打开的任意会话。研究线程不写入普通会话历史，研究过程仍保存在应用本地记录中。当前研究运行关闭 shell、技能和其他 MCP；原生会话路径保留在经典工作台。

Claude Code 官方支持通过程序接口和 MCP 工具集成，所以以后可以使用其原生工具循环。这版保留文字连接，并未声称完成相同研究能力。[程序化使用](https://code.claude.com/docs/en/headless)、[MCP 工具集成](https://code.claude.com/docs/en/mcp)

## 本轮上下文边界

提交时授权当前研究的资料快照，由 Agent 按需取回页面；不是把全部原文直接拼进问题。明确追问的文献优先，其余按研究资料顺序，最多八份；每份最多前 24 页，每页最多 12,000 字符，总计 160,000 字符。范围与截断情况可以从本轮回执查看，实际读了哪些页在对话记录中保存。

跨研究或未关联的全局资料不读取；局部目标不扩大文献授权。只附送当前会话最近六轮内、总计不超过 12,000 字符的已完成研究历史，不混入其他话题；局部对象正文最多前 12,000 字符。缺全文、扫描件无文字、超出预算或准备失败都明确保留缺口。第一版不联网搜索或自动获取全文；旧白板的手动 OpenAlex 搜索与收录继续可用。

引用要求文档与 hash 匹配、页码有效、原句属于 Agent 实际读过的页面，正文编号不能越界；浏览器在保存前再校验资产与来源。原句匹配只证明文字定位，不证明语义支持关系或论文结论正确，初稿仍需阅读核查。

## 验证和仍未交付的部分

真实 Codex 工具冒烟使用两篇明确标注的合成文献，实际调用三种工具并形成双引用草稿，见 [codex-smoke.json](codex-smoke.json)。追加的真实 Claude Code 集成评审见[输入](claude-integration-review-input.md)与[回复](claude-integration-review-response.md)。我们采纳了能力分级、覆盖范围、会话边界与旧功能可达性；未采纳“原句匹配就标已核验”的建议。

另已完成[真实浏览器全链路](browser-live.json)：PDF.js 提取两份有文字的合成 PDF，真实 Codex 按需读取两页并生成双引用文稿，保存证据和文稿后刷新恢复成功，页面无 JavaScript 错误；扫描件与无全文条目明确保留缺口。这次默认模型 `gpt-6.1-sol` 的浏览器研究耗时约 140 秒，属于单次测量，不能当作速度保证。[实际画面](screenshots/live-result-1440.png)和[可重跑脚本](verify-live.mjs)分别保留。首次尝试因未启动 Vite 失败的记录另存为 `browser-live-attempt1-failure.json`；启动后只重跑一次成功。

构建、429 项单元检查、211 项服务端检查、16 项桌面协议／存储检查与 3 条浏览器集成路径均通过，窗口尺寸覆盖 1440×900、1280×800、1024×800。最终检查与截图见 [checks.json](checks.json)。受控浏览器检查另用模拟模型事件流验证修改冲突、停止、迟到结果和三种窗口尺寸；这些检查与真实模型验证分别记录，不能替代真实论文研究质量验收。

本轮没有完整合并卡片画布与 Excalidraw，也没有改写全部阅读、写作工具栏。旧内容和模式保持可达。没有宣称 Claude/OpenCode/模型直连拥有同等研究工具，没有完成 OCR、后台继续运行或真实用户可用性研究；刷新会将未完成运行标为中断，需要明确重试。

# 研究工作台界面与交互方案

日期：2026 年 10 月 21 日。状态：追加讨论后的完整界面提案；已有[第一版实现](implementation/README.md)，其中完整混合画布等尚未交付。以下内容仍包含后续设计要求，不代表正式应用已经全部具备。

2026-10-21 后续反馈及修复：[会话层级复盘](review/session-model/README.md)指出多会话入口和完整多轮主线缺失。现已实现中间完整当前会话、右侧多会话列表与参考；输入、局部目标和滚动按会话独立恢复，切换不退回经典。实际范围与验收见[多会话修复](implementation/session-fix/README.md)。以下会话结构已按实现更新；完整混合画布等后续设计仍不代表已交付。

本版把界面位置、触发、返回和修改规则具体化。采用单个研究主工作面：默认呈现当前会话的完整多轮过程与成果入口；打开成果或深读原文时复用主区。Agent 输入始终位于主区底部；查看会话列表、来源或卡片时展开一个参考区。卡片、来源、白板、文稿仍是共享内容，不要求用户按对象分类推进研究。

## 界面的固定结构

```text
研究与最近内容        当前研究 / 当前会话或正在看的内容        按需参考区
                     ──────────────────────────────────────────────
研究 A               当前会话：比较方法                       会话列表
研究 B               你的问题 → Agent 回复                    [新建会话]
                     多轮过程、执行记录、成果入口               比较方法 · 当前
最近打开             打开成果 / 原文后复用这一区域              补查限制
  检索噪声的比较      顶栏提供“返回会话”                       或来源 / 卡片
  实验条件关系图
                     发送到：比较方法             会话列表
资料库               [围绕第 2 项 ×]
设置                 [唯一 Agent 输入                         发送/停止]
```

1440px 下左栏约 200px；参考区关闭时当前内容使用完整主区，正文保持合适阅读宽度，画布不限制为窄文档。参考区打开时约 360–400px，主区仍可编辑。1024px 下默认收起左栏，参考区优先并列；关闭入口与底部输入始终可达。完整问答只在中央会话视图显示，右侧列表不重复展开消息。

顶部只显示一个可编辑的研究名、本研究资料／查找与当前对象必要操作。当前成果在正文中有一个标题，不再叠加相似的面包屑、资源标签和“研究笔记／初稿版本”路径；当前打开项的数据继续复用，需要找回其他内容时使用最近打开与查找。PDF 深读时用明确返回条代替要求用户重新寻找标签。

默认研究范围通过“本研究资料”入口查看，不在输入里重复资料计数。首次委托说明取用范围和处理片段的模型；扩大到范围外时另行说明。只有显式的局部提问才在当前会话出现一条可清除焦点提示。“会话列表”保留一个固定可见入口。

整个界面只有一个 Agent 输入，始终位于主区底部，显示“发送到：当前会话名”。新建会话从空输入、空历史和无局部目标开始；切回已有会话恢复自己的输入、目标和滚动位置。成果与原文可跨会话浏览，但只有点击列表里的“打开会话”才改变发送话题。

主区保留当前会话每一轮的完整提问与回复，执行细节按需展开；持久成果通过链接打开，避免在对话和文稿中复制长正文。阅读资源时输入上方只留一行状态，顶栏提供唯一“返回会话”。1024px 下发送、停止、返回与关闭参考区均可达。

## 从打开到继续研究

| 情况 | 用户看到什么 | 下一步怎样发生 |
| --- | --- | --- |
| 新研究 | “你想研究什么？”、唯一输入与可添加资料的入口 | 直接描述目标；不先填写项目表单、选择卡片或画布类型 |
| 没有 PDF，要求找研究 | 当前目标与实际检索进展 | Agent 在已要求的公开检索范围内工作；缺少全文的结果明确只有题录／摘要 |
| 有资料，要求比较 | 会话呈现实际进展，完成后提供可编辑成果入口 | Agent 自行查找和读页，用户不逐项勾选上下文或点生成卡片 |
| 只问解释 | 当前会话中的完整问答 | 不强制建卡、写文稿或修改现有成果；切回对应会话可查看全部问答 |
| 明确要求整理或修改 | 会话留下持久成果入口和改动说明 | 长正文不在聊天和文稿中重复展示，不再要求复制保存和摆放 |
| 回到已有研究 | 上次成果或原文位置、未发送输入 | 输入与原来提问对象恢复；迟到结果只显示完成提示，不抢主画面 |

研究名称可以从首个目标拟定，随时直接修改；名称不作为切换研究身份或覆盖资料的依据。普通问答、修改和新的研究方向由用户意图区分，不能仅按回答长短决定是否建立成果。

## 查看与提问有不同的触发

点引用、查看资料或翻页只改变正在看的内容，不改变已经准备的问题及其修改目标。用户选择“围绕这里追问”时，才在唯一输入上方显示一条可清除的焦点提示，如“围绕比较第 2 项”。不把阅读位置、写入目标、来源范围各铺成一排常驻标签。

未发送文字必须保留。用户显式改为围绕另一处提问时，应清楚显示对象变化，并能撤销这次切换；普通浏览不会触发切换。提交后研究、目标和取回材料绑定该次请求，随后查看其他内容不改写已提交范围。

Agent 需要修改现有内容时说明实际目标与变化。解释性问题只产生回答；用户明确要求重分组、改写或补证据后才执行相应修改。歧义会影响既有内容时，先用简短问题澄清。

## 原文和对话的去向

| 触发 | 出现位置 | 返回与保留 |
| --- | --- | --- |
| 点一条引用 | 唯一参考区显示来源、页码与原句 | 关闭后原成果与选区保持；输入及提问对象不变 |
| 点“阅读全文” | 原文占主区，定位到对应页 | 可返回上一处恢复资源位置，也可直接“返回会话”恢复当前话题位置 |
| 在原文里明确问一段 | 复用唯一输入，显示这段原文的焦点 | 保留现有输入，明确告知焦点变化；不产生第二个聊天框 |
| 点“会话列表” | 同一参考区列出本研究多段会话 | 查看列表不改发送目标；一次点击“打开会话”恢复该话题完整问答与输入 |
| 点“资料”或查找 | 同一参考区浏览本研究内容 | 不重置研究身份；旧笔记、卡片、白板、文稿和论文都能找到 |
| 点总资料库 | 同一参考区显示跨研究内容及所属范围 | 只浏览不自动加入研究；一次“采用这些资料”完成需要的去重与关联 |

参考区不叠加第二个抽屉。它的标题说明当前看的是什么，关闭和返回位置固定。“会话列表”入口保持可见，不只提供快捷键；完整多轮问答在中央对应会话中保留。

## 一个画布承载内容和图形

卡片、论文、自由文字、形状和箭头在同一画布共存。画布出现时才展示相关选择、添加、文字、形状、画笔和连接工具；阅读和写作界面不显示这些工具。没有“卡片布局／绘图”的全局切换。

选卡片即可打开正文、查看来源或围绕它研究；调整位置和直接改字继续支持。Agent 在用户明确要求时整理画布；不把每次拖动、改颜色或画线变成模型请求。

自由箭头保留原样，不因统一画布强制改成虚线、附加“手绘”标签或升级为已证实论证。关系说明属于用户判断或 Agent 提议；原文引用与论断是否获得支持继续分开核查。旧绘图、摆放、关系和来源必须完整可达后，才撤下旧模式入口。

## 草稿 修改与恢复

初稿直接留在工作面并自动保存，明确标注来源与尚未核查的依据。手工编辑不等于核实通过，也不抹掉 AI 出处。用户可以继续修改、保留使用的资料或导出，不强制点击“采纳为定稿”完成一次研究。

Agent 修改自己尚未被用户改过的草稿，可直接显示并保留回执；碰到用户已经修改的内容，在原处提出差异建议，动作明确写“采用建议／保留我的”。采用后可撤销本次仍可安全撤销的修改，不能抹掉后来人工编辑的内容。文本输入和正文编辑里的 Ctrl／⌘Z 保留原生撤销含义，“撤销本次 Agent 修改”使用明确的独立动作。

出处与作者用简短文字区分，例如“AI 初稿 · 原文引用”“你已编辑 · 原文引用”；边框只表达选择，不表达核实程度。采用资料的撤销只撤回本次关联，不自动删除全局文献。疑问句也可能是明确的执行要求，不能按问号或“修改”子串机械判断授权；普通解释不触发写入。

停止保留已经完成的部分；重试沿用原目标与已有结果，不重复入库或新建同一成果。刷新后的未完成运行需要明确恢复，不能盲目重放操作。尚未实现的后台继续、自动全文获取与引用核实，不作为界面上的完成状态。

## 从默认界面真正撤下的内容

1. 资料、摘录、卡片、白板、文稿作为必须依次选择的一级研究步骤；替换为正在做的内容、最近与统一查找。
2. 摘录／卡片／AI 的永久右栏模式行，以及重复的聊天标题和助手状态工具栏。
3. “问 Agent／找已有依据／找文献”三条需要用户分别调度的主路径；由研究目标决定取用方式，手动浏览仍可直接进行。
4. 每条候选的加入讨论、入库、放到问题旁，以及回答的生成卡片、确认、保存、摆放连续链；按明确意图批量完成。
5. 输入区常驻的模型、推理强度、技能、Plan、历史轮次与字符预算工具排；运行配置留在设置，范围与实际来源可查看。
6. 卡片与绘图的互斥工作面；统一时完整保留旧内容，不能只隐藏一个模式。

不把这些入口原封不动塞进一个“更多”菜单。日常动作改由委托执行；需要直接浏览或编辑时，对象本身提供对应操作。

## 第一份交付必须同时体现界面变化

以三份已导入 PDF 的比较研究验证最小完整路径，同时交付唯一输入、成果直接可编辑、临时参考、原文返回和局部修改。只完成后台工具桥、仍让用户面对原有搬运流程，不算完成本切片。

界面验证分别记录：普通任务需要多少次强制操作；是否能找到旧内容；打开来源后提问对象是否保持；深读返回是否精确；是否存在第二个输入或长正文重复；1024px 时关键内容是否可用。再以真实模型验证工具选择、真实来源与修订行为，不能用静态原型冒充 Agent 已完成。

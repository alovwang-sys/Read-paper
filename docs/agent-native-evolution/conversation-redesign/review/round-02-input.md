## 结论：选 A。会话进左栏，右栏只放参考，答案只在中央出现

**选 A 的理由**

- A 让每个区域只有一种含义：左栏是导航，中央是正文（会话或资源），右栏是参考。

## 关键规则

**1. 会话列表**

- 每项单行，高 32px，只显示标题，过长截断。
- 时间改用分组标题表达（今天 / 本周 / 更早），每行不再写日期。
- 去掉摘要、"当前会话"文字和 provider。当前会话用左侧竖条标记。
- 行尾最多一个状态符号：⟳ 生成中，● 有新回复，! 失败，⛓ 绑定原生线程。
- 重命名、删除等操作放在悬停时出现的"⋯"菜单里。

**2. 输入框（Dock）**

- 删去"会话已有回复，可返回继续"和"会话列表"按钮。
- 发送目标写在占位文字里，例如"继续「方法对比」…"。
- 选区不会自动发给模型。选中文字后出现"加入提问"，点击后变成可删除的页码标签 [A p.12 ¶3]，消息里保留结构化引用。

**3. 发问后的固定规则**

- 从中央资源发问：中央切到当前会话并显示流式回复；原资源移到右栏，停在同一位置，选区保持高亮。
- 从右栏资源发问：不做任何切换。
- 所以切换最多发生一次，之后稳定在"中央会话、右栏原文"的状态。

**4. 回到原资源**

- 点击消息里的页码标签，右栏定位到该处。
- 右栏顶部的"↗放回中央"把资源放回中央继续阅读或编辑。

**5. 普通会话换助手**

- 原地切换：话题、已有历史和当前输入都保持不变。
- 后续轮次由新助手处理，它通过应用已保存的历史延续上下文。
- 会话正文里插入一条分隔线"以下由 Codex 回复"，这是事件记录，不是说明文字。
- 想开新话题就点"＋新建"，新建会话的语义保持独立，不藏起来。
- 空会话切换时不插分隔线。

**6. 原生绑定会话（⛓）**

- 身份固定，不做原地切换。
- 菜单中另一个助手显示为"Codex · 新会话"。选择后新建一个普通会话，并带走当前输入和标签。
- 只在发生的那一刻提示一次："已在新会话使用 Codex，原线程保留"。
- 某次运行确实用不到 Skills 或 Plan 时，才在那条回复下注一行，平时不常驻。

**7. 最少状态**

- 生成中：列表行显示 ⟳，发送键变为 ■ 停止。
- 新回复：只在用户离开该会话时显示 ●，打开后消失。
- 失败：用户消息下显示"未完成 · 重试"和一句原因，输入内容保留，列表行显示 !。

## 连续路径：聊天 → 打开引用 → 原文提问 → 看回复 → 回原文

1. 在中央会话里点击 [A p.12]，右栏打开论文 A 并停在 p.12，会话仍在中央。
2. 在右栏选中一段，点"加入提问"，输入框出现 [A p.12 ¶3]，输入问题后发送。
3. 回复直接在中央流式出现，不用打开列表，也不用找会话。原文一直在右栏。
4. 想细读时点"↗放回中央"。下次从中央发问，按规则 3 自动回到双栏。

整个过程不需要切换会话或寻找会话。

## 尚不确定、需要挑战的点

1. **跨助手延续历史是否无损**：普通会话原地换助手的前提，是应用保存的历史足以让另一家模型接续。工具调用结果等内容是否会丢失，需要工程确认。如果做不到，我宁可退回"新会话"，但菜单项必须明确写成"Codex · 新会话"，而不是悄悄新建。
2. **白板和文稿在右栏的交互**：白板、文稿在窄栏里能否编辑还没定。我倾向右栏只允许浏览和选取，编辑时放回中央。
3. **中央切换是否打断阅读**：长篇 PDF 连续提问的用户可能反感中央被切走。原型需要用固定样例对比"切换"和"不切换"两种体验，但不会为此新增一个模式开关。
4. **左栏容量**：材料和会话上下叠放的空间，取决于左栏现有宽度，我目前无法确认。

**原型需要覆盖的固定样例**：普通会话 Claude 换 Codex、⛓ 绑定会话换助手、运行失败后重试、上面这条连续路径。

# 设计评审：选区浮窗、原文记录与文章底座

## 初稿的主要问题

1. **新会话规则缺少重叠判定。** 同一句话稍微多选或少选几个字，就会被当作"新位置"，同一处会散落多段会话。
2. **首次提问的等待没有设计。** 底座在首次提交时生成，第一轮必然变慢。初稿没写这段时间里用户看到什么、能不能先只问选区。
3. **AI 操作标记和用户高亮混用。** 初稿中"淡高亮"与高亮功能用了同一种视觉，用户分不清哪些是自己标的。
4. **失败记录会造成杂乱。** 失败的 Activity 如果常驻原文，标记会越积越多。
5. **"摘要卡片"的对象没写清楚。** 应该是摘要当前选区，而不是整篇文章；它只能引用选区原文。
6. **只靠原文标记不够找回。** 翻页离开后，用户需要一个按本篇汇总的入口。

## A. 用户流程与默认会话规则

1. **出现浮窗。** 松开拖选或框选后，选区旁出现浮窗，只有三个按钮：提问、翻译、摘要卡片，外加一个"⋯"（高亮、摘录、手工卡片）。点击空白处关闭。
2. **提问。** 唯一的输入框移入浮窗。提交后，右栏切换到这处选区的会话，PDF 原地不动，浮窗收起成一个标记。
3. **会话归属规则：**
   - 新选区与已有选区重叠 ≥80%，或其中一个包含另一个：浮窗首位显示"继续此处（n）"，另提供"新提问"。
   - 其他情况：默认新建会话。
   - 只选中不提交，不创建 session。
4. **翻译。** 结果直接显示在浮窗里，下方提供"存为摘录"和"就此提问"，不创建会话。
5. **摘要卡片。** 生成一份草稿，用户确认后才保存为卡片，卡片共享父实体。

## B. 底座生成时机、材料边界与失败/并发

1. **时机。** 本篇第一次实际提交提问时才生成。翻译和摘要卡片都不等底座。
2. **等待期间。** 右栏显示"正在通读本篇·已覆盖 p1–p8"，并提供"先只按选区回答"按钮。选这个按钮，本轮标记为"未带底座"，之后的轮次自动带上。
3. **缓存键。** 由 assetHash、提取版本、底座 schema 版本组成。
   - 记录生成所用模型。
   - 切换助手不触发重新生成。
   - 只有用户手动操作或提取覆盖范围增加时才生成 v2；旧会话继续使用 v1。
4. **并发。** 每篇只跑一个生成任务，多个等待中的提问共用它。单个会话取消，不影响任务本身。
5. **失败。** 显示实际覆盖范围，并提供"重试"和"只问选区"两个选项，不假装读过全文。
6. **每次请求的内容。** 只包含：底座 vN、当前选区、本会话历史，不带入其他选区的会话。
7. **底座的定位。** 底座只作为背景，不能作为引用证据。

## C. 让原文记录清楚而不杂乱

1. **两套视觉分开。**
   - 用户高亮：色块填充。
   - AI 操作：细下划线加页边一个小圆点，圆点上显示操作次数。
2. **点开圆点。** 显示这一处的时间线：会话、翻译、卡片，每条可以点击跳转。
3. **失败与进行中的显示。**
   - 失败只出现在时间线里，不在原文上留标记。
   - 进行中显示一个转圈图标。
4. **本篇汇总入口。** 复用顶栏的集合小浮窗，增加一个"本篇"筛选，按页码列出各处记录，不新增栏位。

## D. 框选时文字与图片的处理

先判断框选区域内有没有文本层：

| 区域情况 | 翻译 / 摘要卡片 | 提问 |
|---|---|---|
| 有文本层 | 正常使用，并显示"区域内文字 n 字" | 正常使用 |
| 无文本层 | 按钮置灰，提示"无文本层，未提供 OCR"，不把图片冒充成文字 | 当前连接支持图片：附上区域截图；不支持：让用户明确选择"切换连接"或"仅发区域文字"，不静默降级 |

**原型要求：** 合成的 PDF、框选、底座、翻译结果都要标注"示例数据"。

## E. 验收（7 项）

1. 只选中不提交，不产生会话；同一处重新选中会提示"继续此处"。
2. 两处选区同时首次提问，只生成一次底座，两段会话都标注 v1。
3. 底座生成失败或只覆盖部分页面时，显示实际覆盖范围，"只问选区"可以用；本轮标记为"未带底座"。
4. 材料标签点开后能看到底座版本、覆盖范围、选区内容，以及本轮是否带入。
5. 翻译不创建会话，结果可以存为摘录；回到原文点圆点能找回。
6. 无文本层的区域不能翻译；连接不支持图片时，没有用户确认就不发送。
7. 刷新页面后，标记、时间线、未保存的草稿都还在；AI 标记和用户高亮能分清。

## 不确定处

- 80% 这个重叠阈值需要用真实论文试出来。
- 正式代码里 inline-ai 服务能否按 anchor 汇总记录，要等源码审计结论。

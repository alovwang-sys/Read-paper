# 第3轮视觉复核（依据 screenshot-01 到 04）

**先分清依据：** 下面的判断只来自这四张静态截图。我没有点击界面，也没有跑测试。旧17项会话回归 17/17、现有9项集合回归 9/9 都是 Codex 的观察结果，专项测试还在跑，这些都不算我的验证。凡是交互行为方面的判断，我都标了"推断"。

## 1. 能否交给用户体验

**能。没看到阻断问题。** 主线都能从图上看明白：同一句原文的记录能在一处找到，局部对话能看出用了哪些材料，窄屏下能选文，摘要编辑时原文只读。下面3条建议在交付前改掉：

1. **图2：简要浮层盖住了局部对话的头部和第一行回答。**
   - 可见依据：标题被截成"比较两种检索策略|"，"Codex"标签被压住，回答首行只剩"示例回答：这"。两个浮层叠在一起，用户想对照"简要说了什么"和"回答说了什么"时，正好看不到回答的开头。
   - 建议：简要不再另起一层，改为在局部对话内展开，或贴在对话卡片的左侧弹出。不需要新增布局。

2. **图2：输入框上的标签"文章简要 v1 · 1/20页"有歧义。**
   - 可见依据：标签写的是"1/20页"，浮层里写的却是"覆盖：第12页 / 共20页"。"1/20页"很容易被读成"第1页"。材料范围本来就是这一版要说清的核心。
   - 建议：改成"简要 v1 · 仅第12页"，和浮层里的说法保持一致。

3. **图4（图1也一样）：来源标签写在可编辑的正文里，而且摘要和原文一字不差。**
   - 可见依据：图4 的文本框第一行就是"【基于选区 · 示例草稿】"，后面接的内容和下方"原文依据"完全相同。图1 的摘要卡片记录也是这样。
   - 推断：如果保存时不剔除，这行标签会被写进卡片正文。用户也很难分辨这是"摘要"还是"摘抄"。
   - 建议：把这行标签移出文本框，做成标题旁的小字。样例草稿至少要和原文有明显区别，哪怕只是压缩改写一下。
   - 如果 Codex 确认保存时会剔除这行标签，这条可以降为可选。

## 2. 美观、阅读遮挡、记录查找、材料范围

- **美观：** 整体统一。绿灰配色、浮层圆角和阴影一致，图4 的"稍后继续 / 保存卡片"主次也清楚。图1 的记录面板最后一条"提问"在半行处被截断，又没有任何能滚动的提示，看起来像渲染出错。可以在底部加一道淡出渐变。
- **阅读遮挡：**
  - 图1 的面板盖住了第2段和图表的左半部分。它是从右侧 marker "3" 打开的，弹出位置却在左下方，视线要跳一下。
  - 图3 的选文浮窗盖住了下一行的开头（"样例结果：B的召回更高…"）。浮窗是临时的，可以接受。如果改放到选区上方，就不会挡住接着要读的那一行。
  - 图4 的卡片浮层盖住了右侧的 marker。这在编辑时可以接受。
- **记录查找：** 已经清楚。图1 里同一句原文有3条记录，每条都标了类型、"已完成"状态和时间，按时间倒序排列。翻译记录写明了"示例译文（未调用模型）"。
  - 图3 的第一句原文上看不到下划线，也看不到 marker。推断：这可能是刷新后重置的状态，不一定是 bug。请 Codex 确认截图时的状态。
- **材料范围：**
  - 图2 浮层里写清了"只依据标题和合成第12页，未读取其余19页"，也写了"不能作为原文引证"，回答里写了"文章简要仅作背景"，引用标签是"本处原文 · 第12页"。这三层说法彼此一致。
  - 唯一的风险是第一行"研究问题：如何比较…"的语气像在概括全文。建议在前面加"（据第12页推测）"。

## 3. 建议删除（3项）

1. **图1 的重复计数。** 头部已有"3 条记录"，下面又有"此处记录 3 条"，保留一处即可。
2. **图3 选文浮窗上的"×"。** 点击别处或按 Esc 就能关掉，这个按钮占了位置，信息量却很低。图1 记录面板上的"×"可以保留。
3. **图2 局部对话输入框里的"研究工具 / 图片 / 语音"。** 局部对话的上下文已经固定为选区加简要，这三个入口会让用户以为能扩大材料范围。其中"图片"还可能和"非视觉连接不能发区域"的规则冲突。建议在局部对话里只保留模型选择和发送。

## 4. 仍需用真实 PDF 和真实模型验证的部分

现在所有内容都是内存里的 HTML 样例，刷新就会重置，没有接真实模型，也没有全文提取、OCR 或像素裁图。以下这些在当前原型里都无法证明：

- **锚点：** 文字的精确位置在真实文字层上是否可靠，例如多栏排版、连字符断行、连字、跨页选区、缩放或重新排版之后 marker 的位置。
- **框选和无文字层：** 在扫描版 PDF 上，框选区域的坐标是否稳定；没有文字层时，禁用翻译的提示是否可见。
- **真实模型输出：** 简要能否忠实于所给页面，不越出范围；摘要能否和原文区别开；译文的格式和术语是否可用。
- **缓存与并发：** 简要缓存是否在文件 hash、提取版本、schema、提示版本变化时正确失效；同一篇文章 singleflight 共享任务时，停止其中一个局部对话，其他对话是否不受影响；旧请求在简要后到达时是否不被改写。这些在真实网络延迟下都要重测，而不能依赖现在模拟的 700ms 和 1300ms。
- **持久化：** 停止或失败的记录在重启 App 后是否还能找回。
- **长回答和窄屏：** 回答流式输出、内容较长时，局部对话浮层和简要浮层在 1024px 下如何避让。
- **区域发送：** 视觉连接的判定，以及禁止发送区域时的反馈。

另外，Codex 的专项测试结果出来之前，我不把它当作已验证。

# 第二轮定稿：选区浮窗、原文记录与文章简要

Codex 的 9 点里我大体认可，其中第 1、5、7 点纠正了我第一轮的实际错误。有三处我不照搬，会给出修订后的方案：

- **矩形框选的“同一处”判定**：严格相等在实际操作中几乎不可能命中。
- **简要从“无”变“有”时的处理**：不必一律弹提示。
- **“本篇”汇总入口**：保留，但降为正式版的可选项。

---

## A. 逐点结论

### “同一处”与“不同位置”的界定

**同一处**指同一个锚点，满足以下任一条件即可：

1. **点击原文上已有的标记。** 这是主路径，矩形框选只认这一条。
2. **文本选区与已有锚点完全一致。** 即 assetHash、页码、类型、起止 offset 全部相等。

**不同位置**指其他所有情况，包括多选或少选了一个字、与已有锚点重叠、手动再框一次同一块区域。

**相近的处理：** 如果新选区与已有锚点重叠，浮窗里额外显示一行“此处附近已有 n 条记录 →”。这只是一个跳转链接：

- 点进去后，打开的是**原锚点**的会话，上下文用原锚点的文字或裁图，新选区被丢弃。
- 不点它，提交时就按新位置新建会话。
- 系统从不合并两个锚点，也不扩大任何锚点的上下文范围。

我放弃了第一轮的“80% 重叠就默认继续”。理由是：默认继续会让用户以为问的是新选的文字，实际却是旧锚点的文字，这比多出一段会话更糟。

### 额外命名约束

“文章简要（AI）”与官方 abstract 是两个不同实体：

- 两者在 UI 上不能共用“摘要”一词。
- 简要永远不写入、也不覆盖 abstract 字段。
- “摘要卡片”的对象只限当前选区，卡片上要标明“基于选区”。

## B. 一屏布局与三条核心路径

### 布局

不新增栏位，沿用现有的“PDF 主区 + 右侧侧栏”。

```
┌──────────────── PDF 主区 ─────────────────┐┌─ 现有侧栏 ─┐
│ …正文…［选中文字］…                ●2      ││（仅在点击  │
│        ┌─ ReaderPopover ─────────────┐    ││「侧边继续」│
│        │ [提问] [翻译] [摘要卡片] [⋯] │    ││ 后承载该   │
│        │ 此处附近已有 2 条记录 →       │    ││ 会话）     │
│        │ ┌输入框────────────────────┐ │    ││            │
│        │ 材料：[简要 v1·p1–24][本选区]│    ││            │
│        │       [此处历史 2 轮]         │    ││            │
│        │ 回答区（限高，可滚动）        │    ││            │
│        │            [侧边继续] [新会话]│    ││            │
│        └──────────────────────────────┘    ││            │
│ ▇▇用户高亮▇▇（色块）                 ○     ││            │
└────────────────────────────────────────────┘└────────────┘
```

**标记的视觉规则：**

| 标记 | 含义 |
|---|---|
| 实心点 ●n | 该处有 AI 动作，n 为动作次数；对应文字下方有细下划线 |
| 空心灰点 ○ | 该处只有失败动作 |
| 转圈 | 该处有进行中的动作 |
| 色块填充 | 用户自己的高亮，与 AI 标记完全区分 |

点击任一标记，会在浮窗内打开该处的时间线（会话、翻译、卡片），每条可以跳转。

**材料标签（chip）：** 点开后能看到真实内容：简要的版本和覆盖页、正文；本选区的文字或裁图；本轮带入了哪些历史。

### 路径 1：在新位置首次提问

1. 选中文字后出现浮窗，点“提问”，进入本地草稿状态（不留标记）。
2. 提交后，原文出现带转圈的标记。
3. 如果简要尚未生成，浮窗显示“正在准备文章简要 · 将覆盖 p1–p24”，并提供“先只按选区回答”。
4. 简要就绪或用户选择“只按选区”后，回答在浮窗内流式输出。
5. 用户可选“侧边继续”，在侧栏接着聊同一会话。

### 路径 2：找回与继续

1. 点击原文标记，打开时间线。
2. 选中某条会话，点“继续此处”，上下文为原锚点的选区加上该处自己的历史。
3. 如果用户重新选了一段相近文字：
   - 点“附近已有记录 →”，效果同步骤 2；
   - 直接提问，则新建会话。
4. 时间线中的失败条目可以“重试”。

### 路径 3：翻译与摘要卡片（含框选分支）

**文本选区：**

- **翻译**：结果显示在浮窗内，不创建会话。可“存为翻译笔记”（原文只读、译文另存一栏），也可“就此提问”，后者会以该锚点新建会话。
- **摘要卡片**：只基于选区生成草稿，在现有卡片浮层中确认后才保存。

**框选区域：** 先判断区域内有没有文本层，以及当前连接是否支持图片（视觉）。

| 框选区域 | 翻译 | 提问 / 摘要卡片 |
|---|---|---|
| 有文本层，连接支持图片 | 可用，显示“区域内文字 n 字” | 可用，附上裁图和文字 |
| 有文本层，连接不支持图片 | 可用 | 可用，但标注“图形未发送”，需用户确认 |
| 无文本层，连接支持图片 | 置灰，提示“无可核对文字” | 可用，只发裁图 |
| 无文本层，连接不支持图片 | 置灰 | 置灰，提示“需支持图片的连接”，不提供空回退 |

## C. 简要状态、冻结时机与失败机制

**缓存键：** assetHash + 提取版本 + 简要 schema 版本 + 提示版本。生成所用的模型单独记录。切换助手不会触发重新生成。

**并发（singleflight）：** 每篇文章同时只跑一个简要生成任务，所有等待中的请求共用它。

**两个冻结时刻：**

- **点击提交时**，冻结选区（锚点加文字或裁图）和本处历史。
- **请求真正发出时**，冻结简要版本（或“无”）和覆盖范围。若提交时简要正在生成，这个时刻就是简要就绪的那一刻，或用户点“只按选区”的那一刻。

| 简要状态 | 用户看到 | 新提交如何冻结 | 可执行的操作 |
|---|---|---|---|
| 未生成 | 不显示 | 首次提交触发生成，并进入“生成中” | — |
| 生成中 | “正在准备文章简要 · 将覆盖 pX–pY” | 选区和历史已冻结，简要待定 | “先只按选区回答”（本轮标“未带简要”，生成任务继续）；停止本处请求，不会取消生成任务 |
| 就绪 vN（全覆盖） | 标签显示“简要 vN · 全文” | 冻结为 vN | 点开查看简要正文 |
| 就绪 vN（部分覆盖） | 标签显示“简要 vN · p1–p24 / 共 40 页” | 冻结为 vN，并带上覆盖范围 | 同上，覆盖范围不能隐藏 |
| 失败 | 显示失败原因和已覆盖的页 | 冻结为“无” | “重试”“只按选区”；本轮记录保留在时间线 |
| vN+1 可用 | 旧会话的标签上提示“有新版简要” | 旧轮次保持 vN 不变 | 用户确认后，下一轮改用 vN+1 |

**每轮请求的内容只包括：** 简要（vN 或无）、本锚点的选区、本锚点自己的历史。不带其他锚点的会话，也不带整个文库。

**简要的定位：** 只作背景材料，不作为引用证据。

## D. 验收

### 本轮原型可验证（合成 HTML，示例数据，不落盘）

1. **草稿不留痕。** 只选中、或点了“提问”但未提交，都不出现标记，时间线也不新增。提交后才出现标记。
2. **同一处与附近。**
   - 点击标记或完全一致的文本选区，会出现“继续此处”。
   - 重叠选区默认新建会话。
   - 走“附近 →”进入后，材料标签显示的是**原锚点**的文字。
3. **换宿主不换会话。** 回答出现在浮窗内。点“侧边继续”后，侧栏显示同一会话（会话 ID 和历史一致），浮窗收起。
4. **singleflight 与停止。** 两处同时首次提问，简要状态只有一个，两段会话都标“示例简要 v1”。停止其中一处，另一处仍能拿到 v1。
5. **失败与部分覆盖。** 可以模拟“失败”和“仅 p1–p24”两种状态：页码如实显示，“只按选区”可用，本轮标“未带简要”，材料标签能展开查看示例内容。
6. **翻译笔记与失败找回。** 翻译不创建会话。存为翻译笔记后，原文字段只读。模拟失败的动作仍保留空心标记，时间线中可见、可重试。
7. **框选四种组合。** 按 B 路径 3 的表格，四种状态的按钮可用或禁用、提示文字逐一对得上。原型里的裁图和文字均标“示例”，不声称做过 OCR 或真实截图。
8. **界面约束。**
   - AI 标记与用户高亮在视觉上可区分。
   - 没有第三栏、底部大面板，也没有全局按钮墙。
   - 所有合成内容标“示例数据”。
   - 页面明示“刷新会重置”，这一点不算缺陷。

### 仅限正式版（本轮不要求，也不能声称已通过）

- 刷新后，标记、时间线、草稿都能恢复。
- 真实裁图的发送，以及连接视觉能力的检测。
- 简要的缓存键、版本迁移，以及在真实采集上限下的覆盖页展示。
- 按 sourceAnchor 在服务端聚合时间线。
- 官方 abstract 不被简要污染。
- “本篇”筛选，前提是现有集合浮层确实可以复用。

### 仍不确定

- **多锚点的显示与交互。** 同一页锚点很多时，页边标记会挤在一起，需要用真实论文测试折叠规则。
- **长回答的容量。** 浮窗限高后，长回答放不放得下，以及何时提示用户“侧边继续”，需要在原型里实际体验后再定。

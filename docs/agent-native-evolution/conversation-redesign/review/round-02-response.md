# Papertrail 工作台 · 第2轮最终行为规则

## 对反驳的处理

- **采纳**
  - 左栏以会话为主导航，材料只保留一个入口。
  - 删除顶栏的助手状态和"以下由 Codex 回复"分隔线。
  - 只在提交被接受后才跳转。
  - 迟到的结果不抢主区。
  - 白板和文稿不塞进窄栏编辑。
- **放弃**：⛓ 不再出现在列表里，绑定边界只在助手菜单中体现。
- **说明**：下文的"换助手后用已保存历史续接"是拟议语义，不代表现有实现。

## 规则

**R1 左栏**

- 自上而下：研究切换 ▾、[＋ 新会话]、搜索框、会话列表，底部是"资料与成果 ▸"。
- 列表不加"会话"标题。每行高 36px，只显示标题。
- 当前会话只用底色标出。没有摘要、日期和 provider。
- 只分两组："今天"和"更早"。
- "资料与成果"展开后在左栏原位显示 PDF、卡片、白板和文稿，再点一次收起。它不与会话列表同时滚动。

**R2 状态**

- 行尾只显示正在发生的状态：⟳ 生成中、● 未读、! 失败。
- 三者同时出现时，优先级为 ! > ⟳ > ●。
- 绑定身份不占用这个位置。

**R3 默认页**

- 恢复最近一次的会话、滚动位置，以及输入区里未发送的草稿和标签。
- 右侧参考层默认关闭。

**R4 输入区**

- 输入区只有一个助手按钮"Claude ▾"，占位文字为"追问…"。
- 每条回答顶部用 11px 灰字标注助手名。切换助手后，旧的回答仍保留原来的名字。
- 选区不会自动发送。选中文字后点"加入提问"，生成一个标签，如 [A p.12 ¶3 ×]。
- 不附带全文。

**R5 发送与跳转**

- 提交被接受后：中央切到该会话，资源移到右侧参考层，PDF 停在同一页并保持高亮。
- 提交被拒绝时：留在原页，输入框下方显示"未发送 · 重试"和原因，输入内容不变。
- 运行中途失败时：在该条消息下显示"未完成 · 重试"。
- 迟到的结果：如果用户已离开这个会话，只在列表行亮 ●。回到会话时自动定位到这条回复。

**R6 白板和文稿**

- 发问被接受后，中央切到会话，右侧不打开参考层。
- 白板的缩放、选中状态和文稿光标原样保留。
- 会话正文顶部出现按钮"← 回到 白板1"或"← 回到 文稿：引言"。点击后完整恢复之前的状态。
- 点击消息里的标签效果相同。

**R7 1024px 宽度**

- 左栏固定 220px，中央占据其余宽度。
- 参考内容以单个覆盖层出现，宽度为中央的 55%，右上角有 ×。
- 打开新的参考内容会替换当前内容，不会叠加。
- 左栏在这个宽度下不做成抽屉。

**R8 助手菜单**

- 普通会话：直接切换，原有轮次保持不变。
- 未连接的助手：该项显示"去连接 →"。
- 绑定会话：菜单顶部注明"本会话绑定 Claude 线程"，另一个助手显示为"Codex · 新会话"。选择后新建会话，并复制当前输入和标签，原会话不受影响。

## 仍然担心的取舍

- **白板和文稿发问后整屏切走**：画面上的空间上下文会丢失，必须靠"← 回到"按钮弥补。原型阶段需要用连续多次追问来验证这样是否顺手。
- **11px 的助手名**：原地换助手时，它可能弱到用户察觉不到后续回答已经换了助手。

# 第5轮：浮窗会话选择

> 第1项（分屏标签组）：我还没看到最终截图，也没有看到 11 项复跑的结果，所以不判断视觉是否通过。下面只回答浮窗会话这一项。真实 AI 尚未接入，“在途请求”目前都是 mock 链路。

## A 最小入口与规则

同意 Codex 的方案：会话标题是唯一入口，点开是下拉，不加常驻选择条。

1. 菜单从上到下依次是：
   - 搜索框；
   - 「＋ 新会话」；
   - 至多 3 条建议，分区标签只能是「相关」或「最近」其中一个，按实际结果写；
   - 本研究的其他会话，按时间倒序。
2. 菜单底部只放一个开关：「带上当前选区」。有选区时默认勾选，没有选区时隐藏。
3. 切换会话只改变“正在看哪个会话”。不发送、不合并历史，也不取消任何请求。
4. 新会话在发送第一条消息前不落库。切走时如果它是空的，直接丢弃。
5. 推荐只做建议，不自动切换，也不跨研究推荐。

## B 当前会话与新会话的关系

- 浮窗打开时，沿用侧栏当前的会话。两者共用同一个当前会话，在浮窗里切换，侧栏也跟着切，避免出现两套“当前”。
- 新会话的标题先显示「新会话 · 来自〈文献名〉p.12」。发出第一句后再自动命名。
- 让用户一眼就知道：这是新开的，而且是从这段原文出发的。

## C 排序

**评分：**
- 同一篇文献或同一张卡片作为来源：+3；
- 标题和最近 5 条消息里的关键词重合：每个词 +1；
- 最近活跃时间：只用来打破同分。

**分词：** 用 Intl.Segmenter，去掉停用词；中文如果切不出词，用双字组兜底。

**规则：**
- 来源命中，或关键词命中不少于 2 个，才标「相关」；
- 否则这一区写「最近」；
- 排除当前会话。

**何时升级到语义检索（本地 embedding）：**
- 单个研究的会话数超过约 80；
- 或数据显示用户经常绕过建议去搜索；
- 或需要跨研究推荐。

## D 归属：「文字跟会话走，材料跟用户走」

**数据结构：**
- 草稿就是 `draft[conversationId] = {text, attachments[]}`，沿用现有的会话记录，不新增全局状态。
- 请求在发送那一刻记下自己的 `conversationId`。回复只写回这个会话，不管当时界面在看哪个。下拉列表里，对应会话显示转圈。

**选区：**
- 选区会冻结成一个附件：文献 ID、页码、文本和哈希。
- 附件追加到目标会话的 attachments，按哈希去重。
- 附件不进入文本，所以永远不会和草稿文字冲突。

**已有草稿冲突的方案：**
- 未发送的文字永不自动搬家，源会话的草稿原样保留。
- 目标会话恢复它自己的草稿，不覆盖。
- 如果源会话有未发送文字，目标输入框上方出现一行非模态提示：「原会话有未发送：“前 20 字…” [移过来]」。
- 点「移过来」：把这段文字插入目标草稿末尾，用空行隔开，同时清空源会话的草稿，并提供一次撤销。
- 新会话和已有会话用同一条规则，没有弹窗，也不会静默拼接。

## E 验收断言

1. 切到会话 B 后，B 的草稿与切换前逐字一致；会话 A 的草稿保持不变。
2. 勾选「带上当前选区」后，B 恰好新增 1 个选区附件；再切一次，数量仍是 1。
3. A 的请求还在途时切到 B：回复只出现在 A，B 的消息数不变。
4. 「相关」标签只在得分达到阈值时出现，否则写「最近」；推荐里不出现当前会话，也不出现其他研究的会话。
5. 新建会话但不发送，切走后列表里没有这个空会话；点「移过来」再撤销，A 和 B 的草稿都恢复原状。

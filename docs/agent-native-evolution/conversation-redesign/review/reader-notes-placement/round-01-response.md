# 结论：选 B 的精简版，只做一个笔记浮层；C 的“在标签中打开”放到第二步；不做 A

## 1. 底部路径为什么错

- **生成和取回不在一处。** 卡片在选区旁生成，却只能到文末取回。用户要先离开阅读位置，再自己找回来。
- **集合被绑在 PaperPreview 的文档流里。** 切到别的标签或分屏后，它就找不到了。“本研究”的范围也没有地方放。
- **编辑浮窗没有固定入口。** 关掉以后，草稿还在，但找不回它所在的位置。
- **在同一个滚动容器里看笔记，必然打乱 PDF 阅读位置。**

## 2. 方案与完整流程

**否决 A 的理由：**
- 右栏切到笔记会挡住聊天，违背“聊天和原文同时工作”。
- 左栏入口在 1024 宽度下会被折叠。
- A 实际是两个入口。

**采用 B：** 工作区顶栏放一个“笔记 n”按钮，点开一个不阻断操作的浮层。列表和详情共用这一个容器。范围切换只有“本篇 / 本研究”两项，默认跟随当前激活的论文。数据直接读父状态里的 excerpts 和 cards。

完整流程：

1. **新建：** 选中原文后，仍在选区旁的小浮窗里生成。
2. **保存：** 保存后出现约 3 秒的轻提示“已存为卡片 · 查看”。点击后打开浮层，并定位、高亮这张卡。这是“刚建的卡片一步找到”的唯一捷径。
3. **再找：** 列表按最近时间排序。每条显示类型标记、两行引文和 p.N（显示时由 pageIndex 加 1）。
4. **编辑：** 在浮层内从列表切到详情，与新建共用同一个 CardEditor 组件，不再另开第二个浮窗。关闭时保留未保存的草稿。
5. **回原文：** 点引文后，先激活已打开的该文档标签；如果没打开，就在当前组新开。然后滚到对应页并短暂高亮引文，同时收起浮层。再次打开时恢复上次的范围、滚动位置和选中项。
6. **与聊天共存：** 浮层锚在中央区域右缘，不覆盖聊天栏，不创建会话，不改变聊天的草稿、在途请求和未读状态。只有点击“回原文”会移动 PDF；仅打开浮层不会。

**C 只作扩展：** 详情里放一个“在标签中打开”。它生成单例的笔记标签，复用同一个集合组件，由用户自己拖去分屏。我不确定这个是否必要，建议先上浮层，用后再决定。

## 3. 不同宽度下的布局

| 宽度 | 浮层宽度 | 备注 |
|---|---|---|
| 1440 | 360px | — |
| 1280 | 340px | — |
| 1024 | 320px | 左栏是否折叠维持用户当前状态，不自动改 |

通用规则：
- 高度上限为视口高度减去顶栏再减 24px，列表在浮层内独立滚动。
- 轻阴影、圆角 8px，不加遮罩，不加说明文字。
- 空状态只显示一行“选中原文即可摘录”。
- 浮层会遮住中央区域右侧，这是已接受的代价。需要并排对照时，用标签分屏。

## 4. 入口取舍

**保留：**
- 顶栏“笔记 n”按钮
- 保存后的轻提示
- 选区旁的新建浮窗

**删除：**
- `section.reader-notes`
- 游离的卡片编辑浮窗
- 左栏笔记入口
- 右栏的“聊天/笔记”切换
- 第三种范围、类型筛选栏、说明文案

## 5. 验收标准

1. 文末不再渲染任何笔记区域。在任何标签或分屏下，顶栏都能一步打开集合。
2. 点保存提示中的“查看”，能定位到刚建的卡片。
3. “本篇 / 本研究”的计数和列表都来自同一份父状态，引用为同一对象，不复制数据。
4. 打开、滚动、关闭浮层前后，PDF 的 scrollTop 不变。
5. 点“回原文”后进入正确的 docId 和 pageIndex，并高亮引文；如果标签已打开，不重复新开。
6. 编辑到一半关闭再打开，草稿还在；重复保存同一句话不会产生重复项。
7. 浮层开关前后，聊天输入的草稿、在途请求、未读状态和会话 ID 都不变，也不新增会话。
8. 在 1440、1280、1024 三个宽度下，浮层不覆盖聊天栏，左栏折叠状态和两组分屏的布局都不被改动。

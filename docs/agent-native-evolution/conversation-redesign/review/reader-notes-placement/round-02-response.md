# 审查结论：同意 Codex 版本，补 4 处歧义后定稿

**1. 最小且完整吗？** 是。保留左栏“研究笔记”是对的，它是文稿，不是卡片集合。我上轮说删除左栏入口是误判，应撤回。删除文末 `section.reader-notes`，再加一个顶栏入口，范围已经够用。

**2. 能解决“底部找不到”吗？** 能。原问题出在取回点跟着文档流走。现在入口固定在工作区顶栏，与标签、分屏无关；保存后的“查看”负责刚建卡片的定位，常驻按钮负责以后再找。前提是“查看”在任何范围或搜索状态下都能找到那张卡（见第 2 条）。

**3. 现在做 C 吗？** 不做。没有视图身份，就不画按钮。以后接入已有的 `openResearchView(...,'cards')`，不新造笔记标签。

**4. 范围默认值：** 我改为同意“默认本研究，并记住用户显式选的范围”。理由是本研究包含全部条目，新卡一定在里面。如果跟随焦点自动换范围，用户会看到列表悄悄变化，比多看几条更糟。

## 必须修的 4 处歧义

1. **未保存稿**
   - 草稿的键为 `cardId`；从摘录新建时为 `new:excerptId`。
   - 切换条目、关闭浮层、跳回原文都不清空草稿。列表中有草稿的行显示一个圆点。
   - 对同一摘录再次点“写成卡片”，打开已有草稿，不新建。

2. **“查看”与过滤冲突**
   - 刚保存的卡不在当前范围或搜索结果里时，自动清空搜索、切到本研究，并保持与列表一致。
   - 如果浮层已打开且正在编辑，不覆盖当前草稿，只在列表里定位并标记新卡。

3. **窗口边界**
   - 浮层锚在整个中央工作区，不锚在某一组分屏上。
   - 宽度取 `min(设定值, 中央宽 − 24)`，下限 280px；低于下限时贴满中央区域。
   - 点击 PDF 不关闭浮层（方便继续选文），关闭只用 Esc 或再次点按钮。
   - 选区小浮窗和提示条的层级要高于集合浮层。

4. **出处跳转**
   - 查找顺序：当前组里已打开该文档的标签 → 另一组里已打开的标签（激活那一组，不移动标签） → 在当前组新开。
   - 由 root 下发一次性的定位指令（docId + pageIndex + 引文），等目标挂载后再执行，执行后作废。
   - 文档不可用时，在行内提示“原文不可用”，不收起浮层。

**最终建议：** 按 Codex 方案实施，并补上以上 4 条。验收时加 4 条专项用例：“查看”能穿透过滤，草稿按键隔离，两组分屏下的跳转正确，窄中央宽度下的布局正确。我没有执行过这些测试。

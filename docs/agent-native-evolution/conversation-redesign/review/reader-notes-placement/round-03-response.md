# 第 3 轮视觉复核：没有必须修的可见阻断，同意定稿

我读了这 4 张静态合成截图。下面的判断只来自画面；交互、测试和状态保持都来自 Codex 的观察，我没有点击过界面，也没有跑测试。

**1. 固定入口清楚吗？** 清楚。4 张图里，“卡片与摘录”都在顶栏的“分屏 / 聊天”旁边，位置不变，有图标和文字。名字和左栏的“研究笔记”分得开，没有多出别的入口。

**2. 紧凑、好找吗？** 基本够用。
- 卡片有粗体标题，摘录用左边竖线标出引文，两者一眼能分开。
- 出处页码和“写成卡片”在同一行，没有多余层级。
- 图 4 在 1440 宽下能看到约 6.5 条，紧凑程度可以接受。
- 刚保存的项排在最前，有浅绿底色；图 4 里 PDF 上对应的原文也有高亮，前后呼应。

**3. 浮层和右侧聊天的关系清楚吗？** 清楚。三个尺寸下，浮层右边都离中央区右缘约 12px，有阴影，没有压到聊天栏的分隔线。聊天内容和输入框完整可见。图 2 的编辑态和列表用同一个容器，边界一致。中央内容被临时盖住是已知取舍，翻页箭头被遮也在其中，不算错误。

**可选微调（不影响定稿）**
1. 浮层打开时，顶栏按钮看不出按下状态。加一个浅底色，能让按钮和浮层的对应关系更明显。
2. 新项只靠浅绿底色标记，和选中的“本研究”标签同色，可能被当成“当前选中”。可以加一个小字“刚保存”。
3. “卡片 / 摘录”的类型标签字很小、颜色偏灰，对比度偏低。
4. 推断风险：图 4 的长列表几乎伸到底部，而图 1、图 3 里提示条在中央区底部居中，两者在水平方向会重叠。如果两者同时出现，提示条会盖住列表末尾。这一点截图没有展示，需要 Codex 确认。

**静态截图看不到的部分**
- 列表行上的草稿圆点（图 2 没有列表）。
- 点“查看”后穿透过滤、跨分屏组跳转、Esc 关闭。
- 列表滚动条（截图里没有显示）。

**结论：** 没有必须修的可见阻断，同意按当前版本定稿。以上 4 条可以另排。

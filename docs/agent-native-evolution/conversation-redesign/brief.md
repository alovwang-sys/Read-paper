# 会话连续性与界面减法

2026-10-23，设计讨论与交互原型；不代表正式应用已实现。

用户的新反馈聚焦三处：发送后仍需到右侧寻找对应会话和答案；会话条目占地过大且重复标题、摘要和状态；助手切换展示了大量用户不需要理解的实现说明。本轮的“绘画”按上下文理解为“会话”。

本轮请 Claude Code 作为设计主笔，完成七次真实调用、逐轮反驳和修订。旧讨论不计入本轮次数。方案必须改变用户路径，而不只是改文案或把原控件塞进另一处。

## 必须能在原型中判断的路径

| 操作 | 应能直接观察的结果 |
| --- | --- |
| 发问题 | 主工作面立即显示这次问题、处理状态与完整回答；不靠打开会话目录寻找结果 |
| 阅读 PDF／白板时追问 | 问题所带材料明确；发送后答案在稳定可见处，原资源位置可找回 |
| 切换会话 | 单击紧凑条目即可恢复该会话的问答和独立输入；当前项仅用选中样式表达 |
| 换助手 | 直接选择助手；正常情况不要求读说明段落，也不悄悄切换已有话题或丢草稿 |
| 引用与文献 | 引用可打开；文献可示例收录；不要求跨三个区域搬运 |
| 特殊情况 | 未连接、执行中、失败和原生绑定会话只在发生时提供简短、可执行的反馈 |
| 小窗口 | 1440×900、1280×800、1024×800均能发送、看答、切会话，避免叠加两个抽屉 |

## 约束

沿用研究、会话、消息、文献与共享成果的数据关系。保留原文、卡片、白板、文稿、图片／系统听写和资料库的产品能力；本原型只演示与本次问题有关的路径，不冒充这些能力的真实执行。

合成样例、模拟连接和模拟回答必须可识别。不得读取真实研究或改变已安装应用，不传送真实资料给设计审阅者。普通状态不展示原生线程、Skills、Plan、历史重放、实现兼容等解释；需要开发者了解的边界放在设计记录。

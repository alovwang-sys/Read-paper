当前隔离预览已通过[17项连续操作检查](verification/workspace-preview/README.md)和[6项真实拖拽专项](verification/workspace-tabs/README.md)，含1440／1280／1024与1157实际窗口的布局检查。本组追加完成7轮真实 Claude Code 讨论，其中3轮实际看图，发现的浮窗遮选区、工具裁切与焦点归属问题已修正；不将静态看图视作实际点击验收。范围是原型：Excalidraw 为真实本地编辑器，资料、PDF与回答为合成样例；没有更改正式软件、模型配置或用户资料。

## 五点放到同一套结构里

| 反馈 | 目标行为与入口 | 边界 |
| --- | --- | --- |
| 两个资料库分不清 | 研究内入口叫“研究资料”；侧栏最底部、分隔线下叫“全局资料库”。前者只显示当前研究关联资料，后者显示全部，有“加入本研究”与“返回研究” | 浏览不自动关联；关联复用同一文献和原文件，不复制 |
| 输入缺权限与语音 | 同一行显示助手、当前权限短标签与带文字的“语音”。点标签才查看可用能力／选项 | 不能给每家助手画同一套权限，也不能把研究工具边界称作系统沙箱 |
| 资源旁聊天与多页 | 默认聊天在中央；打开论文、白板、文稿工作时，当前会话可在侧栏继续。统一标签与既有分屏入口保留多个资源页，各自保存位置 | 换聊天位置不换会话、不复制草稿、不偷偷切经典工作台；双聊天分屏不在此切片 |
| 白板绘图、连线和框选 | 继续复用本地 Excalidraw；卡片、自由笔迹、文字、形状和箭头在同一场景。选择／框选后出现“问选中内容·N项” | 普通箭头只表示人工画线，不自动变为“支持／反驳”语义关系；仅明确选中材料进入请求 |
| 操作不必跳页 | 原文短问答、卡片查看编辑优先在原处浮层完成。浮窗可移到侧栏，长任务可展开中央；关闭仍保存草稿与在途请求 | 一个会话 ID 同时只在一个地方呈现，只有一份逻辑输入和请求状态 |

默认布局保留留白和清晰层级，不常驻多套输入，不增加配置横幅。主资源顶栏只保留资源标签、分屏与聊天入口；浮窗头部只保留继续位置和关闭。详细权限、发送材料与执行过程按需展开。

## 问哪段、带哪些

- 在侧栏直接问：沿用标题所示的当前会话。
- 白板“问选中内容”：沿用当前会话，材料是按下按钮时的选区快照。随后改选区、拖动或改卡片，不更换已加入的材料。
- PDF 选段／卡片“问这处”：创建有名称的局部会话，左侧立即可见；“在侧栏继续”移动同一会话 ID，不搬运复制消息。原来会话的草稿仍保留。
- 框选含所选图形、附属文字、卡片正文和局部图片。箭头连到选区外的节点不自动跟进；不追加整板、邻居、整篇原文或整库。手绘观点不能当成论文证据。
- 明确加入与发送是两个动作。材料可以预览和移除；所选连接不能看图时，保留图片和草稿并阻止提交，不能悄悄只发文字。

切换显示位置不扩上下文、不重新创建运行，也不重放另一段历史。当前请求仍绑定研究、会话和提交时的快照。用户切走或关浮窗后，迟到回复只更新原会话，在左侧同一条记录标记未读，不抢正在读的页面。

## 浮窗里选择会话：只加一个标题下拉

用户继续提出选择已有／新会话、推荐相近主题的需求。最小方案是把聊天标题做成下拉入口，主区、侧栏和浮窗共用这一入口，不再加一条常驻选择栏。

- 点击标题，搜索本研究的会话，或选“新会话”。当前资源页面不跳转，聊天仍在原承载位置。
- 无搜索词时最多展示3条建议。先比较相同文献／卡片／所选元素来源，再用标题与最近5条消息的关键词重合排序；同来源或至少两个有效词重合才标“相关会话”。没有相关结果写“最近会话”，不假称语义最接近。
- 推荐只供选择，不自动换会话，不跨研究扫描，不为此额外调用模型。只有实际用例表明本地匹配经常失效时，才考虑语义排序；不凭空设会话数量阈值或先建向量库。
- 切换恢复目标会话自己的草稿；原会话的未发送文字、历史和在途请求留在原处。新会话从空输入开始。没有自动拼接、覆盖、迁移或清空源草稿。
- 当前选区可用菜单内“带上当前选区”勾选带入，默认开启；只复制冻结材料，按来源／正文／所选元素和范围去重。取消勾选则不带入。它不是合并历史或扩大资料权限。

入口、草稿归属和材料流转已在预览中可点击验证；推荐是保守的本地匹配，不宣称已测真实研究主题的语义相似度。新会话仍需通过发送时的既有上下文校验；推荐到某个会话不授予该会话整篇论文或整库的访问权限。

第5轮 Claude 建议再增加“移过来＋撤销”以及未发送空会话清理；本次不采纳，这会增加新的草稿搬移状态和操作，超出最小入口需求。现有按会话保留的输入与材料已经足够支撑选择、新建和建议。

## 权限与语音必须忠于真实能力

| 连接 | 当前事实 | 应显示 |
| --- | --- | --- |
| 默认研究 Codex | 有研究读取、公开检索、草稿等产品工具；每轮隔离原生运行。未接经典文件访问控件 | “研究工具”；点击查看边界，不画一个无效的三档下拉 |
| 经典 Codex | 运行时目前可能提供只读／完全访问；完全访问已有明确确认 | 显示当前档位，仅列实际可用项；不把尚未开放的项目内写入画成可选 |
| Claude Code／OpenCode 现有适配 | 目前为显式文字问答，禁工具／MCP／图片，不等于外部原生程序完整能力 | “文字问答”；不继承 Codex 的权限和图片能力 |
| 语音输入 | macOS 桌面桥请求系统听写；浏览器和其他平台显示快捷键。系统管理麦克风权限 | 按钮写“语音”；识别文字留在草稿，不自动发。不以派发成功冒充开始录音，不声称支持录音上传或语音通话 |

原型助手选择和权限状态均为演示；语音弹层只演示系统听写指引和一段可放入草稿的例句，不访问麦克风。

## 分屏、来源与小窗口

沿用现有资源窗格和视图 ID，不建立“另一个分屏模式”。论文、卡片、白板、文稿引用共享实体，页面位置和编辑光标按视图独立。普通打开只作用于所属或当前窗格，不清掉其他页。

用户追加明确偏好浏览器式标签：每个窗格有自己的标签栏，可拖动排序、拖到另一组、拖向窗格边缘建立分屏；落下前给接收位置预览。关闭只关闭视图，最后一页关闭后收回空组，资料和草稿仍在。正式方案沿用现有递归标签树及独立阅读位置；本次隔离预览只演示两组，不能据此宣称新的壳已完成所有递归分屏逻辑。

主区为聊天时，引用在右侧参考区打开；主区为资源且右侧在聊天时，引用使用现有资源窗格的新标签或临时原文浮层，保留原位置。用户明确点“在分屏中打开”才建立对照页。

1440／1280保留中央资源和右侧聊天的稳定分区；1024可先收起左栏，仍保留用户分屏树。内容挤时由用户主动放大当前页、再恢复分屏，不自动把其他页收走。浮窗尺寸与位置约束在可见区域，不能遮住自身输入与关闭按钮。

## 为什么旧功能存在却用起来像消失

本轮只读核实得到：

- [App.tsx](../../../src/shell/App.tsx) 在 Agent 模式仍使用 `WorkspaceSplit`；但右侧 AI 被换成会话历史，打开非历史 AI 还会自动切经典工作台。这是需要修的宿主分支，不是多加一个聊天组件就能解决。
- [InlineAIPopover.tsx](../../../src/features/reader/InlineAIPopover.tsx) 和 [inline-ai.ts](../../../src/services/inline-ai.ts) 已有 PDF 局部独立会话与同 ID 右侧继续，不能在新版里删掉或改成隐藏副本。
- [BoardDrawing.tsx](../../../src/features/board/BoardDrawing.tsx) 已包含自由图形、共享资料摆放、原生箭头和框选研究链路；新 UI 应接回它，不重造简陋绘图器。
- [多窗格规范](../../panes/README.md) 已支持递归分屏。当前主页引用未绑定独立 `conversationId`，复制主页不会得到两个独立聊天。
- 前一原型两处“资料库”进入同一内容，权限和语音也只是占位，白板缺原生工具；不能用这些占位证明正式功能已经贯通。

上述源码为本次审计依据，未在本轮重新调用真实模型或操作已安装软件。

## 正式实现顺序

1. 统一会话承载和输入归属，保留研究隔离、草稿、进行中请求与未读；先移除侧聊暗中切经典的行为。
2. 资源旁发送保持原页面；同 ID 浮窗／侧栏／中央继续，引用遵守已有窗格位置。
3. 接回真实能力驱动的权限工具行、VoiceInput 和资料范围接口。
4. 接回既有 Excalidraw、共享卡片、人工关系和选区快照；验证选择范围、来源与图片能力。
5. 三尺寸验证多页、放大恢复、研究切换、刷新、持久化、停止重试和迟到响应，再进入安装包交付。

新布局预览的双页示例不等于已把正式递归窗格、原生连接或数据迁移接入新壳。正式实现前不删除旧绘图或分屏能力。

预览内的场景、会话和资料关联只保存在内存，刷新会复位；没有验证桌面听写、真实研究工具调用、跨厂商原生续接或磁盘恢复。推荐为保守的本地匹配，并非语义相似度质量评测。只有用户明确选择的选区才会带入目标会话。

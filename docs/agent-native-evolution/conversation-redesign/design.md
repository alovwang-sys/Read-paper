# 对话工作台设计规则

后续修订：用户要求保留侧聊、分屏、绘图与局部浮窗，最新规则见[连续工作区](workspace-continuity.md)。资源工作时右侧可以显示同一会话，发送保持原页面；主区会话、侧聊和浮窗只改变承载位置。本页下方保留前一版设计，不再以“资源发送必回中央会话”作为后续目标。

状态：七轮真实 Claude Code 往返已完成，最终可点击原型通过16项交互验证。本页描述目标设计，不是正式应用的已实现清单。

## 一个会话，一处回答

左栏用于会话导航；中央默认显示当前会话的完整问答；右侧只查看引用、资料或参考内容。会话目录不再放在右侧，输入区不重复“发送到”与会话列表入口。头部只留当前会话名和必要操作。

会话列表每条36px、单行标题、选中底色；移除摘要、逐条助手／日期与“当前会话”标签。执行或未读只在发生时用一个小标记显示；后续实现的重命名等操作按需出现。资料与成果为一个入口，原有文献、卡片、白板和文稿都可以找回。

## 从发送到看到答案

| 当前操作 | 发送接受后的去向 | 保留什么 |
| --- | --- | --- |
| 中央聊天发问 | 同一会话原地显示本轮问题、进展和答案 | 上下文、未发送后续草稿与滚动意图 |
| 右侧原文加入选区后发问 | 中央同一会话直接回答 | 右侧原文所在页、选区与可清除材料标签 |
| 中央全文阅读后发问 | 中央回到同一会话，原文停在原页的参考区 | 原文位置和明确加入的问题材料 |
| 全宽白板／文稿发问 | 中央回到同一会话，提供一个“回到原资源”入口 | 画布视口或文稿编辑；不把复杂编辑器硬塞进窄参考栏 |
| 发送前校验失败 | 原页面和输入保留，给一句可操作原因 | 文字、图片、选区材料 |
| 发出后主动切走 | 结果只更新所属会话，出现未读标记 | 不抢当前资源或另一会话，不改写新草稿 |

浏览原文不自动扩大问题范围。用户明确加入的选区才成为本轮材料；消息保留来源，点击可回到同页。回答中的文献提供直接查看／收录入口，避免搬运。长回答完整可读，执行记录默认收起。

白板入口必须打开关系画布，不能用只有“加入提问”按钮的卡片清单代替。打开卡片与提问分开：点击正文查看和编辑，返回白板保留内容、摆放与视口；加入提问固定当时正文快照，后续编辑不改变已加入的材料。当前原型已补三张可打开、编辑和拖动的卡片及随动连线；完整绘图工具仍需接正式应用的已有 Excalidraw。

## 助手选择只做选择

输入区只有一个助手按钮。菜单显示名称、当前勾选与必要连接状态，不展开实现说明段落。普通应用会话换助手时，话题、消息与当前输入保留；已发生的回答继续标注原助手，下一轮才使用新选择，不增加“以下由某某回复”的分隔通知。

| 边界 | 最少反馈 |
| --- | --- |
| 未连接 | 对应菜单行提供“连接”动作，输入不动 |
| 当前会话正在执行 | 助手选择暂不可用；保留当前停止按钮 |
| 原生绑定身份不能切换 | 对应助手行显示“新会话”，复制当前草稿／附件，不从原记录搬走 |
| 已有图片而助手不支持 | 保留附件，在选择时简短说明并允许返回原助手 |
| 运行失败 | 在该轮显示原因与重试；不覆盖失败后写的新草稿 |

这些是目标交互。现有研究工具仅已验证 Codex，跨助手研究工具、不同厂商原生线程与上下文继承仍需工程实现和实测；原型中的模拟选择不能证明后端已具备能力。

2026-10-28 更新：Agent 工作台对 Claude Code、OpenCode、模型直连与演示也使用同一研究界面，不再切回经典面板。它们没有 Codex 的逐页工具，而是每轮随问附送本轮论文页面文字（按连接设单次预算），成果以一个 JSON 成果块返回，再由与 Codex 相同的引用核对写入草稿；不能联网检索或看图。这条“附送原文”路径已有确定性测试，Claude Code / OpenCode 的真实回答质量尚未实测。见[助手连接诊断](../../verification/agent-connections/README.md)。

## 尺寸和阅读

1440×900与1280×800：左栏224px，中央问答按阅读宽度居中；原文打开时右参考区360px，中央分别为856px与696px。1024×800：左栏默认收起，中央664px与右参考360px并列。901–1100px收起左栏；1101–1247px仅在参考打开时收起左栏，普通聊天仍保留导航；≥1248px恢复固定左栏，参考打开时中央至少664px。≤900px参考改为覆盖面，发送后收起并保留原文位置，输入保持可用；导航与参考覆盖不能叠两层。

视觉使用暖灰侧栏、白色主区和统一的品牌绿（#397b65）；正文15px／1.8行高，导航13px，消息内助手名12px。输入框18px圆角、细边框与轻阴影；助手菜单36px行高，状态／连接操作固定右对齐。引用、收录和返回使用相同色系，避免大面积卡片、重复标题与说明段落。

只有一个主要会话滚动区，回复不再塞入固定高度的小窗口。输入随内容增长，保持发送／停止可达；用户上滚阅读时不强制把位置拉到底部。

资料编辑按需使用全宽，不叠第二个输入框。含图片而助手不支持时不得静默丢图并只发文字，必须保留图片并阻止该次提交，直到用户明确选择仅发文字或兼容助手。原型图片与语音只是入口示例，不能代替真实能力验证。

## 进入实现前的最小切片

1. 调整共享导航和会话行，不复制另一套会话状态。
2. 在本轮请求接受时打开所属会话；完成回调只更新所属请求，不做抢焦点导航。
3. 让普通助手切换保留产品会话，旧轮次与原生记录归属不变；按真实能力阻止不可执行的操作。
4. 合并原生／经典记录的阅读入口，避免“点一段记录却被迫切整个工作台”；是否能接续由实际能力决定。
5. 验证多会话草稿、资源编辑、迟到结果、图片材料和未连接状态，再更新桌面安装包。

# Claude Code 产品演进讨论记录

日期：2026 年 10 月 21 日。根据用户明确要求，与真实本机 Claude Code 累计完成六轮讨论；本次在前两轮基础上新增第三至六轮。CLI 版本为 2.1.304，六轮返回模型均为 `claude-opus-5-5`，退出码均为 0、`subtype: success`、`is_error: false`。执行状态与输入量见 [status.json](status.json)。

第一、二、三、五轮只处理所给文字，禁用内置工具。第四、六轮只启用 Read，在临时目录读取提供的截图，分别取得 2 条和 3 条成功的 image 回执；未让 Claude 操作浏览器、修改文件或联网。所有轮次使用 safe-mode、空且严格的 MCP、禁 slash、dontAsk、permission-prompts none，并关闭原生会话持久化。未修改登录或模型配置。各轮以新调用附上前轮答复和主设计者反驳延续内容，不冒称原生会话续接。

Claude 收到产品文档节选、已核实代码事实和用户本轮诉求；第四轮实际查看旧产品截图，第六轮实际查看新原型截图。它没有直接操作产品、读取整个仓库、联网或执行交互验证。它的意见是设计建议，不是实现或可用性验收。原有生产文件与测试改动属于前轮实施，本轮只修改方案与独立原型。

## 讨论如何改变建议

第一轮确认了病因：研究步骤仍依赖用户逐个点击，Agent 缺少对共享应用对象的结构化操作；显式材料和两种画布模式又让实现细节变成了用户负担。第一轮主张画布为中心、默认收录候选和草稿，以及增加公开 PDF 获取能力。

主 agent 对这套建议提出八项反驳，要求压缩范围、保护人工内容，并区分可观察事实和模型判断。第二轮接受了主要修正，收回画布必须主导、阅读器降级、拖动代表采纳及固定三次人工判断。

| 讨论点 | 最终采用的取舍 |
| --- | --- |
| 画布主导所有研究 | 当前成果占中央；比较、关系整理、写作由实际任务决定，深度阅读继续保留 |
| 默认把候选与草稿全部写进正式资料 | 发现与草稿自动保存；正式入库按用户意图批量执行，不污染既有整理 |
| 拖出草稿区视为采纳 | 不采用；浏览、拖动不构成隐形认可 |
| 首切片增加自动 PDF 下载 | 不采用；先用已导入、文本就绪的真实 PDF 验证工具闭环 |
| 每次研究必须经过三次判断 | 不采用；仅关键歧义、范围扩大或缺少不可替代材料时停下 |
| 取消逐条附送就是放开所有目录 | 不采用；应用范围由工具强制执行，本机目录访问能力如实单独说明 |
| 页内原句匹配意味着论断已成立 | 不采用；代码核查出处，独立审阅论断与引文之间的支持关系 |
| 立即移除模式开关 | 统一操作面的方向保留；移除之前完整保留和呈现旧绘图、共享卡片及关系 |
| 新建 CardDraft 组表格模型 | 首切片先用现有正文与来源表达，不先建设单元格管理系统 |

第二轮仍有需要主设计者进一步约束的建议：并非每条有效引文都只能在一页中出现一次，存在多处命中时应定位与核对；整批撤销也不能抹掉后续用户编辑。最终方案保留这两项边界，没有把“唯一命中”和“无条件恢复原状”照单全收。

## 第三至六轮怎样把界面定下来

第三轮指出原方案虽然说明了研究分工，却没有决定输入、对话、引用预览、旧内容与采纳的具体位置。Claude 当时推荐中央对象加永久 Agent 栏的 B 布局。主 agent 用旧界面提出反驳：这种做法主要改名称和工具条，仍保留三栏争夺注意力，新研究仍像先导入资料再去右侧找 AI。

第四轮让 Claude 实际读取文稿与绘图两张旧截图。它收回 B，选择默认单主工作面、唯一输入与临时参考区的 C。第五轮进一步检查无 PDF 发起研究、任务迟到、未发送问题的焦点、问与改的区别、旧内容找回、批量留存、用户编辑冲突和窄屏失败恢复。

第六轮实际读取欢迎、成果与 1024px 来源三张原型图，指出重复的对话记录、资料计数、多层标题路径和每段的编辑提示，要求再删一轮。原型据此调整，同时保留作者、依据和待核查缺口的必要区别。原图与 hash 分别见[旧产品图片清单](claude-round4-image-manifest.json)和[原型图片清单](claude-round6-image-manifest.json)；后者指向修正前的冻结截图，最终图另见[原型验证](../verification/ui-v2/README.md)。

第四轮首次尝试因主 agent 的观测器只接受字面 `/tmp` 路径，未处理 macOS `/private/tmp` 的路径别名而中止，没有取得完整设计答复，未计为一轮完成。修正路径规范化后重跑，记录实际两个图片读取回执。[首次失败](claude-round4-attempt1-failure.json)与成功结果分别保留，没有覆盖成一次性通过。

主 agent 仍没有照单全收后续建议：

- 固定例子中的检索数量、全文可得比例和年份不是项目能力证据。
- 不按问号或“修改”子串判断执行许可；礼貌疑问也可能是明确委托，普通解释不能误写正文。
- 不将用户手改、已有引用或点击采纳当作已核实，不给旧自由箭头自动贴标签或改线型。
- 不把全局删除当作采用资料的撤销；撤销本次关联与删除全局实体分开。
- 不在文本输入里夺走原生 Ctrl／⌘Z 的编辑语义。
- 不能把原文返回、用户编辑保护和窄屏可用性都推到下一阶段；第一份新交付必须同时完成可见主路径和真实工具闭环。

## 尚不能由讨论证明的事情

独立原型的点击与布局检查单独记录，不验证新的结构化工具桥、真实连续研究、生产画布迁移或真实用户的可用性。没有在本轮运行生产回归测试，因为未修改应用代码。首切片需要分别验证确定性权限／来源／持久化、真实模型工具选择，以及实际研究者完成任务的情况。

最关键的产品分歧仍是：直接出现在工作面的 AI 草稿，用户能否分清可编辑初稿与自己采纳的研究结论。若必须再加复杂的确认体系才能分清，就说明这轮减法还没有成功。

收敛后的产品原则见[演进方案](../README.md)，具体布局、触发和返回规则见[界面与交互方案](../ui-spec.md)，可直接打开[固定样例原型](../prototype.html)。

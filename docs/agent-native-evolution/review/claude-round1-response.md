# 第一轮诊断：从"点击驱动的阅读器"到"Agent 推进的研究面"

以下基于你给的事实和文档节选，我没有看过 UI，也没有读完整个仓库。

## 1. 真正的病因

问题不在按钮数量本身，而在于**研究状态只能靠人手推进**。入库、加入讨论、摆放、建卡、连线都是 UI 事件，Agent 没有可调用的结构化操作。所以每多一种能力，就只能多一个入口。

还有两个次要病因：
- 显式材料契约在信任上是对的，代价是用户被迫兼任"上下文管理员"。
- 绘图和卡片布局本是实现差异，却暴露成了用户必须切换的模式。

**聊天中心和 Agent 中心的区别**：
- 聊天中心：主产物是对话文字，用户再手工搬运到别处。
- Agent 中心：主产物是研究对象（问题、文献、证据、结论）。Agent 通过与 UI 相同的服务修改这些对象，对话只用于下达意图和查看过程。
- 检验标准：删掉聊天记录后，成果是否仍完整留在画布和文稿里。

**应退到数据层的概念**：摘录（改为卡片上的原文引用）、摆放实例、搜索批次、请求快照、语义边与自由箭头的区分、会话与助手的绑定、"加入讨论 / 入库 / 放到问题旁"三态。

**应退到高级入口的**：历史轮次选择、字符预算、助手/模型/权限切换、检索年份与方向、版本比较。

## 2. 唯一主方案：一个问题一块画布，Agent 只有一个入口

- **主画面**：研究问题所在的画布，不再分模式。卡片、PDF、手绘和文字在同一层。连线只有一种，可以带"支持 / 限制 / 反驳"标签，标签是用户判断或 Agent 的提议。
- **Agent 入口**：只放在画布底部的输入条。选中什么就以什么为锚点；什么都不选，就以根问题为锚点。
- **运行过程**：在右侧展开为该问题的线程，复用现有 Conversation。工具调用折叠成一行行回执，不另建计划、任务或日志模块。
- **阅读器**：退为"核查器"。点击任意引用，就在中央打开到对应页并高亮，核完回到画布。
- **Agent 产物**：落在锚点旁的"Agent 草稿"分区。它只是普通分区加状态样式，不是新模块。
- **文稿**：保留为唯一输出物。Agent 可以起草，但写入正文必须由用户采纳。
- **左栏**：收为研究切换、本研究的画布与文稿、资料库、设置。

我明确反对两个方向：把右侧聊天做成主角，以及给 Agent 加一个计划面板。

## 3. 完整路径示例

用户在画布上写下："检索噪声如何影响 RAG 回答的可靠性？在什么条件下影响最大？"然后发送。

**Agent 第一段连续执行：**
1. 检索本研究内已有的卡片和 PDF。
2. 生成 2–3 组查询调用 OpenAlex，并去重。
3. 读首批摘要，按"噪声类型 / 度量方式 / 结论方向"聚类。约 8 篇元数据以"候选"状态入库，在草稿区排成对照表，每格标注"摘要层"。
4. 对有开放获取 PDF 的论文尝试下载并校验 hash。

**介入 1**：用户在对照表上划掉不相关的论文，并为付费墙文献补 PDF。这是一次批量判断，不是逐条确认。

**Agent 第二段连续执行：**
5. 逐篇读取 PDF 文本层，寻找支撑或限制的段落。引文必须经服务端在该页文本中匹配通过，才成为 `pdf_quote`。匹配失败或遇到扫描件，就标"未能定位原文"。
6. 把对照表的格子从"摘要层"升级为"原文层"，并提议连线。
7. 起草条件化结论，每句附引用。只有摘要依据的句子显式写成"据摘要"，绝不出现页码。

**介入 2**：用户核查结论所依赖的关键引用（点开即跳到对应页），否决错误的。Agent 据此修订。

**介入 3**：用户采纳或改写结论，写入文稿。

全程只有三次判断。

## 4. 从"勾选材料"演进为"研究范围 + 运行回执"

| 类别 | 内容 |
|---|---|
| 默认可读 | 本研究的卡片、标注、PDF 文本、板结构。通过应用工具读取，逐条记入回执 |
| 自动取回 | OpenAlex 元数据与摘要；开放获取 PDF（单次运行设上限，可在研究设置中关闭）。外发内容仅限 Agent 生成的查询词，在线程中可见 |
| 自动保存 | 候选元数据、草稿区卡片、回执。整次运行可一键撤销 |
| 需明确授权 | 读取其他研究或资料库中未关联的内容；外发卡片正文或 PDF 原文；修改用户写的正文；移动或删除用户摆放的对象；付费或需登录的来源；原生助手的目录写入 |

**降低管理负担的三个做法**：
- 用"排除 / 钉住"代替"加入"。
- 用事后看回执代替事前选材料。
- 范围在研究层设置一次，不必每轮重选。

**必须坦白的边界**：Codex 等原生助手的目录权限不受这套范围控制。所以第一版工具闭环应走应用可控的路径。原生助手即使通过 MCP 接入同一套工具，界面也仍要如实显示"目录可读"。

## 5. 减法清单（均为提案，不删数据，迁移须有旧数据映射）

- **移除**：
  - 绘图 / 卡片布局切换
  - 独立的"找已有依据"按钮
  - "加入讨论"作为必需动作
  - 候选逐条点"加入资料库"
  - 左栏的摘录和研究主页（主页信息并入画布头部）
- **合并**：
  - 入库 + 添加到本研究 + 放到问题旁 → 一个"收下"动作，Agent 默认执行
  - 草稿确认 + 建卡 + 摆放 → 草稿卡直接落板，编辑或拖出草稿区即视为采纳
  - 两种连线 → 一种连线加标签
  - 右侧参考与 AI → 一个线程，对象详情改用画布浮层
- **按需显现**：快照与材料详情、字符预算、历史轮次、助手/模型/权限、检索条件、批次回看、版本比较。
- **保留**：共享实体、来源 id/hash/页索引、来源分层标注、不覆盖用户正文、保存/版本/ZIP 备份、PDF 阅读器、导出、撤销。

## 6. 第一个完整切片

范围：第 3 节路径到"原文层对照表"为止，暂不做结论起草。

**工具（与 UI 共用服务层）**：
- `search_research`
- `search_openalex`
- `save_candidates`（幂等）
- `fetch_open_pdf`
- `locate_quote`（服务端页内文本匹配）
- `create_draft_cards` / `propose_links`（复用现有 before/after 历史）

**新增状态**只有两项："候选"状态，以及线程内的读写回执加整次撤销。

**运行时**：先只做一个。glm-5.3-flash 的多步工具调用可靠性必须先测，不能假定可用。

**判断它是 Agent 产品而不是多几个按钮的标准**：
- 同一任务中用户决策不超过 3 次，且不需要手动选材料。
- 所有写操作都有工具形态，新能力以工具交付，而不是新按钮。
- 用户可以发起后离开，回来再看结果。
- 对照表中的引用 100% 通过服务端匹配。
- 与现状对比点击次数和页面切换次数。

只要用户仍需逐条点击候选，这个切片就算失败。

## 7. 最危险的两个取舍

**一、用默认可读范围替代显式材料。** 这能省掉管理成本，但用户可能说不清结论到底依据了什么。回执能否重建信任、原生助手的权限无法强制怎么办，都必须用真实任务测试，不能靠这次讨论定下。

**二、让 Agent 直接写入共享工作面。** 自动入库和草稿卡落板是这次减法的核心，也最容易污染用户空间、削弱拥有感。草稿区的边界、撤销粒度、状态何时自动升级，需要原型对照来决定。

另外，左栏收到四项和取消画布模式，都涉及数据迁移和既有习惯，同样不宜在本轮定论。建议先做可点击原型对照。

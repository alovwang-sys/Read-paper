# 研究工作台导航与笔记整合方案

日期：2026 年 10 月 17 日。状态：整体调整提案，待评审，尚未实施。

本方案整理用户对导航层级、摘录与卡片、资料库切换和右侧面板的反馈。目标是让用户直接完成阅读、留存、思考与写作，减少为了操作工具而学习的分类。推荐保留五个研究入口，把摘录作为阅读标注和引用来源，把卡片作为统一的研究笔记，并让全局资料库在当前研究环境中打开。

现有 v2 设计及其验收记录仍描述当前实现；本方案供下一轮评审和实施使用，不将下文行为视为已经交付。

## 用户问题与调整决策

| 用户遇到的问题 | 调整决策 |
| --- | --- |
| 阅读、思考与写作不能点击，证据与论证、研究结论却能点击，外观又相似 | 去掉两条分组标题，平铺主要入口；具体白板和文稿显示类型图标、缩进和父子关系 |
| 卡片已经展示摘录，为什么还要管理另一套摘录 | 撤下摘录一级入口；保留阅读标注、集中查找标注和引用来源；卡片容纳原文与个人笔记 |
| 点资料库后研究名、导航、标签和右侧内容都变了 | 保留当前研究身份与工作位置，资料库在中央唯一标签内浏览，提供明确返回 |
| 左右都有摘录和卡片，不知道区别，也容易把右栏都理解成 AI | 左侧负责进入研究集合；右侧只提供参考和 AI 两种模式，参考内容标明范围与用途 |
| 不清楚研究主页、白板、文稿、研究结论的关系 | 统一术语、页面说明和空状态；研究结论作为文稿内容表达，不再作为另一层功能 |

## 产品概念与内容关系

研究围绕一个可修改的问题组织工作。用户可以从阅读开始，也可以先写想法或文稿，再回头寻找资料。下面的关系说明内容如何复用和追溯，不规定必须依次完成的步骤。

| 名称 | 对用户的含义 | 与其他内容的关系 |
| --- | --- | --- |
| 研究 | 围绕一个问题展开的工作环境 | 关联资料与卡片，拥有白板、文稿及自己的工作位置 |
| 资料 | 论文 PDF、文献信息或尚未补全文的线索 | 从共享资料库选入研究；同一资料可以用于多个研究 |
| 标注 | 阅读时留下的文字高亮、区域标记及随手批注 | 保存原文和位置；可以只用于阅读，也可以被卡片或文稿引用 |
| 卡片 | 用户主动收下并准备复用的研究笔记 | 可以只有原文，也可以包含批注、综合理解、问题或假设；可引用多个来源 |
| 白板 | 摆开资料和卡片、比较和组织关系的画布 | 保存摆放、分组与连线；不保存另一份卡片正文 |
| 文稿 | 连贯的研究笔记、对照分析或结论稿 | 可以取用卡片及原文引用；不要求先使用白板 |
| 研究结论 | 对研究问题形成的回答，包含条件、依据和限制 | 写在文稿中；不是独立的导航类别，也不代表系统已判定结论正确 |
| 摘要 | 对论文或其他内容的简短概括 | 区分作者摘要与个人或 AI 总结；本轮不新增独立摘要模块 |

用户界面统一使用“标注”描述阅读留存动作，卡片内使用“原文引用”描述来源。既有“摘录”是这些来源记录的历史名称，迁移时保留内容、身份与引用关系。

## 左侧导航与中央工作区

左侧从上到下为当前研究切换与项目设置、新建研究与搜索、五个研究入口，底部为全局资料库和设置。

```text
当前研究名 ▾  …
新建研究    搜索

研究主页
资料
卡片
白板 ▾
  证据与论证
文稿 ▾
  研究结论

资料库
设置
```

五个主要入口全部可以点击，统一使用类型图标、点击区域和选中状态。白板与文稿的文字打开对应列表，独立的展开箭头控制子项；子项使用更深缩进和较小的类型图标，不能再像静态分组标题。子项名称来自用户内容，不能根据“研究结论”等名称推断对象类型。

已有白板和文稿原名保留，不批量重命名。新研究先展示空列表和明确的新建入口，不自动放入两份容易误认成功能栏目的空内容；用户创建时再命名。

中央仍使用一套资源标签。论文、卡片、白板和文稿各按同一身份复用标签，引用跳转只改变定位，不重复打开同一资源。左侧负责找集合，中央标签负责切换正在处理的内容。

| 页面 | 主要内容与操作 |
| --- | --- |
| 研究主页 | 编辑研究问题、接着上次、引用与待核查问题、最近活动；新研究提供添加资料和新建笔记入口 |
| 资料 | “全部资料 / 全部标注”二级切换；资料沿用阅读状态、补 PDF 和添加入口；标注按资料分组，支持搜索、定位、多选和加入卡片 |
| 卡片 | 统一管理主动保存的研究笔记；按标题、正文和原文引用检索，显示来源与使用关系 |
| 白板 | 白板列表、新建和具体画布；支持取用现有资料及卡片 |
| 文稿 | 文稿列表、新建、正文编辑、引用核对和导出 |

“全部标注”默认属于当前研究；同篇资料在其他研究留下的标注仍可明确展开查看。原有随手记、多选、隐藏与恢复、AI 起草等能力归入该二级视图，不因撤下一级入口而丢失。

## 阅读标注与统一卡片

### 阅读时的操作

选中 PDF 文字或区域后提供“标注”“收为卡片”“问 AI”。只标注时立即保存并允许撤销，不要求起标题或写观点。收为卡片时自动保存或复用来源，并打开带原文引用的卡片；用户可以直接保留，也可以继续补充笔记。问 AI 继续明确区分解释与加入对话，不因选中或浏览而自动发送。

已有标注可直接加入现有卡片，也可以新建卡片。同一标注支持多张卡片，一张卡片可引用多篇资料；防止同一次收录连点或重试产生重复，不限制用户有意创建不同笔记。

### 卡片的展示与编辑

卡片采用同一个编辑器：标题、可选的笔记正文、零到多条原文引用。只有原文时直接展示引用内容；补上正文后展示用户批注或理解。用户无需先选择卡片类别，也无需为了保存原文编写一个观点。

原文引用显示论文、PDF 页码、原句或区域预览及“回到原文”。个人笔记可编辑；保存的原文和出处不随改写笔记或 AI 起草而改变。卡片中的来源引用复用既有记录，不复制出互不关联的摘录。

普通高亮保留在论文及全部标注中，不自动占满主要卡片列表。只有用户主动收录的内容进入卡片；纯原文卡片同样可以放上白板或在文稿中引用。纯原文卡的预览和导出必须显示所引用的原文，不能因为正文为空而输出空白。

卡片可以暂时没有来源。独立的问题、计划和假设不统一列成“缺少依据”的待办；进入文稿的引用再按实际来源和核查状态提示。系统不自动判断一段文字究竟是假设还是已证明结论。

### 来源与核查

保留现有来源 ID、文档 ID、页索引、原文、区域资产和研究归属。编辑笔记、移出研究、移出白板或从某张卡片移除引用，都不删除共享资料与其他使用者的来源。已被引用的来源继续受删除保护，隐藏标注不破坏卡片与文稿的出处链。

研究主页将“结论站得住吗”改为“引用与待核查问题”，只表达代码能验证的情况：来源缺失、引用失效、尚未核对、卡片增加来源后文稿仍未补引用。纯原文卡已有有效来源时，不误报没有依据；界面不宣称有引用就证明观点成立。

## 资料库与当前研究的关系

资料库是跨研究共享的资料与卡片总库；研究内的资料和卡片是对同一实体的关联。查看资料库不会自动把条目加入研究，也不会复制文件。

点击资料库时，在中央打开或激活唯一的“资料库”标签。顶部继续显示当前研究名称，左侧研究导航和原资源标签保留。页面标题明确“全局资料库”，加入按钮明确显示“加入「研究名」”，避免全局页面里含糊的“加入本研究”。

库内列表、筛选、滚动和资料预览使用独立浏览状态，列表到预览的往返只发生在这个标签内，不占用研究的返回历史。需要标注、写研究卡片等研究操作时，先明确“加入「研究名」并打开”，再进入该研究的资源标签。添加已有卡片时，继续由共享服务同时关联其依据资料。

| 场景 | 目标行为 |
| --- | --- |
| 打开资料库 | 研究身份、原标签、研究历史和右侧状态保留；库浏览不自动切右侧到卡片或创建 AI 会话 |
| 关闭活跃的资料库标签 | 回当前研究进入资料库前的页面或资源；该资源已不存在时回研究主页 |
| 关闭非活跃的资料库标签 | 当前页面不变 |
| 从 A 切到 B | 立即恢复 B 自己的页面、标签和右侧状态；资料库标签可以保留，但不抢占活跃位置 |
| 从 B 再进资料库 | 返回点属于 B；加入目标默认 B，不能暗用 A 的旧目标 |
| 刷新或重启 | 恢复当前研究身份、原标签、资料库是否打开与活跃、筛选及预览位置 |
| 没有当前研究 | 可以浏览全局库；加入前选择目标研究；关闭后回研究选择或空工作区 |

加入目标始终可见，提交时固定目标研究。A 的加入请求提交后切到 B，结果仍归 A，迟到结果不抢走 B 的页面。用户在库内明确选择其他加入目标时，按钮同步显示该名称；随后切换研究时，新操作重新以当前研究为默认目标。

库筛选中的“本研究”动态跟随当前研究，A 切到 B 后显示 B 的关联内容；没有当前研究时回到全部。若用户明确按名称选择某一研究筛选，则持续显示该名称并保留选择，与加入目标分别表达。

库浏览不覆盖研究右侧内容。右侧 AI 如仍显示，继续明确标明原研究归属；当前浏览资料不自动进入材料列表。库中未关联内容先加入研究，再由用户显式选择为 AI 材料。

## 右侧参考与 AI

右侧继续复用一个可收起、可调宽、可固定的面板，顶层使用“参考 / AI”两种模式。参考内按照正在做的任务显示内容，并在标题中说明范围；不再把摘录和卡片作为与左侧同名的顶层入口。

| 主区任务 | 参考模式提供的内容 |
| --- | --- |
| 阅读 PDF | 本篇标注、所选原文及收为或加入卡片的操作 |
| 查看或编辑卡片 | 当前卡片的原文引用、找依据和定位 |
| 组织白板 | 选中卡片或资料的详情、来源预览 |
| 写文稿 | 可引用卡片、当前引用的出处链、补引用和回原文 |
| 查看研究内集合页面 | 当前选中条目的详情；没有选择时显示明确的选择提示；资料库例外，按前节在中央预览并保留研究右侧内容 |

参考内部仍可以切换相关内容，支持返回；进入找依据或出处链后，保留任务及原位置。固定后不随普通选区或资源切换自动改内容；切换研究时恢复目标研究自己的固定状态。切参考与 AI 保留各自内容、未保存编辑和未发送输入。

AI 继续使用原有研究、会话和提交时材料快照。浏览参考、切标签、打开资料库或改变选区都不等于加入材料。模型直连仅提交明确选择的材料与历史；本机助手已有的目录权限与累计会话能力按现有界面如实显示，不能把“所选材料”宣称为其全部可访问范围。回答和起草结果归提交时的研究，不自动覆盖现有正文。

## 实施范围与交付顺序

本轮方案保留现有三栏工作台、共享实体、PDF 资产、来源定位、目录绑定、备份与 AI 契约。首先调整入口、术语、展示和导航状态，不为卡片的不同内容形态新建三套功能，也不把多人协作、OCR、自动资料推荐或知识图谱加入本轮。

| 批次 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 方案验证 | 阅读留存、统一卡片、资料库往返、文稿参考四个可点击场景 | 对照现有方案观察任务完成、分类犹豫、来源理解和查找成本，调整主要入口与文案 |
| 框架与状态 | 平铺导航、图标与子项、资料库标签、研究与浏览状态的边界、旧入口恢复映射 | 开关资料库、切研究和刷新不丢位置与内容；旧摘录入口回到资料的全部标注 |
| 标注与卡片 | 资料二级标注视图、直接收录、统一卡片显示、原文引用复用、搜索和纯原文输出 | 轻量标注无需建卡；同源多卡、多源一卡与已有数据都可用 |
| 参考与引用 | 两模式右栏、找依据和出处链、主页核查文案、空状态与错误恢复 | 参考不抢主区、不改变 AI 材料；检查提示准确；三种主区与右侧组合跑通 |
| 集成验收 | 持久化与备份回归、三尺寸验证、关键截图、验收记录 | 按下节逐项验证后再标记完成 |

主 agent 统一维护导航、共享类型、状态迁移、样式和文档；阅读与卡片模块、右侧参考与写作模块在契约稳定后分别派工。执行者不直接修改公共 schema 或建立第二份全局实体。若需要增加持久化字段，先定义最小变更、旧数据映射和备份兼容，再实施迁移。

恢复旧右侧状态时，原摘录与卡片模式映射到参考中的对应子视图，保留原资源、找依据目标、出处链、固定状态和返回历史；原 AI 模式继续归原研究与会话。不能只改模式名称而丢弃原参考任务。

## 验收要求

以下为后续实施的验收要求，不代表本次文档交付已经运行这些检查。

| 范围 | 必须验证的用户路径 |
| --- | --- |
| 概念与导航 | 不解释术语也能找到资料、留下笔记、打开具体白板和文稿；五个入口均可点击，实例层级明确 |
| 轻量阅读 | 留下文字和区域标注，不建卡仍可刷新找回；撤销和失败重试有效 |
| 卡片复用 | 一条标注收为纯原文卡；同一次连点重试不重复；同一来源用于两张卡，单卡引用两篇资料 |
| 来源完整性 | 编辑笔记不改原文；移出白板或移除一处引用不破坏其他位置；纯原文卡的预览、插入文稿和导出不为空 |
| 核查语义 | 个人无来源笔记不产生统一催办；文稿的缺失、失效和待核查提示准确，不把可追溯等同于学术正确 |
| 资料库往返 | A 中文稿和 AI 输入有未保存内容、右侧固定卡片时，进库筛选和预览，再关闭完整恢复 |
| 研究隔离 | A 进库后切 B，B 恢复自己状态；从 B 进出库回 B；切回 A 恢复 A，刷新与重启一致 |
| 加入与迟到结果 | 仅预览不关联；加入成功后复用同一实体；提交加入 A 或 A 的 AI 请求后切 B，结果只归 A |
| 右侧面板 | 主区 PDF 加右侧卡片，主区白板加右侧原文，主区文稿加右侧 AI；切模式、返回和固定均保留内容 |
| AI 范围 | 仅查看标注、卡片和资料库不增加材料；引用通过原有校验，演示与真实调用分别记录 |
| 数据与布局 | 旧卡片、标注、引用和未保存缓冲保留，ZIP 往返一致；1440×900、1280×800、1024px 抽屉可用；覆盖有内容、空、加载、错误状态 |

可用性对照使用同一任务材料：留三处原文和一个想法；综合两篇论文写一张卡片；在较多标注中找回某条原文；从文稿返回来源。观察成功率、犹豫、错误归类及不必要的页面切换。若用户经常独立管理跨论文原文，且二级入口明显拖慢任务，再考虑提升标注入口。

## 对外介绍

Papertrail 是围绕研究问题工作的论文阅读与写作工具。用户收集资料、在阅读时标注重点，把值得复用的原文和自己的想法保存成卡片；需要梳理关系时使用白板，需要表达成果时写成带引用的文稿。资料库支持跨研究复用，右侧参考和 AI 帮助在当前任务旁核对与讨论。

# 白板上的局部研究

日期：2026 年 10 月 20 日。状态：用户确认继续后已接入正式应用；原方案与原型保留作设计对照。实际能力、检查和真实调用边界见[实施验收](verification/implementation/README.md)。

白板中的每个问题都应当能继续追问、补充文献和形成新理解。本轮建议把“选中内容 → 问 Agent 或找文献 → 挑选入库 → 放回原问题旁 → 阅读并继续追问”做成一条连续路径。现有白板生成、人工绘图和整理关系继续使用同一工作台。

入口：[可点击原型](prototype.html) · [上下文与连续探索](context-design.md) · [第二轮核实](review/context-audit.md) · [竞品与来源](references.md) · [开发切片及验收](development-plan.md)。原型使用三篇真实论文的固定样例，问答和搜索过程为模拟，不调用模型或文献 API；入库与卡片仅保留在本页内存，刷新清空。

第一版原型的 20 项交互检查和三尺寸证据见[第一版验证](verification/README.md)，保留[第一版](prototype-v1.html)供比较。第二轮结合 [Claude Code 两轮讨论](review/claude-code-review.md)，补齐材料与历史、独立找依据、同一问题的论文追问、焦点替换与主动保留，以及搜索批次和旧轮快照；[第二版验证](verification/context-v2/README.md)单独记录。正式功能沿用现有工作台与本地持久化，覆盖两种白板模式、绘图文字转问题及多选／分区核对，实际结果以实施验收为准。

## 要解决的体验

用户能让 Agent 生成白板，却在看到某个不清楚的小点时无法接着深入。现有白板主要提供结构展示和整板整理；研究活动仍需要离开画布、重新解释上下文、在外部搜论文，再手工整理回来。

检查代码后，问题集中在三个断点：选中节点没有直接提问入口；普通聊天未必携带选中卡片正文；文献搜索结果没有进入共享资料库的路径。已有板的 Agent 编辑契约还禁止创建新卡片，因此“整理白板”也不能承担继续补充知识的职责。具体代码位置见[实施计划](development-plan.md#现有能力与改动位置)。

用户完成这一轮探索时，应当既多了一份可以继续读的资料，也知道这份资料与原问题有什么关系、哪些判断还需要核查。

## 一次完整操作

以“检索的材料越多，回答一定越可靠吗？”为例：

1. 在白板上点选这个问题。节点附近出现“问 Agent”和“找文献”，已有编辑、连线和移动操作继续可用。
2. 点“问 Agent”。右侧 AI 面板显示正在讨论的问题和本轮材料，输入“如果检索结果里有噪声，会怎样？”。用户核对后发送，主区保持原位置。
3. 回答说明当前材料能解释什么、还缺什么。用户可以继续问，也可以点“找文献”寻找新材料。
4. 右侧显示可编辑的检索词和研究方向。提交后返回候选论文的标题、作者、年份、来源及可用摘要；是否相关需要用户核查。
5. 用户挑选论文，点“加入资料库”。同一资料同时关联当前研究。成功后可以点“放到当前问题旁”，成为同一文献的白板入口。
6. 点击这篇论文，在右侧看摘要，或在主区打开 PDF。没有全文时先补 PDF；不能显示虚构页码或已读标记。
7. 阅读后保存原文依据，回到白板，围绕原问题继续问。把有用的回答编辑后收为卡片，保留对话来源与实际使用的原文来源。

用户也可直接在白板点“添加内容”写一个新问题，然后开始同样的流程。无需先导入论文或先让 Agent 生成整张图。

## 白板与右侧面板

沿用项目现有左栏、中央资源标签和单个右侧面板，不在画布上铺开多个聊天框。中央承载思考的空间，右侧承载围绕当前问题的连续讨论、检索结果和临时来源预览。

```text
白板                                 唯一右侧面板
                                     当前问题：材料越多越可靠吗？
   [材料越多，回答一定越可靠吗？]      本轮材料：1 张卡片、1 条原文
      问 Agent  /  找文献             你的问题 / 回答 / 候选论文
                │                    可编辑输入
       用户选择后放到问题旁
                ↓
   [Lost in the Middle · 待读]
     相关文献，关系待核查
```

| 场景 | 交互规则 |
| --- | --- |
| 选中一张卡片 | 显示该卡片的局部操作；卡片正文与显式勾选的引用可进入本轮材料 |
| 多选卡片或一个分区 | 显示数量并允许展开核对成员，适合比较分歧；不隐含选择整张板 |
| 选中论文 | 明确“问 Agent”后将文献信息作为当前焦点，保留原问题和同一会话；摘要和原文分别标出可用状态，未读全文不会伪装成全文问答 |
| 在空白处提出新问题 | “添加内容 → 问题”创建普通共享卡片并摆放到当前视口，然后可问 Agent |
| 自由绘图中的文字 | “作为问题提问”先预览文字，确认后生成共享问题卡片与摆放实例，保存原元素 ID 和文字快照作为来路，再以问题卡开启讨论。原文字保留；图形、图片和手写笔迹不声称已被理解 |
| 想再找一批论文 | 修改查询、切换方向，或将选中的论文设为新种子；保留上一轮结果和起点 |
| 切到另一张卡片 | 只改变选择高亮，不改写已经准备或提交的问题范围；点击新的提问入口才切换问题上下文，原输入保留 |
| 收起面板或查看来源 | 返回时恢复原输入、结果列表、滚动位置和问题锚点 |

1440×900 与 1280×800 保持三栏。1024px 收起左侧导航，以抽屉打开；白板与右侧仍可同时识别当前问题。右侧继承已有调宽、收起与返回机制。原型只演示此次路径，不把现有导航调整提案一并实施。

## 提问与查文献

“问 Agent”默认附送可见背景、当前焦点和主动保留的材料，不自动开启资料库或外部搜索。换焦点替换自动材料，明确“加入讨论”的材料才持续保留。用户通过独立的“找已有依据”在白板或研究中取回候选，选择后加入问答。应用不默认附送整库；本机助手的目录读取权限另外显示，不把材料清单冒充权限沙箱。

“找文献”明确开启外部检索。提交前展示可编辑的查询、时间条件和材料摘要。默认用小问题生成查询；有明确论文时也能以论文为起点，首轮建议最多展示 10 条。用户点击后才继续下一页或扩展一轮，避免无限搜索。

研究方向可以选择“相关研究”“支持与反例”“后续进展”。这些选项改变检索方向，并不证明结果支持或反对观点。摘要不足以判断时，结果应显示“需要阅读全文核查”。切换到其他研究时，迟到结果仍保留在发起研究的会话中。

同一问题下的论文和观点是不同焦点，追问保留同一会话和原问题。完整历史一直可读；默认发送上一完成轮加最近一次原问题轮，去重，可逐轮调整。该初始策略需用真实任务对照验证，不宣称最佳。输入旁显示材料、历史和找依据入口，全部从同一请求清单计量。移除来源不应让历史重新附送完整原文，但旧回答、派生卡和原生目录仍可能含相关信息。具体语义以[上下文设计](context-design.md)为准。

## 候选文献如何进入资料库

每条候选展示来源实际提供的标题、作者、年份、文献标识、落地页、检索来源和全文状态，缺失字段如实说明。摘要标为“OpenAlex 提供的摘要”，不保证是作者原始摘要。当前不额外生成 AI 相关性文案；排序、摘要和关键词都不能证明论文支持或反驳观点，阅读原文后再判断。

| 动作或状态 | 结果 |
| --- | --- |
| 加入资料库 | 创建或复用全局文献，并关联当前研究；不立即铺到白板 |
| 已在资料库但未在本研究 | 显示“添加到本研究”，复用原实体，不重新建一篇 |
| 已在本研究 | 显示“已在本研究”；仍可放到当前问题旁 |
| 放到当前问题旁 | 为该资料新增或复用当前问题关联的摆放实例；不复制 PDF 或文献实体 |
| 找到公开全文链接 | 显示“可获取全文”；只有下载和校验成功才变为“已导入 PDF” |
| 无法获取全文 | 元信息仍可入库；可打开来源页或使用现有“补 PDF”入口 |
| 撤销这次放置 | 移除本次摆放和相关连线，资料继续留在库中；不撤销其他研究的使用 |

当前去重使用规范化 DOI 和 OpenAlex 来源 ID；标题相似不会自动合并，arXiv 标识及相似标题复用提示留待后续。同一工作可复用已有元信息；遇到不同 hash 的版本 PDF 时保留现有独立文档与资产规则，不自动合并或替换。首版不新增同一文档管理多个版本的模型。

论文刚放入白板时，连线只表示“相关文献 · 待核查”。用户阅读后，将原文依据附在观点卡片中；“支持 / 反驳 / 限制条件”连线仍表达用户判断，不声称系统验证了关系。首版不扩展连线的证据模型。搜索推荐、作者摘要、个人理解、PDF 原文是不同来源层次。

## 把理解补回白板

回答提供“收为卡片”，先打开可编辑草稿，用户确认后创建共享卡片，并选择放到原问题旁。卡片保留对话来源；真正使用了原文证据时，同时保留结构化引用。没有原文时允许保存问题和理解，但不会生成 PDF 页码。

首版不通过“编辑已有白板”的 BoardPlan 直接修改旧卡正文。继续复用已存在的草稿确认、共享建卡和摆放服务，新增内容只增加到当前问题附近。自动生成的联系先作为提议；替换、重排或移出已有内容继续沿用差异预览与确认规则。

当节点附近已经拥挤时，新内容放在最近空位并提供“定位新增内容”，保留原视口返回入口。用户可以自行分组、移动和连线。后续再考虑把成熟的一组探索移动到子白板，首版不自动展开大量支线。

## 失败与恢复

| 情况 | 用户看到什么以及如何继续 |
| --- | --- |
| 没有选中内容 | 提示选中一个节点，或直接写一个问题；不禁用整张白板 |
| 搜索中 | 显示提交的查询、可停止状态；已有白板和输入仍可操作 |
| 查询无结果 | 保留查询，提供放宽时间、改关键词、换方向；不宣称没有相关研究 |
| 服务失败、限流或离线 | 显示真实失败与重试入口，保留已返回结果；不能展示为零结果 |
| 仅部分来源返回 | 明确标出结果不完整；重试建立新批次，旧结果与已加入的材料继续保留 |
| 入库或保存失败 | 按 dirty / saving / saved / error 显示，保留候选与草稿，独立重试不重复入库 |
| 原节点被移走或白板已改动 | 讨论和搜索结果继续保留；入库可完成，摆放前重新确认目标位置 |
| 刷新或切换研究 | 正式实现按研究保存问题会话、查询、结果和输入；结果归属不会跟随当前页面漂移 |

## 首次实施范围

第一轮完整交付局部提问、手动添加问题、一个真实学术检索来源、选择入库、放回问题旁、继续追问、草稿建卡和原文回查。已有 PDF 阅读、补 PDF、共享引用、白板版本历史和备份继续复用。对公开全文的获取单独报告验证结果，不能把“发现链接”算作 PDF 已保存。

现已接入 OpenAlex 的搜索和元数据 API，支持可编辑查询、起止年份、首批 10 条、停止／重试和旧批次回看。限制／反例及当前论文标题只作为可编辑检索词建议，不自动发送。真实匿名查询和年份过滤已验证，缺失摘要与未获取全文分别展示；公开 PDF 链接存在不等于文件已经获取。[官方 API](https://help.openalex.org/api/)。TikHub 用于产品参考检索，学术文献入口不依赖社交搜索。

后续再扩展多来源检索、引文网络、持续更新提醒、自动综述和图形区域理解。详细任务依赖、数据边界和验收见[开发计划](development-plan.md)。

# 白板研究的上下文与连续探索

日期：2026 年 10 月 20 日。状态：第二轮设计已接入正式应用，实际验证见[实施验收](verification/implementation/README.md)。本文收敛[产品方案](README.md)中的上下文规则；[核实依据与审阅结论](review/context-audit.md)保留实施前的官方事实、代码检查和待验证项。

## 采用的方案

沿用现有工作台、唯一右侧面板和紧凑输入区，加入节点附近的“问 Agent / 找文献”。一次探索始终围绕原问题展开，论文、观点和摘录可以成为当前焦点。用户明确另开问题时才产生另一段探索。

上下文分成三件事：本轮主动附送哪些内容，某次查找任务覆盖什么集合，以及执行中实际读过哪些内容。三者分别记录和展示，不能用一个“材料数量”概括。普通问答默认只用明确材料和所选历史。“在当前白板找依据”“在本研究找依据”是独立动作，范围只绑定这次检索任务，不成为后续聊天自动查找的常驻许可。

本机助手还可能拥有目录读取能力。任务范围与文件权限分别显示；当前 Codex 的研究目录权限不能由材料勾选框缩小。只有应用能完整控制输入及工具读取时，才能声称材料范围由代码强制执行。原生模式必须按适配器展示实际能力，不能统一标成严格隔离。

## 默认附送内容

| 层次 | 默认内容 | 扩展方式与边界 |
| --- | --- | --- |
| 研究背景 | 当前研究问题、白板标题、原问题的标题和正文 | 作为研究方向，不当作论文证据；背景在材料详情可见 |
| 当前焦点 | 明确执行“问 Agent”的卡片标题及完整正文；多选时为核对后的成员 | 光标移动、选中或摆放不自动替换；明确切焦点后，旧的自动焦点正文被替换，不持续累加 |
| 结构信息 | 当前问题与焦点的关系、所属分区名称（存在时） | 不默认包含邻居正文；“加入关联卡片”需展开成员并显式选择 |
| 原文依据 | 用户选择加入的摘录、文档标识、PDF 页索引和原文快照 | 卡片已有引用先列为可添加来源，不能因此读取整篇 PDF |
| 文献元信息 | 用户选择“加入讨论”或明确向该论文提问的题录和可用摘要 | “加入讨论”主动保留为附件，切焦点仍保留；只作为自动焦点带入的摘要随焦点替换。入库不附送，未入库候选也可加入 |
| 历史 | 默认上一完成轮，以及最近一次焦点为原问题的完成轮；两者相同只带一次 | 可逐轮选择、全部、最近一轮或不带；默认规则是初始设计策略，须真实对照验证；中断或未通过检查的回答不默认进入 |

研究背景、个人理解、作者摘要、PDF 原文及历史轮次分别建类型，建议使用 `background / card_note / abstract / pdf_quote / conversation_turn`。未入库摘要使用检索来源 ID、URL、访问时间和内容版本，无须伪造本地 documentId 或 PDF 页码。“为何相关”的模型建议不混入作者摘要。

卡片内已有的 `[1]` 不直接当作本轮证据序号；组装时重映射来源。所选历史的引用若对应原文未附送，替换为“历史引用，原文未附送”，不得成为本轮有效编号。只有当前清单中的 `pdf_quote` 可生成 PDF 原文引用；其他来源保留自身类型和可追踪链接。

研究／会话／原问题的定位 ID 与标题可作为可见请求标识保留；若用户取消背景和根问题卡，不能仍从 `originQuestion.description` 等元字段绕回完整问题正文。预览应区分始终保留的名称与可取消的正文。

## 允许查找的集合

“找已有依据”打开一次查找任务，在“已选材料 / 当前白板 / 本研究”中选择范围，确认后只返回候选。可以记住上次选项以减少重复选择，但它不是普通问答的后台查找许可。新任务冻结范围和查询，不改写旧请求；用户无需为任务范围内每次索引读取重复确认。

在应用控制的检索路径里，先读集合索引和命中摘要，返回可核对的候选；找依据任务读取必要原文片段时，另存该检索任务的读取清单与容量记录。用户明确选择“加入讨论”后，这些原文才进入下一次问答的证据集合，不因允许查找整个研究就自动取得回答引用资格。候选预览与正式依据问答分别绑定快照，沿用项目显式选择证据的约定。研究范围之外的实体由服务端拒绝，不能仅靠提示词约束。原生文件工具读取不受该服务完全控制时，界面同时显示目录可访问范围，并将应用记录标成不完整，而非宣称完整审计。

外部文献搜索通过独立的“找文献”动作开启。提交前展示查询与条件，不把研究卡片全文发送给学术搜索服务。该操作可以在说明后使用首批最多 10 条候选的题录和摘要生成相关性建议；读取字段和候选清单保存在该搜索批次。批次中读过的摘要不会自动成为下一轮问答的材料。

找到论文后，用户可看详情、加入讨论、加入资料库或放回问题旁。这些动作分别改变对话材料、资料关联和白板布局，不互相隐式触发。点击论文“问 Agent”明确将该论文作为焦点，但仍保留原问题与这段探索的历史。

## 历史与材料移除

同一问题保存完整对话，发送范围单独选择。初版默认上一完成轮，加最近一次焦点为原问题的完成轮，去重后通常 1–2 轮，避免从论文回到问题时只剩论文聊天。用户可以逐轮选择、带全部、只带上一轮或不带历史；固定保留的研究要点复用用户确认的卡片，不增加新的记忆实体。该结构规则来自 Claude 第二轮建议，是待验证的初始策略，不称为质量最佳值。自动研究摘要留到复杂案例验证以后，不把摘要判断变成原文事实。

材料与历史两个紧凑入口共享同一份类型化请求清单。直接附件、自动焦点、主动保留的材料和选中的历史统一组装、去重、计量；预检、预览和真正发送使用同一结果，不另存一份可能漂移的范围。超限直接定位到具体来源或轮次，允许就地取消，不只给“全部或无”的粗粒度选择。

“不再附送这条材料”同时过滤直接附件和历史来源快照中的副本，不能像当前生产 `snapshotContext` 一样从旧轮次把完整原文重新合并回来。增加可追踪的排除集合；重新明确加入讨论时解除对应排除。此前问答文字仍可能转述该材料，不能承诺信息被遗忘。

卡片保存 `derivedFrom` 的已知来源 ID 和轮次 ID。AI 回答收为卡片后标为“AI 草稿 · 用户确认 · 待核查”；若它与排除集合相交，在材料旁提示派生内容仍在，不能改标为用户原创。背景与卡片里的手动转述也在分支预览中可读，不声称能够识别并清除所有转述。

“以当前材料另开干净分支”保留用户预览确认的背景与当前材料，历史助手消息从零开始；旧会话仍可从问题下的讨论列表返回。它只保证应用请求不自动继承旧助手正文，不能保证原生助手读不到研究目录内的旧会话文件。

历史选择变窄时，原生会话若已持有被取消轮次，必须重建或由适配器确认支持替换历史。当前局部研究每次提交均按同一请求清单新建原生运行，保留应用内的稳定会话，避免旧原生状态暗带取消的轮次。实际 Claude 六轮对照见验收；目录访问边界另行处理，研究目录中的旧文件仍可能被有读取能力的助手访问。

| 动作 | 应用请求变化 | 原生会话处理与残留 |
| --- | --- | --- |
| 明确切焦点 | 替换自动材料，主动保留项不变 | 可复用，但旧焦点内容可能仍在所选历史或原生上下文中 |
| 加入讨论／主动保留 | 加入类型化清单、解除该来源排除 | 不代表该来源成为 PDF 证据 |
| 停止附送来源 | 附件与历史来源快照均过滤该 ID | 历史文字、派生卡与已有原生记忆可能仍含信息，就近说明 |
| 缩小历史轮次 | 取消轮次不进入应用清单 | 已持有这些轮次时重建／替换；能力不支持则明确显示残留 |
| 找依据／找文献 | 独立批次，只产出候选和批次读取记录 | 不自动改变问答清单 |
| 干净分支／另开问题 | 新应用会话，明确预览的材料与零继承历史 | 新原生会话；研究目录中的旧内容仍可能被读取，不称运行时隔离 |

## 长度预算和超限

目前没有实测支持某个通用的最佳 token 数，因此不在原型里伪造 token 精度。原型显示实际文本字符估计、材料数、历史轮数；数字不等于模型 token，也不包括不可观测的原生系统提示和历史缓存。

正式实现应在最终组装后统一预检：问题、背景、卡片正文、文献摘要、原文、历史、工具返回和应用提示分别计量，重复来源按稳定 ID/version 去重。能取得所选模型窗口、tokenizer 或服务端计量时使用真实能力，并为输出与工具开销预留容量；能力未知时显示“模型剩余容量未知”，不能展示一个看似精确的百分比。

集成保留现有保护阈值作为工程约束：问题 4,000 字符、原文证据至多 16 条且合计 24,000 字符、历史问题与回答合计 80,000 字符、服务端业务输入上限 120,000 字符。卡片、摘要和背景计入同一总预算，并预留 2,048 字符格式化开销；客户端与服务端分别检查实际清单和编译输入。相关预算与超限拒绝已有单测。这些不是质量最优值，不能直接换算成 token。

超限时不默默截断原文、丢弃引用或替换用户材料；给出超限来源和可操作的缩减方式。选择保留哪些材料后重新生成发送清单。若某段摘要只是截取预览，要标明截取，不能让模型或用户误认为已读完整内容。

## 每轮冻结与连续探索

沿用 `Conversation` 作为稳定的探索身份，增加原问题起点及当前焦点，不另建一套聊天。用户在同一探索里从问题切到论文、比较论文，再回到问题，仍使用同一会话。明确“另开问题”或“干净分支”才生成新的会话并保留来路。

问答提交时冻结研究 ID、会话 ID、原问题、白板及摆放锚点、焦点、问题、材料正文与版本、历史轮次 ID；普通问答清单不包含常驻查找许可。找依据和找文献分别冻结自己的查询、范围及原问题归属。后续读取记录追加到对应任务，不修改先前的直接附送快照。编辑卡片不会改写过去显示的“当时材料”。

搜索任务以批次保存查询、结果和原问题归属。A 问题搜索期间切到 B，A 的结果仍回到 A；不会以完成时的 `state.context` 或当前选区重新归属。放置默认使用结果批次中的原问题锚点；用户若想放到另一问题，明确选择新目标并留下关联。目标不存在时保留结果，要求重选放置位置。

## 界面如何表达

输入区上方使用紧凑一行：“材料 N / 历史 N 轮 / 找已有依据”，按需展开。材料明细按背景、卡片、摘要、原文和历史区分计数与字符估计。原问题显示在焦点上方，可点击返回。常驻大标题和长引导在首次研究操作后收起，移至空态或说明。

材料详情可核对正文、勾选项、历史轮次和派生来源。每个回答的“当时材料”展示冻结的请求清单、历史范围和已知读取记录；找依据的范围与实际读取保存在其批次。原生工具记录不完整时如实标明。原型只展示模拟快照和字符估计，不伪装真实调用。

## 进入开发前的验收门槛

1. 问题 → 找论文 → 加入讨论 → 论文追问 → 返回问题，全程不丢原问题或已有对话。
2. A 搜索中切 B，A 的迟到结果、查询、来源清单和摆放仍属于 A。
3. 旧轮次发送后编辑卡片，旧轮材料保持原文字，新轮使用明确核对的新版本。
4. 从材料中移除来源后，历史残留有明确说明；干净分支不继承旧助手正文，原生新会话不被旧历史重新污染。
5. 入库不扩大上下文，未入库候选也可明确加入讨论；摘要与 PDF 引用不混用。
6. 增大卡片、摘要和历史长度，统一预检可发现超限；字符估计与真实 token 用量分开验证。
7. 不同助手分别验证实际权限和上下文能力；无法提供严格隔离的运行方式不使用“只能访问所选材料”文案。
8. 研究内找依据返回的原文先显示为候选，只有明确加入讨论后才进入问答引用集合；改变查找范围不自动扩大原文证据。
9. 三种尺寸保持原工作台与单个右面板；材料详情可键盘操作，关闭后保留输入与探索位置。
10. 固定六轮 Q → 原文 E1 → 找文献 → 论文 P → P 追问 → 回 Q，对比仅上一轮、上一轮加原问题锚点轮、全部历史。记录是否记住原结论、是否自相矛盾、是否假称知道未附轮次，以及用户需要补选多少次；真实结果出来前不宣称默认策略优于其他选择。
11. E1 → AI 回答 → 用户确认卡片 → 移除 E1，派生卡回流有说明；历史旧编号不能伪装当前原文编号。取消背景和根卡后，正文不能从元数据绕回。

这些门槛先在原型验证可观察行为，再在真实模型、真实检索和持久化路径分别验收。原型测试不替代正式能力验证。

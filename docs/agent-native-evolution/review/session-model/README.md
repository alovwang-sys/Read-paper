# 会话层级与工作区分工复盘

2026-10-21 复盘记录。后续已完成[多会话修复与验收](../../implementation/session-fix/README.md)，本页复现截图与讨论保留为修复前证据。

原复盘范围：用户体验首版后提出“中间与右侧为什么只显示一条 session”的疑问，当轮核对代码、复现问题并与 Claude Code 讨论；当时没有修改应用界面或数据结构。以下为当时确定的修正方向。

## 已核实的现状

| 层级 | 当前实际存储和行为 |
| --- | --- |
| 研究 | `Research` 包含研究资料，关联共享卡片、文稿和白板；可有多段应用会话 |
| 产品会话 | `Conversation` 有自己的 `requestIds[]` 和未发送输入；每段可包含多轮问答 |
| 一轮问答／执行 | `AIRequest` 记录一次提交、回答、工具读取与产出；它不是一整段会话 |
| 工作区状态 | 代码里的 `Session` 保存打开项、阅读位置和 `activeConversationId`；不是聊天 session |
| 原生运行线程 | 新研究每轮创建独立的 Codex 临时线程，ID 记录在对应请求；应用通过显式历史维持多轮关系 |

底层已有多会话、多轮数据，界面却没有表达清楚：中间只露当前会话最后一轮，右侧主要是当前会话详情；多会话隐藏在下拉框里，新版缺少新建入口与明确的当前话题。研究运行没有维护会话标题和活动时间。“选择助手”还复用了旧路径中按供应商查找最近会话的逻辑，用户无法区分换助手与换话题。

此前把“唯一输入”当成最重要的简化目标，忽略了输入必须属于一个清楚可见的会话。单会话生成、编辑和引用路径验收通过，未覆盖多会话导航；这次反馈揭示了验收范围的缺口。

## 独立窗口复现的两处问题

1. **切换会话会退出新版工作台。** 在全新的浏览器测试上下文中建立两段命名会话，打开右侧记录再选择另一段。`selectConversation` 写入 `aiView='chat'`，被 App 的旧功能兼容逻辑识别成应回经典工作台。见 [复现状态](reproduction.json)、[切换前](two-conversations-before.png)和[切换后](two-conversations-after.png)。
2. **新话题继承旧的局部修改目标。** `agentFocus` 目前放在研究级工作区中。围绕文稿设置目标后新建会话，新会话仍保留同一目标。见 [焦点隔离记录](focus-isolation.json)。只确认继承事实，本轮没有调用模型执行改写。

两次复现均使用隔离浏览器里的种子数据，没有操作用户真实资料或调用研究模型。

## 推荐的修正方向

一个研究可以有“比较方法”和“补查限制”等多段会话；每段有自己的多轮消息、输入与局部追问目标。共享研究资料可供各话题明确取用，其他话题的历史与修改目标不自动串入。成果归研究共享，通过既有请求与成果关联回溯产生过程，不另建一套成果库。

中间默认呈现当前会话的完整多轮过程及成果入口；打开 PDF、文稿或白板时继续复用主区，提供明确的“返回会话 A”，恢复话题与位置。完整问答只显示在一处，长成果通过现有文稿与白板打开，不复制两份正文。

右侧的会话入口先呈现可识别的多会话列表，显示标题、最近活动、简短预览、当前标识与新建入口。点击一条明确的“打开会话 B”导航，一次恢复 B 的完整问答和自己的输入；不要求先预览、再确认继续。仅查看列表、原文引用或成果，不改变发送会话。参考资料与会话列表复用按需区域，不叠加第二个侧栏。

唯一输入归当前明确打开的会话。新话题从独立输入、历史和局部目标开始；已有会话保留各自未发送输入，切换不丢内容。打开其他会话产生的共享文稿，不自动把发送目标切过去；围绕文稿继续研究需要明确选择对象。

选择助手与打开话题需要分开。已有原生会话保留供应商和续接约束，不能为了界面统一强行修改原生身份；应用研究话题也不应在换助手时无提示跳到另一段旧对话。当前新增研究工具仅接 Codex，不能借本次复盘宣称已经支持跨运行时无损续接。

## 讨论证据与取舍

第一轮 [实际输入](round1-input.md)、[Claude 回复](round1-response.md)；第二轮 [反驳与边界](round2-input.md)、[Claude 回复](round2-response.md)。执行状态见 [status.json](status.json)。首次较长输入的尝试在 180 秒超时，保留为 `round1-attempt1-*`；缩短输入后重试成功。第二轮首次调用在 240 秒超时，保留为 `round2-attempt1-*`；缩短为核心反驳后重试成功。两次超时均不计入完成轮次。

采纳完整对话连续性、可识别的多会话层级，以及导航与发送目标需要明确的意见。没有采纳“会话列表每次必须先预览再点继续”的额外步骤，也不在本轮重命名内部类型、新建通用 Agent 平台或强行改造供应商会话。第一轮把当前显式历史称为“摘要重放”、认为产品已经宣称原生无损续接，不符合现有实现与界面说明，已在第二轮纠正。

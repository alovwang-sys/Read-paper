## 结论

7 条反驳基本接受，我上一轮的建议有三处需要更正：

- **只传结构文本不能算"看图"。**
- **我漏了 sources 的默认附件问题。**
- **我漏了卡片正文的问题。**

## 最低可接受切片（目前全部未实现）

1. 选区触发"问Agent"，生成冻结快照。快照包含：
   - 局部 PNG；
   - 选区结构（节点、两端都选中的箭头、跨界连接标为"选区外"）；
   - 卡片正文快照及其 ID/位置映射。
2. 预览内容就是实际发送的内容。
3. sources 默认为空，问图附件只读，不带文稿修改目标。
4. 请求绑定研究、会话和快照。切换后迟到的答复只进原会话。
5. 只有验证过支持图片的适配器才发送图片。不支持时明确提示，由用户选择仅发结构或换连接。选择仅发结构的回答要标注"未看图"。

## 最关键的两项验收

1. **发送载荷审计**：实际请求与预览逐项一致，不含未选节点，不含研究 PDF（除非用户显式要求）。
2. **会话隔离**：切换会话后，迟到答复不抢主区，也不改写旧稿。

## 我仍反对的一点

第 6 条（基于图找论文）不应进入最低切片，应放到第二切片。理由：
- 它新增外部工具权限，会扩大本轮验收面。
- 即使只发关键词，关键词也可能来自用户私有笔迹，发出前应可预览和编辑。

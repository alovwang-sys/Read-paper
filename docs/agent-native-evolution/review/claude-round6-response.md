# 第六轮验收：三张原型截图

我用 Read 打开了三张截图。下面的判断只来自截图和给出的说明，我没有点击过原型。

## 1. 三张图里能确认的变化

**确实减轻了负担的地方**
- **右栏不再常驻。** 1440 宽时主区约 1236px，正文限宽约 800px 并居中，旁边没有右栏；旧图是 780 加一条 420px 的常驻右栏。正文宽度差不多，但旁边少了一整栏争注意力的东西。
- **控件少了。** 结果页可点的控件我数下来约 25 个，旧图约 50 个。三处保存提示、"作为问题"的模态框、"材料 / 历史 / 字符"计数行，图上都没有了。
- **输入框只有一个。** 欢迎页的输入框在中央，结果页移到底部，宽度和正文一致。
- **1024 宽是"推窄"而不是"盖住"。** 参考区约 350px，主区约 674px。第 02 项还保持选中（绿边），底部输入框没动，参考区里原句高亮，下半部分空着，没有拿说明文字填满。
- **"还缺什么"块。** 它直接写明结论的边界，这是产品内容，不是装饰。

**仍然杂乱的地方**
- **同一信息重复出现。**
  - "对话记录"出现 2 次（已知）。
  - "可直接编辑"出现 4 次：每张卡一次，回执行一次。
  - "3 份资料"在结果页出现 3 次：顶栏"资料·3"、输入框标签、"原文 3/3 份"。欢迎页另有一处"已备好 3 份示例"。
- **身份信息叠了好几层。** 顶栏面包屑"检索与回答可靠性 / 检索材料与回答可靠性·初稿"，正文里又有一行"研究笔记 / 初稿 v1"，再加上标题。同一件事有四个名字。正文第一段之前约有 240px，其中两行是路径。
- **欢迎页在发送前就有了研究名。** 侧栏和面包屑已经显示"检索与回答可靠性"，这和第五轮场景 1"发送时才建研究"不一致。
- **"围绕这里追问"每张卡常驻一份。** 在 1024 宽下这一点更明显。

## 3. 最终 6 条设计规则

1. **一个主内容，至多一个参考区。** 参考区里的内容互斥，打开时推窄主区；主区窄于 560px 时才改为覆盖。关闭按钮位置固定。
2. **一个输入框，最多一个焦点。** 输入框只在两个位置：空态居中，其他时候在底部。只有显式点"围绕"才改焦点，可撤销；浏览永远不改焦点，也不清草稿。
3. **同一信息每屏只出现一次。** 名称、计数、入口各有唯一位置，重复的就删。
4. **状态只在例外时出现，且只在活动行。** 保存、权限、预算默认不显示，只显示失败、需要批准、已完成；不加徽章。
5. **作者和依据是两个独立属性，用文字标。** 作者：Agent / 你 / 你改过。依据：全文 / 摘要 / 无出处 / 你画的（未论证）。人工编辑只改变作者；Agent 的改动不覆盖人改过的内容，只给行内建议；界面不设"已核实"。
6. **离开就有返回，迟到不抢焦点。** 替换主区内容时出现返回条，回来后恢复滚动位置、光标和视口。完成通知只出现在活动行和左栏圆点。

**四种场景怎样共用这些规则：**
- 阅读：PDF 是主内容或参考区的内容；选中原文后点"问"，生成焦点标签。
- 写作：表格行和段落带作者和依据标注。
- 画布：卡片同样标依据，自由箭头标"你画的"；画布工具只在画布里出现，不进顶栏。
- 研究对话：只出现在参考区和短答里，不单独占一栏。

## 4. 移除 / 合并 / 保留

| 项 | 处理 |
|---|---|
| 输入框下的提示行（含第二个"对话记录"） | 移除 |
| 每张卡的"可直接编辑" | 移除，改为"作者 · 依据" |
| 正文里的"研究笔记 / 初稿 v1" | 移除 |
| 输入框里的默认范围标签 | 合并进"资料·3" |
| 顶栏两段面包屑 | 合并为一个研究名 |
| "围绕这里追问" | 保留，但只在悬停或选中时显示 |
| 原文高亮和"阅读全文" | 保留 |
| "还缺什么"块 | 保留，进入正式产品 |

**落地顺序**
- **第一步：界面和真实工具闭环一起交付。** 在真实应用里，对 3 份已导入的 PDF 做到：
  - 唯一输入框，从居中移到底部；
  - 真实模型读页，逐行写比较表，引用对应真实页码；
  - 区分问和改：只问就给短答，要求修改才动表；
  - 点引用，参考区打开原文并高亮原句；
  - 活动行和停止按钮；
  - 作者和依据的文字标注。

  同一版里撤下旧右栏、模态框和保存提示。旧白板和旧卡片要能通过 ⌘K 找到。
- **第二步：** 中央深读和返回条、行内建议、统一画布及旧绘图迁移、跨研究采用资料与去重、1024 宽下的折叠顺序、导出文首状态说明、活动行里的权限请求。旧入口要等旧内容全部能找到之后再撤。

## 5. 是否推荐给用户评审

**推荐评审。** 第 1–3 项和"对话记录"去重改动很小，建议先改完再拿去评审。

这是**可评审的设计**，不能**生产交付**：原型的数据全在内存里，不调用模型，不解析真实 PDF，也不保存。

**有一个争议只能靠用户试用来定：** 在 1024 宽深读 PDF 时，短答一直留在输入框上方、直到下次发送（第四轮的坚持），是方便追问，还是挡住了阅读？需要让用户在窄屏上真实地连续追问几轮，再决定是否收紧这条规则。

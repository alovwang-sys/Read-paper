# 第三轮：把"一个工作面"画成线框

## 1. 旧提案中仍然含糊或矛盾的地方

以下依据根 agent 对 1440×900 截图的文字描述，我没有看过截图。

1. **"一个工作面"自相矛盾。** 提案说"按任务呈现比较内容、画布或文稿"，又说"不因工具调用自动切换页面"。如果用户正在白板上，要求做比较，比较表出现在哪里，提案没有回答。
2. **Agent 输入位置没有定。** 第二轮说放在中央底部，现状是右栏 420px，提案只说"只保留一个"。输入框放在中央，消息流、回执、追问就没有地方显示；放在右栏，又和"右侧是参考位"冲突。
3. **引用预览和对话抢同一个位置。** "点出处看原文"如果在右栏打开，聊天就被顶掉；"深读后回到原位"没有说明返回入口和返回目标。
4. **长回答和文稿重复的问题没有规则。** 现状是文稿和 AI 长回答显示相似内容，提案没有规定哪些内容只进对象、哪些只留在对话里。
5. **"按需浏览资料"没有落点。** 摘录、卡片、旧白板去了哪里，用户怎样找回上周的东西，提案没有交代。
6. **"一次采纳"没有位置。** 草稿和定稿在界面上怎样区分，导出时怎样区分，都没有说明。

## 2. 两种结构的比较

- **A 对话流主导**：中央是对话，成果在侧边就近打开。
- **B 持久研究桌面主导**：中央是对象标签页，右栏固定为 Agent 线程，输入框在右栏底部。

| 场景 | A 对话流主导 | B 研究桌面主导 |
|---|---|---|
| 新研究首屏 | 好：一个大输入框 | 中：需要设计空态，引导用户看向右侧输入框 |
| 继续已有研究 | 差：成果埋在滚动的对话里 | 好：恢复上次的标签页和滚动位置 |
| 深读 | 差：阅读器被挤进侧栏 | 好：阅读器是中央标签页 |
| 画布操作 | 差：画布只是附属预览 | 好：中央全宽，Agent 在旁边 |
| 1024 宽 | 好：单栏 | 中：需要收起规则（见下文） |

我也考虑过第三种结构 **C：桌面加中央底部命令条，不设对话栏**。它在 1024 宽下很干净，但追问"你为什么这样分"、运行回执、权限请求都没有地方放，最后只会长出浮层或第二个面板，所以不采用。

**结论：选 B。** 研究是长期积累对象的工作，A 只在"第一句话"这一个场景占优。B 的首屏弱点用空态解决，不靠移动输入框来解决。

## 3. 推荐线框（1440×900）

```
┌左 216–232──┬──────中央 ≈800（自适应）──────┬──Agent 栏 384–400──┐
│研究名 ▾  ＋│[比较表·草稿●][论文B p7][白板1] │检索噪声 ▾    ＋    │36
│⌕ 查找 ⌘K   │对象工具条（随对象变化）       │                    │36
│最近         │                               │ 你：比较…          │
│ ▪比较表     │                               │ ▸已读4篇12页·缺1处 │
│ ▪白板1      │    表 / 阅读器 / 画布 / 文稿   │ ▣已写入《比较表》v2│
│ ▪论文B      │                               │   查看差异 · 撤销  │
│全部内容     │                               │────────────────────│
│总资料库     │                               │范围:本研究·焦点:第3行×│
│             │                               │[输入 2–8 行]       │
│⚙ 设置       │                               │模型 ▾      发送/停止│
└────────────┴───────────────────────────────┴────────────────────┘
```

- **中央顶部从三行合并为两行。** 对象标题并入标签，双击标签即可改名。
- **右栏顶部合并为一行。** 只保留线程名、▾（历史线程）、＋（新线程）。

### 默认常驻顶级控件（6 类）

1. 研究切换（含新建研究）
2. 查找（⌘K）：搜本研究的全部对象和总资料库
3. 左栏内容导航：最近、全部内容、总资料库
4. 中央标签栏和对象工具条
5. Agent 栏：线程、唯一输入框、范围标签、模型标签、发送/停止
6. 设置

### 从主界面撤掉的旧入口

- **左栏**：研究主页、资料、摘录、卡片、白板子项、文稿子项。它们改为"全部内容"标签页里的类型筛选，旧数据原样显示。
- **右栏**：摘录/卡片/AI 模式行、刷新按钮、单独的助手行（并入模型标签），以及底部折叠的材料/范围/白板工具条。白板工具回到白板自己的工具条。
- **流程类入口**：逐轮勾选"加入讨论"、"找已有依据"按钮、"让 Agent 整理"按钮、候选逐条三个动作、"生成卡片→确认→摆放"链。
- **白板模式切换**：改为单一工具条（选择·文字·卡片·形状·画笔·连线）。首期仍保留两层数据：画笔和形状写入旧绘图层，卡片写入卡片层。手绘箭头用灰色虚线并标"手绘"，关系连线用实线并带标签。

## 4. 新研究的三屏

**第 1 屏：新研究刚建好**
- 中央空态：拖入 PDF 的区域，加"从总资料库添加"。下方三条示例问题，点击后填进右栏输入框。中央不另设输入框。
- 右栏：输入框在空态下最高 8 行，占位文字为"想研究什么？"，范围标签显示"本研究·0 份资料"。
- 研究名在首轮对话后由 Agent 拟定，可以在左栏直接改。

**第 2 屏：发送之后**
- 右栏：用户消息下方出现一条运行行，例如"查本研究→读页→定位"，发送按钮变为停止。点击运行行，步骤和回执在原处展开。
- 中央：Agent 新建对象时，规则如下。
  - 如果中央是空态，或者用户正看着的就是目标对象，结果在当前位置出现。表头先显示"覆盖：读原文 0/4"，内容逐步填入。
  - 否则只新增一个高亮但不聚焦的标签，线程里出现"已新建《比较表》→打开"。
- 如果本研究没有资料，Agent 在线程里请求扩大到外部检索。用户同意后，候选以一个中央标签页列出，并提供一个批量动作"收入本研究"。

**第 3 屏：结果完成后**
- 中央：草稿表。表头一条显示"草稿 v1 · 4 篇原文 / 2 篇仅摘要 / 3 条未读 · [采纳为定稿] [撤销本次]"。
- 草稿状态：标签上带"草稿●"标记，草稿导出时自动加"草稿"水印。这样回应第二轮留下的分歧，又不回到多步确认。
- 右栏：只放结果卡和 2–3 句缺口说明，**不重复表格正文**。
- 正文去向规则：结构化或长篇产出一律写进对象；对话里只保留短答、追问和结果卡。

## 5. 继续、深读与找旧工作

**继续已有研究**
- 打开研究时恢复上次的标签页组和滚动位置，右栏恢复上次线程。
- 旧线程在线程名 ▾ 里。旧的摘录、卡片、白板、文稿在"全部内容"里按类型和时间筛选，也可以用 ⌘K 直接搜。

**引用与深读**
- 点击引用：在引用旁弹出约 380×260 的浮层，显示页图截取、高亮原句和页码。浮层不占用右栏。
- 点击浮层里的"打开原文"：阅读器作为中央新标签打开到该页。阅读器顶部有返回标签，如"← 比较表·第 3 行"，⌥← 也能返回，回到原标签和原滚动位置。
- 在阅读器里选中文字：出现浮动小工具条（摘录 / 问 Agent）。"问 Agent"只把右栏输入框的焦点标签改为"论文B p7 选区"，不出现第二个输入框。

**其余"按需"内容的触发和位置**

| 内容 | 触发 | 出现位置 |
|---|---|---|
| 模型、权限、技能、字符预算、历史轮数 | 点模型标签 | 输入框上方的弹层，约 6 项 |
| 扩大范围（加总资料库、外部检索） | 点范围标签；或 Agent 需要更大权限时 | 弹层；Agent 发起时为线程内的请求卡 |
| 差异确认 | Agent 要改用户改过的内容 | 线程内的差异卡，对象里同步高亮 |
| 论文元数据 | 在全部内容中点论文行 | 该行原地展开 |

## 6. 1024 宽的变化

- 左栏收成 48px 图标栏（研究、查找、最近、全部内容、设置）。"最近"点开后是弹层。

我的反驳：
1. B的左216+右400常驻，中央不足一屏，你的‘6类控件’只是把二十个控件分组；新项目仍以导入PDF空态为中心，研究目标被挤到右边，正是用户抱怨的阅读器外挂AI。
2. 你拒绝C理由是历史/过程/审批没地方，这不是充分理由。可复用唯一临时参考区：对话记录/来源/资料在此互斥打开，默认闭合；单行活动与短解释在同一个底部输入上方，长成果只在中央，输入不变。用户没有问‘为什么’时，不需永久留一栏给解释。
3. 建议C的具体形态：研究主工作面单列优先。左栏只研究列表、最近打开项和底部资料库/设置，可收起。空研究中央一句目标输入（整个产品只有一个），同处可拖资料；发送后这个同一输入固定到主区底部，中央出现Agent写出的持久成果与一行实际进展。普通短答只在输入上方简短展开，不强制生成卡片。引用点击开一个右侧临时参考区，深读开中央原文且有明确返回成果。全文对话、资料、设置都是明确触发才开同一参考区，绝不叠第二个drawer，也不藏一个几十项垃圾菜单。已有研究恢复上次成果或PDF，底部输入仍在。
4. C要自己承担难点：空态到运行输入移动必须只在提交时发生；长对话入口要易发现；任务产出为新对象且用户正在深读时不抢画面；打开来源不改变既有编辑目标；1024时参考区怎么与输入共存。请认真处理，不因难点又长出一套面板。
5. 你第一版‘草稿->采纳为定稿’又造强制收尾。自动保存AI初稿，用户能直接改；明确保留/采纳可一批操作，但不能把点击它当作科学结论正确。导出状态说明即可，Markdown没‘水印’能力不应虚构。模型/权限/技能/预算也不应全堆模型菜单。
6. 用户明确说‘找论文’时已经授权公开学术检索，空项目不要再问一次‘允许检索吗’；跨研究私有资料/付费另说。手绘线型属于用户表达，不能统一时悄悄强改为虚线并贴手绘标签。

# 以 Agent 推进研究的产品演进方案

日期：2026 年 10 月 21 日。状态：方向提案；2026-10-21 已交付首版子集，见[实施与边界](implementation/README.md)。下文完整演进方向不代表全部已经实现，实际能力以实施记录为准。

用户进一步要求具体简化 UI 后，已追加第三至六轮真实 Claude Code 讨论，包含旧产品与新原型的实际图片审阅。当前唯一推荐布局和交互以[界面与交互方案](ui-spec.md)为准，可直接查看[固定样例原型](prototype.html)；下文保留研究分工与工程边界，不再把“一个工作面”留成未决定的布局。

产品应让用户交代研究目标，由 Agent 连续取证、整理和修订，让可核查的成果直接留在研究工作面。用户主要决定研究方向、判断关键证据和修改成果，无需学习资料、摘录、卡片、摆放、白板模式之间的搬运顺序。

当前的问题是工作分配：用户在推进研究，AI 负责其中某一步。此前接通局部提问与文献搜索，解决了“这一步能不能做”，没有解决“谁负责把整件事做完”。收起按钮、把聊天框放大，都不足以改变这个分工。

## 一次研究应怎样发生

用户说：

> 帮我比较这些论文：检索材料增加时，回答在什么条件下反而更不可靠？先用本研究的资料，整理证据和分歧，形成一份我能核查、继续修改的结果。

1. **Agent 开始工作。** 输入附近用一句话显示本轮范围与产物，例如“本研究资料，由当前模型处理必要片段；生成比较初稿”。方向清楚就开始，只有影响结论的关键歧义才询问。用户不必先选历史、卡片类型、白板模式或技能。
2. **Agent 自行推进。** 找到相关资料、读取必要页面、定位原文，按实际发现决定补查哪一段、重找什么关键词。进展只展示已查到、正在查和缺什么，不输出另一个需要用户逐项操作的计划表。
3. **成果直接出现。** 比较问题呈现可编辑的比较内容；梳理关系时呈现画布；写作要求呈现文稿。复用中央工作区与现有资源标签，不增加“成果中心”。结果本身写清读了几篇原文、哪些只有摘要、哪些未读，不能把覆盖缺口藏在执行详情。本轮草稿自动保存，聊天里只交代进展和改动，不要求再复制答案、生成卡片、保存并摆放。
4. **用户直接核查和纠正。** 点出处查看对应原文；也可深读整篇论文。回到原工作位置后，说“这里混淆了检索数量和噪声比例，重新比较”，Agent 只修订受影响的内容，保留来源与改动记录。
5. **按意图留存。** “把采用的文献收进资料库”“把这部分整理成关系图”都由 Agent 批量完成。无须逐篇入库、加入讨论、摆放。用户手改的正文不会被后续运行悄悄覆盖。

这里没有规定必须经过三次确认。普通研究应直接给出初稿；扩大范围、需要不可替代的材料、改写已有成果时才出现相应决策。

## 一个持续工作的研究空间

左侧保留研究切换、最近打开的内容和按需浏览资料的入口。资料、标注、卡片、白板、文稿继续作为共享对象存在，分类管理退为辅助视图，不再是必须学习的研究步骤。

中央保持正在处理的成果。首次进入空研究时，从目标开始；已有研究恢复上次内容。Agent 在现有工作位置给出可见结果，不因每次思考或工具调用自动切换页面。完整论文阅读仍可独立进行，不把阅读器缩成只能核对一句引用的窗口。

整个研究只保留一个持续可用的 Agent 输入。选中内容时，输入范围清楚显示“围绕这里继续研究”；未选中时沿用当前研究问题。来源、执行详情与高级设置按需展开，避免多处聊天框、多个材料面板和一套新的任务导航。

卡片、论文入口、自由文字和图形应能在同一画布操作。卡片是可复用内容，绘图是表达工具，不再让用户在两套互斥工作面之间来回切换。统一前保留旧绘图的可访问入口；只有旧内容、关系和编辑操作都能完整呈现后，才移除模式开关。

## 明确做哪些减法

| 当前主路径上的负担 | 调整方向 |
| --- | --- |
| 先理解主页、资料、摘录、卡片、白板、文稿，再选页面 | 以当前研究与正在做的成果为主；分类收进资料浏览，不删除底层对象 |
| 左侧摘录／卡片与右侧同名模式 | 参考内容跟随所看的对象出现，减少重复入口 |
| 问 Agent、找已有依据、找文献三个独立决定 | 一次研究委托，由 Agent 在许可范围内判断使用已有材料还是外部检索；手动搜索仍可用 |
| 候选分别入库、加入讨论、放到问题旁 | 按“采用这些资料”的意图批量关联和组织，不再要求了解三个内部状态 |
| 回答先选范围，再生成卡片、确认、保存、摆放 | 直接产出可编辑且带出处的研究草稿；需要正式留存时一次采纳或一句话批量处理 |
| 卡片布局与绘图切换，两种箭头含义难懂 | 同一画布编辑；来源和关系含义在对象上说明，手画箭头不会自动成为经核实的论证 |
| 每轮配置材料、历史、字符预算、助手、技能、Plan | 普通运行只显示研究范围、当前焦点和状态；具体材料回执与运行选项按需展开 |
| 独立“让 Agent 整理”及重复指定目标 | 当前成果和明确选区作为目标；重排或改写用户内容仍先给差异 |

保留直接阅读、手写笔记、拖动、编辑、引用跳转、停止、撤销和导出。直接操作比语言更快时，继续允许用户直接做，不把每个动作变成一次模型请求。

## 上下文由 Agent 取用 用户保留边界

当前实现要求用户逐项准备附送材料。提案把这件事调整为“明确委托范围，Agent 自行取回必要材料”，具体规则在实施时同步修改产品契约，不能只改提示词。

| 内容 | 提案中的默认规则 |
| --- | --- |
| 当前研究资料 | 在本轮明确的研究范围内查找；由当前所选模型处理必要片段，实际采用的材料、页面、版本可查 |
| 其他研究与未关联的总库内容 | 不默认读取；用户扩大范围后才取用 |
| 选择与浏览 | 可提供焦点，但不自动扩大允许读取的资料集合 |
| 用户明确排除的来源 | 在后续查找、附送和历史材料中继续排除；不因一次自动研究委托悄悄恢复 |
| 对话历史 | 用于保留研究目标与已做的决定；事实依据仍回到可追踪来源，不以旧回答代替原文 |
| 外部文献搜索 | 在用户要求补充研究时生成可见查询；不把私有卡片或整篇 PDF 正文当作搜索词外发 |
| 无全文文献 | 仅按题录／摘要处理；无法定位原文就保留缺口，不生成 PDF 页码或声称已读全文 |

首版不建设语义向量库或无限记忆。范围内查找与按需读页就先验证是否能完成任务，沿用字符总预算；超限由 Agent 缩小取回范围或给出明确缺口，不要求用户日常管理 token。

本机助手的目录访问权限与应用材料范围分别表述。当前 Claude 文字连接禁用工具，不能声称它已能操作应用；Codex 可访问目录也不等于受到了单卡限制。只有通过应用可校验的工具边界，才能承诺范围内取用。

## 自动保存不等于自动认可

候选发现和 Agent 初稿复用已有候选记录、草稿和白板变更历史保存，不新增一套收件箱或任务中心。尚未采用的论文不默认进入精心整理的资料库，AI 初稿不默认升级为用户认可的论断。

用户已经委托“保存这些文献”时，直接批量完成去重、关联和留存，并显示实际结果。保存范围不明确时，先留在本轮发现中，供后续继续研究。拖动、浏览或切换模式都不作为隐形采纳。

Agent 可新建自己的草稿并整批撤销；改写用户正文、删除内容或大范围重排时展示差异。撤销只撤回本次仍可安全撤回的修改：已被用户改写或复用的内容保留，冲突需明确呈现，不能承诺无条件回滚一切。

## 第一阶段只证明一个完整闭环

先用同一研究里已经导入、文本就绪的三份可核查 PDF，完成“一句比较要求 → Agent 自行找材料并读取 → 带原文出处的结果直接保留 → 一句话修订”。同一版必须交付单主工作面、唯一输入、成果直出、临时参考与明确返回，并撤下主路径中多余的搬运入口；只完成后台工具桥不算完成。沿用现有宿主、画布、编辑器和共享数据，不先建设自动下载或多来源平台；完整混合画布与旧绘图迁移另按兼容要求推进。

真正缺的工程能力是：让一个经过实际验证的模型连接调用应用的查找、按页读取和草稿提案服务，并根据返回结果决定下一步；沿用现有研究身份、来源校验、幂等保存和变更历史。界面与 Agent 操作同一份对象，不让模型直接随意写工作区 JSON。

最少的工具职责是范围内找资料、读取来源、提交或修订带出处的草稿。一次请求先取得真实工具结果，再决定继续、修正、给出缺口或停止。这个循环需要有可见的工作上限、停止和检查点；不另建通用编排平台，也不要求首轮让所有助手达到同等能力。

第一份比较用现有草稿正文中的表格与结构化来源表达，不为它先建表格实体或单元格管理系统。沿用草稿版本号保护用户修改；只有真实使用证明正文编辑不足以处理比较，才扩大编辑模型。

闭环成立后，再将现有 OpenAlex 搜索交给 Agent 调用，并统一卡片和绘图的操作面。自动获取公开全文另作后续能力，不能把“找到链接”显示成“已经阅读全文”。

## 用行为验收转型

以下是下一轮的验证要求，不是当前已通过结果。

| 检查 | 通过条件 |
| --- | --- |
| 用户是否仍在调度 | 从明确委托到第一份可核查初稿，不强制点材料、检索表单、建卡、入库和摆放，不强制确认计划 |
| Agent 是否真的执行 | 至少一个真实模型能依据查找／读页结果自主决定后续调用；改变来源内容会改变后续动作或结论，不用固定演示冒充 |
| 来源是否完整 | 代码校验原句、文档、hash、页索引与实际读取记录；缺失／多处命中／文本不就绪明确处理 |
| 论断是否站得住 | 另做逐条语义审阅，核查引用是否支持对应论断；原句存在于该页不等于支持关系已经成立 |
| 用户能否接管 | 原文能直接打开，结果能直接修改；一句纠正只修订相关部分，用户编辑受到保护 |
| 能否停止与恢复 | 停止后不再发新工具调用；已完成内容保留，失败可从检查点继续；刷新后的旧运行不得盲目重放或重复入库 |
| 是否确实减负 | 同一组真实研究任务记录旧版与提案的必要操作、页面切换、完成时间、错误与人工纠正；减少点击不能以牺牲证据质量换取 |

先用固定样例验证数据和权限边界，再用真实模型验证取证与工具选择，最后用实际研究任务比较体验。旧版功能测试不能替代新产品路径验收，也不能预先断言哪种布局最优。

## 方向依据与待验证选择

Anthropic 区分预先规定步骤的工作流与由模型决定过程和工具使用的 Agent，并强调观察真实执行结果、设置停止条件、保持实现简单。这支持先做一个有边界的研究闭环，不支持为了“Agent 化”搭建复杂编排系统。[Building effective agents](https://www.anthropic.com/research/building-effective-agents)

Linear 的产品表达允许委托整件工作，同时保留人的责任与可检查的变更；Elicit 的研究 Agent 展示了限定来源、持续追问和留存研究来源的路径。这里采用的是委托与可追查的交互原则，不搬入其任务平台或宣称本项目已拥有对应能力。[Linear for Agents](https://linear.app/agents)、[Elicit Research Agent](https://support.elicit.com/en/articles/14756886-elicit-s-research-agent)

需要实际试用验证的核心选择是：研究成果直接呈现后，用户能否在不学习对象分类的前提下理解、修改和信任它。主要成果采用比较内容、画布还是文稿，应由任务和已有工作位置决定，不预设所有人都必须先画图或先聊天。

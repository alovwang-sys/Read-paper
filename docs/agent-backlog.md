## 开发方式

先建立统一框架、共享契约和固定样例，再并行开发可独立接入的模块。每批任务都形成可运行的用户行为，集成完成后继续下一批。

采用一个主 agent 负责集成、最多两个执行 agent 并行、一个 agent 按需评审的安排。角色随任务复用，无需创建常驻角色或新的侧边栏聊天。

用户负责产品方向和关键体验取舍；主 agent 负责共享边界与端到端验收；执行 agent 对自己认领的模块和验收证据负责。

## 计划中的模块所有权

| 模块 | 计划路径 | 负责人 | 修改边界 |
| --- | --- | --- | --- |
| 应用框架、导航与面板 | src/app、src/shell | 集成 agent | AppShell、资源打开、研究切换、布局恢复 |
| 共享对象、应用服务与持久化 | src/domain、src/services、src/data | 集成 agent | 唯一 schema 与迁移入口；供各 feature 调用 |
| 设计变量与共用组件 | src/ui | 集成 agent | 字体、尺寸、按钮、资源项、弹出层 |
| 研究概览与资料列表 | src/features/research、src/features/library | 按任务指定执行 agent | 不自行保存第二份全局资料 |
| PDF 与证据 | src/features/reader、src/features/evidence | 阅读执行 agent | 阅读位置、文本选区、证据展示与来源定位 |
| 卡片与白板 | src/features/cards、src/features/board | 组织执行 agent | 正文经共享服务更新，白板仅保存引用与布局 |
| 结论与导出 | src/features/writing、src/features/export | 按任务指定执行 agent | 结构化引用、编辑与导出 |
| AI 对话 | src/features/ai | 按任务指定执行 agent | 显式上下文、请求快照、草稿与引用校验 |
| 集成验证 | tests/e2e、docs/verification | 集成或验收 agent | 关键用户路径与截图证据 |

并行 worker 只修改自己认领的文件。共享类型、依赖清单、入口注册、全局样式和数据库变更向集成 agent 提出，由其统一处理。每次派工明确说明“你不是唯一在修改代码的人，保留并适配其他人的改动”。

```text
  ↓

  ├── T4 白板与卡片复用 ──┐
  └── T5 结论与导出 ─────┤

                          ↓

```

T4 和 T5 可先基于 T0 的同一组样例做隔离视图，真实数据集成以 T3 契约为准。T1 通过前，避免多个 agent 同时创造应用框架。

## T0 确定共享契约与示例

负责人：集成 agent。范围：计划中的 app、domain、services、data 及依赖清单。

交付：最小运行入口；产品规划中对象与交互契约的实际类型；同一组研究、论文、证据、卡片、白板与结论样例；加载与保存接口；统一资源标识与设计变量。

验收：各视图能通过同一 ID 读取同一实体；页索引口径唯一；卡片正文与摆放位置分别存储；样例引用可被代码校验。保留最小有用示例，避免首批建设通用框架。

## T1 工作台框架

负责人：集成 agent。依赖：T0。

用户行为：从左上入口查资料，从左下切换打开项，在主区完成任务，在右侧查看参考。

交付：左侧全局入口和竖向打开项；主区标题、路径与视图宿主；单个右侧面板宿主；打开、关闭、固定、切换研究、搜索弹层；按研究恢复界面状态。2026-10-16 增加中央资源标签，直接复用打开项状态，支持固定、关闭、拖动及键盘排序，引用复用论文标签并保留右侧 AI。收件箱、论文库、研究空间、卡片库、研究产出五个集合入口首批均使用统一导航控制器和固定样例，真实操作随对应功能批次接入。

验收：

- 点击同一资源复用已有打开项；资源关闭后按明确规则选择下一项。
- 右侧打开卡片不替换主区；“在主区打开”后可返回先前任务。
- A、B 两个研究分别保留打开项、右侧模式及固定资源。
- 主区与右侧各自返回；面板模式切换不丢未保存内容；资源删除与保存失败有明确状态。
- 使用 dirty、saving、saved、error 统一保存状态；模拟保存失败后关闭打开项、切换研究、切换右侧模式，重新打开仍能恢复编辑缓冲。
- 1440×900、1280×800 下内容不重叠；1024px 下折叠或抽屉行为可用。
- 键盘可进入导航、切换右侧模式、关闭弹层并返回触发位置。

截图证据：论文库、研究概览、阅读器占位、白板占位、结论占位、右侧展开与折叠、窄宽度状态。占位内容必须能打开同一组真实样例对象。

## T2 PDF 阅读

负责人：阅读执行 agent。依赖：T0、T1。

范围：reader 模块；通过既定应用服务保存文档和阅读状态。

用户行为：导入有文本层的 PDF，打开、翻页、缩放、搜索并继续上次阅读。

验收：刷新后文档、研究关联和页码仍在；导入失败、原文件缺失、空文本与文本提取失败各有明确可操作状态；阅读就绪不依赖 AI 就绪。

用合法的固定样例验证单栏与双栏论文；至少包含一份扫描 PDF 验证能力边界提示。复杂公式提取不作为本任务完成条件。

截图与路径：导入论文 → 打开阅读器 → 翻页并展开右侧面板；另交文本提取失败状态截图。

## T3 证据卡片与来源定位

负责人：阅读执行 agent；卡片编辑接入可交由另一个执行 agent，但共享契约由集成 agent 维护。依赖：T2。

用户行为：选中原文，建立证据，写出观点，点击来源回到 PDF。

交付：选区菜单；证据数据；卡片基础编辑；证据面板；统一来源跳转。

验收：证据保留文档 ID、摘录和正确页索引；页面缩放和刷新后仍可定位；矩形失效时能回到页并显示摘录。创建卡片不依赖 AI；保存失败时保留未保存内容。引用缺失时显示原因，不能静默跳到错误位置。

截图与路径：选中原文 → 创建卡片 → 右侧编辑 → 点击引用定位回原文。验证卡片与证据文档的研究关联由统一服务建立。

## T4 白板与复用

负责人：组织执行 agent。依赖：T3；视图可基于 T0 样例提前开发。

范围：board 模块。用户行为：将已有卡片放入研究白板，移动、分组、连线，在右侧查看并回到来源。

验收：

- 同一卡片可在两个白板出现，编辑正文后两个位置一致。
- 从白板移除实例后，卡片库与另一白板保留该卡片。
- 连线引用摆放实例，语义说明可编辑。
- 离开后返回恢复白板视口；刷新后布局一致。
- 添加 PDF 摆放实例 → 打开专用阅读器 → 返回白板，布局与视口恢复；文档摆放同样使用 placementId。
- 连线、拖动和编辑手势不互相抢占；键盘能打开和移出卡片。

首批工具：选择移动、添加卡片或文档引用、连接、分组、查找与缩放。嵌套白板、自由绘图、自动布局和完整撤销历史后置；删除与移出操作需有可恢复方式。

截图与路径：白板添加卡片和 PDF → 分组连线 → 右侧预览来源页 → 返回原视口。

## T5 结论与导出

负责人：写作执行 agent。依赖：T3；视图可基于 T0 样例提前开发。

范围：writing、export 模块。

用户行为：在主区写结论，在右侧查证据，插入卡片引用，导出研究笔记。

验收：草稿刷新后保留；正文引用指向结构化证据；导出包含标题、核心问题、结论、文献信息、PDF 第几页及原文摘录；导出前检测失效引用并明确显示。导出不依赖白板存在。

首版 Markdown 导出不承诺携带原始 PDF，也不承诺外部读者能使用应用内深链。可迁移的 PDF 导出包另立任务。

截图与路径：打开结论稿 → 右侧查证据 → 插入引用 → 导出；交付编辑状态截图及实际导出文件。

## T6 AI 辅助

本节为首版演示基线。下一轮由 AR0–AR5 扩展真实多轮对话、独立卡片草稿与双来源；原始聊天与卡片编辑必须分开保存，不沿用直接改写请求回答的做法。

负责人：AI 执行 agent。依赖：T3、T5；集成 agent 维护模型调用与引用校验边界。

用户行为：选择一组证据，请求解释或比较，修改回答后保存为卡片或插入结论。

交付：右侧 AI 模式、已选上下文列表、生成中与失败状态、草稿保存、请求记录。

验收：

- 实际请求只包含显式选择的材料；选择范围在发送前可见。
- 提交时保存研究、会话、证据及内容版本快照。
- 切换研究不改变已提交请求的归属，完成后不写入另一个研究。
- 返回引用必须属于本次上下文；范围外或不存在的 ID 被代码校验阻止。
- 请求失败可重试，原正文不被覆盖；超出上下文容量时提示缩小范围。
- 用户可以编辑、放弃或另存草稿；更新已存在结论需要显式动作。

先用确定性测试响应验证引用范围、错误状态和请求归属；再用已配置的真实模型完成一次生成冒烟验证，记录实际条件。模型调用配置未提供时，界面功能与模拟验证可以完成，但不得标为真实调用已通过。

截图与路径：选择两条证据 → 查看上下文列表 → 生成草稿 → 点击引用 → 保存卡片；另交生成失败状态截图。

## T7 全链路验收

负责人：主 agent 与独立验收 agent。依赖：T2–T6。

固定场景：一个研究、三篇合法样例 PDF、若干证据与观点，完成“导入 → 阅读 → 证据 → 卡片 → 白板 → 结论 → 导出”。随后切换研究、刷新并恢复，检查所有引用。

每个可运行批次都做适当验证；T7 只补充跨模块风险和最终体验验收。对引用完整性、持久化、研究切换隔离与共享实体复用做有意义的测试，常规视觉间距由截图检查。

截图覆盖：左栏完整与折叠、阅读器与选区、右侧证据、白板分组连线、结论与参考、AI 上下文、空状态、错误状态及窄宽度布局。必须验证“主区 PDF＋右侧卡片”“主区白板＋右侧原文页”“主区结论＋右侧 AI”三种组合。官方截图用于解释结构，本产品截图用于验证本产品的行为和布局。

记录实际运行命令、结果、截图位置和未解决问题。只有实际跑通并留有证据的任务才能标记完成。

## 每批完成的判定

功能能在统一工作台中运行，数据与其他视图一致，完成约定的验收并提交实际证据。仅有独立静态页面、缺少引用关系或未接入统一状态的模块仍属于待集成。

按用户行为完成切片，再将稳定边界并行化；agent 数量与真实可并行任务匹配。

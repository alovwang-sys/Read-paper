# 原生输入区控件验收

2026-10-17。依据用户提供的 Codex 输入区截图补充；用户明确带黄点的附加图标暂不加入。浏览器和 Electron 复用同一生产组件，没有嵌入或操控 Codex 桌面窗口。

## 已实现的行为

- 两行工具栏保留“＋”材料、助手切换、权限、技能、Chat/Plan、模型、推理强度及麦克风，发送／停止采用圆形图标按钮。右栏按原尺寸工作，中央论文继续可见。
- “＋”通过共享 `addContext` 选择当前研究证据，也可沿用 PDF 导入。取消、添加或导入不会发送问题；未发送输入保留。图片区域仍遵循当前连接的图像能力限制，不把导入论文等同于自动提交整篇。
- 模型和推理强度来自当前本机目录；模型切换回新模型默认档位。显式选择的模型、effort、模式、权限与技能冻结到请求，刷新与研究切换保留各自设置。
- 只读与完全访问由原生 `permissionProfile/list` 的允许列表决定。完全访问先说明项目外文件与网络范围，再确认；下一次请求通过原生 profile 生效，不改全局配置。降权续接会显式重设 thread/turn 权限。项目可写模式未完成独立保护验证，暂不显示或假设材料和技能目录仍受保护。
- 麦克风聚焦当前草稿，展示系统听写说明，不自动发送、不请求媒体权限。当前没有内置录音转写，也不把 Codex realtime 或浏览器 SpeechRecognition 构造函数当作听写已可用。
- 文件更改汇总使用当前请求的原生 `turn/diff/updated` 事件，不叠加累计 patch 与单个工具 patch，不扫描整个 Git 工作树。只显示经过脱敏与大小限制的节选，可展开查看；凭据文件整体隐藏。

## 已运行检查

构建与 TypeScript 通过；125 项单元、138 项服务端、16 项桌面边界测试通过。相关网页 E2E 共 47 项通过（旧助手／Codex／项目路径 22，阅读／中央引用／TikHub 16，新输入区 9）；最终 UI 尺寸调整另复跑 3 项通过。没有为本轮输入区执行新的真实模型请求。

新输入区测试使用自建临时 HTTP 服务与可控 NDJSON，覆盖完全访问取消／确认、请求设置快照、模型档位变化、能力受限、材料选择、语音说明焦点和局部 Escape、原请求停止、原生 diff、刷新与三尺寸。模拟消息和模型名称均有文字标识，不作为真实模型成功证据。

本机真实能力 GET 返回 7 个模型、含 Ultra 的实际档位、Plan、只读和完全访问两档。主 agent 在应用内浏览器的自制验收研究只读查看权限和推理菜单，并取消完全访问确认；系统听写说明保持输入焦点，Escape 仅关闭说明。未更改个人研究权限或发送模型请求。

真实无模型权限探针见 [permissions-probe.json](permissions-probe.json)：Codex CLI 0.162.1，仅在自制临时目录通过原生 command/exec 验证只读拒写、完全访问可写、随后降回只读拒写及拒绝读取项目外自制文件；没有创建原生 thread 或调用模型。

真实 macOS arm64 新包已完成构建、打包及运行文件 hash 核对。独立 HOME／应用资料目录的项目路径与输入区联合检查 **2 项通过**；不启用完全访问、不请求录音或模型。不同隔离运行实际出现两种结果：[200 能力可用轮次](desktop-composer-available-evidence.json)读取 8 个模型并打开／取消完全访问确认；[最终联合轮次](desktop-composer-evidence.json)读取能力返回 502，权限／模型菜单展示公开错误与重试、不提供完全访问选项。两轮均验证材料取消、系统听写焦点与 Escape、1024 控件可达、重启后草稿及只读状态恢复。失败 trace 保留，502 的具体原因未确定；不能据此宣称新环境真实模型认证或回复成功。

发布前 [CI 38947358781](https://github.com/alovwang-sys/Read-paper/actions/runs/38947358781) 的 macOS arm64 桌面检查出现 6 项通过、1 项失败：提示在 3500ms 自动关闭，测试先检查可见再点击时恰好被卸载，导致点击等待超时。测试改为重试断言等待提示消失，保留全部输入区验收。复用上述本机包执行 `npm run test:desktop:e2e -- tests/desktop/composer-controls.spec.ts --repeat-each=5`，**5 项通过（30.7s，exit 0）**；1 轮返回 200 并取消完全访问确认，4 轮返回 502 并验证降级菜单。本次只验证测试时序修复，三目标 v0.1.1 产物仍以发布流水线为准。

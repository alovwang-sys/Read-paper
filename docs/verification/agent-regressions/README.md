# 默认 Agent 工作台回归修复与复核

日期：2026-10-21。基线为发布版 v0.1.12 / `566ce3e319da0463bdc4dd675c315648ac0b77a8`。修复分支 `codex/fix-agent-regressions`；本记录描述本地修复，尚未发布新的安装包。

本轮范围是用户反馈的长消息、发送残留、回答难找、对话空间和从聊天发现文献入库；同时审计这些路径的恢复与引用边界。不是整个仓库的零缺陷证明。用户真实研究、已安装应用和既有发布附件没有被修改。

## 已定位的问题与处理

| 问题 | 原因与本轮处理 |
| --- | --- |
| 以前取消的长度限制重新出现 | 新 textarea 的 `maxLength=4000` 会直接截断输入，客户端也拒绝超过4000字；后端另限8000。已取消这些分散限制，统一按本轮实际传输预算校验，保留草稿并明确报错。 |
| 发送后仍显示原问题 | 新路径只在整轮成功后清空。现请求正式入会话即消费本轮文字与附件；失败／停止仅在没有有效答复、没有新草稿且仍为最新请求时恢复。 |
| 下一条问题重复带上一张图 | 完成回执把图的清理绑定到输入文字仍相同。现提交时冻结请求快照并消费对应附件，后续编辑不改变已发内容。 |
| 对话上下文静默消失 | 原实现仅取六轮、累计12000字符，超过就整轮移除；一次长成果可使下一轮历史为空。现在完整保留已完成且未被替代的本会话历史，不静默裁剪。 |
| 完整回答被藏到成果入口 | 服务保存的聊天正文被替换为一句说明，界面还刻意隐藏成果全文。现当前会话直接显示真实全文审 | 本人提交后定位新轮；上滚读旧内容时保留位置，提供查看最新回复。实时检索候选也触发通知。简化会话标题与输入区域，执行范围／读页说明折叠；长问题可展开查看全文。 |
| 新默认界面丢失文献收录 | 遗漏经典 `SourceRecommendations`，且成果链接在 `result.body` 而非占位正文。现复用旧预览、去重、入库、全文获取、研究关联与来源记录；同轮typed候选与正文链接按标识去重。 |
| 对话里不能真正找新文献 | 新工具只有本轮资料目录、读页、提交文稿。现增加只读 `search_literature`，复用原OpenAlex服务；候选、空结果、失败与停止状态留在原消息中，用户明确收录后才写资料库。 |
| 候选／已收录摘要无法继续问 | 已完成候选按原顺序进入非PDF历史材料；已收录摘要进入来源目录。点击“围绕这篇追问”会显式优先该文献，不受它在原资料顺序中的位置影响；不把摘要变成页码证据。 |
| 持续工作的长任务仍被三分钟截断 | 新路径使用整轮绝对截止，未复用经典空闲语义。现在真实活动重置空闲计时，停止／断开／超时后不能被迟到事件复活。 |
| 可读会话归档缺少正文与新候选 | Markdown归档现保留实际成果全文、按顺序排列的题录／摘要／检索状态和错误。原JSON及ZIP已经保留完整数据，不做破坏性迁移。 |

修复过程还补上停止后立即发下一轮的旧回填竞态、多条合法事件合在同一网络块时误判超限，以及桌面新模块遗漏允许清单。它们在集成测试中暴露并修正，没有发布这些中间状态。

## 根因与取舍

新默认界面另建了发送、上下文与展示路径，却没有延续此前修复过的契约。原有大量浏览器／桌面检查显式进入经典工作台，不能证明新默认路径正确。最初新增的四条浏览器回归全部失败；修复后扩充到长消息、正文、入库刷新、未入库候选追问、滚动和检索错误等路径。

[两轮真实 Claude Code 讨论](claude/README.md)均成功，保留原始输入与结果。第二轮撤回了对历史及正文做有损截断的建议；没有把模型意见当作产品验证，也没有采纳未经复现的引用必然错配推断。此次保留现有原生隔离，不为修回归临时改造会话权限和线程接续。

## 验证证据

- 新默认界面浏览器回归：`tests/e2e/agent-regressions.spec.ts`；覆盖1440×900、1280×800、1024×800，短输入时正文滚动区超过视口68%，发送与来源操作可达。
- 旧路径回归：Agent成果／人工修改保护、来源阅读返回、绘图快照与重试、经典发送／新输入竞态、原文小窗、来源预览／补全文及持久化。
- 业务与持久化单元：完整历史、候选入历史、失败／停止／迟到隔离、摘要与PDF证据分离、刷新和ZIP语义校验、可读目录。
- 服务端：共享OpenAlex网络边界、并发、取消、错误、候选不能冒充PDF引用、逐条事件、输入预算以及可控时钟活动超时。
- 桌面：Forge允许清单和运行依赖闭包；本机macOS arm64打包应用的默认Agent路径与既有桌面测试，使用隔离HOME与临时userData，不进入真实研究。
- [真实合成 Codex 检索](live-research/README.md)：一次生成30.385秒，实际调用新工具，OpenAlex返回10条，答案中的前两条题名及DOI/URL与真实结果一致；无用户资料、PDF读取、文稿或资料库写入。前两条为同论文不同版本，不宣称两篇独立论文。
- [真实OpenAlex服务探针](openalex-live.json)：公开合成检索词，HTTP200、10条题录；不包含密钥。
- 最终各项检查结果见[checks.json](checks.json)。关键截图在[截图目录](screenshots/)。

## 当前仍有边界

- 新研究运行依然每轮使用隔离原生线程，通过显式历史续聊；没有接通原生线程自动压缩、Skills和Plan的同等体验。经典工作台的原生连续会话保留。
- 历史最多80000字符（含完整候选元数据），本轮问题、历史、局部对象和绘图结构序列化后加协议预留总计最多120000字符；这不是模型token窗口。超过时保留输入并明确停止发送，不偷偷换模型、压摘要或丢前文。
- 仍按已披露范围准备前8份研究资料／每份前24页／总160000字符，局部对象及单篇来源摘要最多12000字符。明确“围绕这篇追问”优先它；没有宣称任意大资料库已被完整阅读。
- 后续文字历史不会自动重发上一轮绘图像素；需要重新看图时需重新附选区。不能把已记录的上一轮图片说成当前模型仍能直接看见。
- 新研究工具目前仅Codex接入，其他连接保留各自既有能力。真实冒烟仅一次公开合成请求，无法保证所有研究任务的检索质量、全文可得性或跨版本去重。
- 本轮尚未发布新的安装包，没有替换 `/Applications/Papertrail.app`，没有人工重走DMG/Setup安装、干净机器或跨版本升级验收；Windows／Intel本轮未重新构建。

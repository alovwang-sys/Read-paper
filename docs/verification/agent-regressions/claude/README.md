## 独立审阅结果

以下“确定”指由给定基线源码可直接推出；浏览器行为仍以主执行者实际复现为准。静态审阅未发现可证实的 P0 安全或不可逆数据损坏，不采用 Claude 首轮将两项体验回归直接判为 P0 的等级。

| 等级 | 问题与证据 | 判断 / 最小修复 |
| --- | --- | --- |
| P1 | `ResearchAgentWorkbench.tsx` textarea `maxLength={4000}`、`submitResearchRun` 限制 4,000，服务端允许 8,000；旧经典路径的 4,000 限制早已取消 | 默认路径重新引入长度回归。去掉输入控件静默截字，客户端和服务端同步按完整请求预算显式校验，超限保留原文 |
| P1 | 服务只在成功 `done` 时通过 `owner.input === prompt` 清空；请求进入会话与清输入不在同一事务 | 发送后的文字残留。提交时冻结快照并消费本轮草稿，失败恢复不能覆盖新草稿，重试不得消费新输入 |
| P1 | 绘图附件清理也位于上述输入相等条件内；用户在执行中起草下一条后条件不成立 | 已成功发送的图片可残留到下一条。发送时清理对应待发附件；请求保留独立冻结副本；恢复时保护新附件、focus 和输入 |
| P1 | 历史 `.slice(-6)` 后按 12,000 字符逐轮 `shift()`，单轮成果可到 80,000 字符 | 长成果可导致下一轮历史为空，界面仍显示完整会话。保留完整历史至明确预算，超限显式阻止，禁止静默删轮或以短摘要替换 |
| P1 | `server/research.mjs` 要求提交成果后不重复全文；服务将 `saved.body` 覆盖为一句占位；展示又隐藏与 `result.body` 相同的正文 | 三层合起来将结果藏到“打开成果”。新旧记录都应在会话内显示 `result.body` 全文，保留打开编辑入口，避免要求用户离开会话找回答 |
| P1 | 默认 `ResearchAgentTurn` 没有 `SourceRecommendations`；研究工具仅列出本轮本地目录，明确不联网 | 原有回答链接收录在默认路径消失；联网研究工具则是已记录的能力缺口。恢复链接收录，并复用现有 OpenAlex 服务打通受控搜索、真实候选和一键入库 |
| P2，需浏览器验收 | 滚动仅在 `nearBottom` 时追随，无新回复跳转；本人上滚后提交也不主动定位新一轮 | 区分本人提交定位、近底部追随、上滚阅读保护、会话滚动恢复；有新输出时提供明确跳转 |
| P2，需浏览器量测 | 会话说明、绑定行、附件、模式提示、输入和配置纵向叠加；dock 没有整体限高 | 压缩非正文内容、附件默认紧凑折叠，按实际三尺寸验证阅读区，不能只用“所有控件都存在”的测试替代 |

独立实测由消息执行者提供：6,001 字问题在服务入口拒绝且无 fetch；请求已进入 `generating` 时输入仍保留；前轮正文 12,001 字时 history 变为空；下一条草稿导致旧图片残留。这些是第二轮讨论输入，Claude 本身没有执行这些测试。

## 两轮收敛与未照单采纳的意见

第二轮 Claude 明确撤回首轮“12 轮 / 24k / 每成果前 1,500 字”方案，接受完整历史到预算后显式拒绝；撤回“正文前几段 + 展开”，接受正文全文直接可读；撤回“文献移出后删除该轮回答”，区分历史数据与本轮原文证据授权。

共同建议按以下次序修复：先恢复消息提交、草稿和上下文的正确性；再恢复正文与滚动阅读；最后将原有文献服务接回默认会话。执行记录和配置默认折叠，不增加平行找文献页面。

本次不强接原生线程。隔离运行允许按本轮快照重新授权；直接续接旧线程可能隐式继承已撤回材料和工具结果。原生续接、Claude/OpenCode 研究工具、Skills/Plan 对齐需要各自验收，不能为修这轮回归声称已经支持。

仍有几项建议需要人工判断，未当作已证实 bug 或直接实施要求：

- Claude 将历史 `[n]` 对到本轮其他论文描述为必然事实，但实际研究成果由 `submit_result.citations` 顺序、hash、原句匹配与本轮 `read_page` 联合校验，不是“读过三页即自动映射”。语义错配是待验证风险；不能据此删除引用校验或大改原生契约。
- 引用解析会处理代码块、数学、Markdown 链接之外的裸 `[n]`，因此普通候选列表“[1] 作者…”可能触发未映射引用错误。这是确定的协议冲突，但模型实际生成频率未测。候选用 typed 数据及题名/DOI/链接显示，不能把未读候选当 PDF 页证据。
- “失败时 `trim()` 为空即可恢复”可能覆盖用户有意输入的空白；恢复条件应保护当前草稿、附件、局部目标及工作区 generation，而不是只看视觉上是否为空。
- Claude 建议“服务端从会话推导入库研究 ID”，本应用实体保存在客户端 IndexedDB，不能直接套用。应始终绑定请求保存的研究/会话 ID，沿用共享服务验证归属，不能取当前界面研究。
- “只发关键词”是工具接口和提示的约束，无法保证模型绝不将敏感词写进 query。可核实的边界是固定 OpenAlex 端点、长度限制、不自动附送完整问题/历史/PDF/图片、展示实际查询词与服务端次数限制。

## 必须实际验证的路径

- 默认 Agent 工作台粘贴 10,000 字可完整提交；超预算不发请求、不清原文；20,000 字成果后继续追问仍有完整历史。
- 提交瞬间输入和对应附件清空；执行中可起草下一条；完成、失败、停止、重试、切会话和恢复备份均不会覆盖下一条或重复旧图。
- 旧占位记录和新成果直接显示完整正文。近底部自动跟随，上滚 300px 保持位置并能跳到新回复；本人提交定位，会话切换恢复位置。
- 真实检索候选、空结果、错误和停止都留在当轮；刷新后还在；一键加入共享资料去重，发现来源可追溯；跨研究隔离；下一轮题录/摘要与 PDF 原文严格区分。
- 1440×900、1280×800 和 1024px 下，短/长输入、附件、配置展开都保留可读对话区。不能用经典工作台的旧长消息测试代表新默认通路通过。

本目录未运行应用测试、点击浏览器或调用应用内真实研究模型；两次 Claude 调用成功只证明讨论完成，不证明修复通过。

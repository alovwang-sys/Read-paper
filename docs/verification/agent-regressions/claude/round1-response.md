# Papertrail v0.1.12 回归审阅（第 1 轮）

**说明**：以下只基于所给源码片段做静态审阅，没有运行。以下内容未提供，相关结论标为"待复现"：`mapCitationNumbers`、`collectResearchSources`、父级布局 CSS、`DrawingQuestionPreview`。

## 一、问题分级

### P0：新回归，且会静默丢数据

1. **输入被静默截断**
   - `ResearchAgentWorkbench.tsx:119` 设置了 `maxLength={4000}`，超长粘贴会被直接截掉，没有任何提示。
   - `research-agent.ts:189` 又把上限卡在 4000。
   - 服务端 `research.mjs:73` 却允许 8000。
   - 三处上限不一致，相比经典聊天是倒退。
2. **连续对话的历史会被整段清空**
   - `:206` 对产物轮取 `item.result?.body`，最长可达 80000 字。
   - `:207` 在总长超过 12000 时，从最旧一轮开始逐轮 `shift`。
   - 结果：只要有一个长成果，就会把包括上一轮在内的历史全部删光。界面上只在折叠的 sourceSummary 里显示"附送最近 0 轮"。
   - 这是"续问失忆"的直接根因。逻辑可以从代码确定，但仍建议补单测确认。

### P1：新回归，影响体验或功能

3. **发送后输入框不清空**
   - 只有成功完成时才清空（`:300`）。执行中、失败、停止，以及 `!current()` 提前返回时都保留原文。
   - 执行期间只要用户改过一个字，`owner.input !== prompt`，之后就永远不会清空。
4. **回答难找**
   - `:287`、`:291` 用固定文案覆盖了模型流式输出的正文。成果只剩一张链接卡，用户必须离开会话去打开草稿。
   - `:78` 只在 `nearBottom` 时跟随滚动。用户发送时如果不在底部，新的一轮不会进入视口。
5. **文献闭环断开**
   - `ResearchAgentTurn` 完全没有挂载 `SourceRecommendations`。
   - 加上第 4 条的正文覆盖，答案里的链接也会丢。
   - 另有一个疑点（待复现）：`:295` 可能把"[1] 作者…"形式的参考列表判为未映射引用，导致整轮报错。

### P2 / 已有缺口

6. **Agent 不能联网搜文献**：这是设计如此（`search_sources` 不联网），不是回归。
7. **上下窗口被挤压**：dock 没有总高度上限，绘图预览、模式说明、错误提示和 136px 输入框会叠加。但父布局未提供，待在 800px 高的窗口中复现。
8. **历史内容不准确**：历史取的是 `result.body`，而不是用户编辑后的当前草稿；失败或停止的轮次不进历史，也没有任何提示。

## 二、要不要立即改为原生线程续接：不建议

反对理由：
- 原生线程会携带此前 `read_page` 返回的全文，无法剔除之后已从研究中移出的论文。
- 接续原生配置、Skills 或 Plan，会把 shell 和联网权限带进隔离运行，破坏现有边界。
- `nativeSessionId` 可以继续保存，留待以后做"授权集合没有缩小时才续接"的增强。

**最小可靠方案：由应用侧组装历史**
- **预算**：客户端与服务端同步放宽，例如不超过 12 轮、24000 字。
  - 每轮单独截断。产物轮只发送提问、说明，以及"成果《标题》前 1500 字…（已截断）"。
  - 最新一轮只截断，不整轮丢弃。
- **不静默**：被省略的较早轮次，在 history 中插入"已省略较早 k 轮"的占位；同时在回复头部可见地标注"带入 n 轮 / 省略 k 轮"。
- **授权过滤**：`:206` 目前把 `context` 置空了，应改为保留其中的 `documentId`。如果某轮引用的文档已不在 `documentIds` 中，该轮只发送提问，并注明"引用资料已移出本研究"，不发送正文。

## 三、阅读区与自动滚动

**回答正文优先**
- 不再覆盖 `saved.body`。产物轮在会话内显示标题和前几段，并提供"展开全文"和"打开编辑"。
- 显示顺序：正文 → 成果卡 / 修改建议 → 文献 → 错误 → 默认折叠的执行记录。
- "共享成果"移出最后一条回答的下方。

**给阅读区留空间**
- 附件预览限高 72px，可展开；模式说明合并为一行。
- dock 总高不超过视口的 40%（具体数值待按真实布局校验）。

**滚动规则**
- **跟随**：
  - 内容增长前，距底部不超过 80px；
  - 用户刚发送时，强制把新提问滚入视口并开启跟随；
  - 切回一个正在执行、且上次停在底部的会话。
- **不跟随**：用户通过滚轮、触控、键盘或拖动向上离开阈值。需要区分用户手势和程序滚动，避免误判。
- **提醒**：不跟随期间若有新增内容或回复完成，在 dock 上方浮出"↓ 新回复"或"回复已完成"。点击后跳到该回复的开头，而不是直接到底；完成时通过 aria-live 播报。
- **实现**：改用 ResizeObserver 监测内容高度。现有依赖只有 body 和 status，成果卡等内容出现时不会触发滚动。

## 四、文献闭环

### 最小恢复（本补丁）

- 在正文下方渲染：
  `<SourceRecommendations request={{...request, body: [request.body, request.result?.body].filter(Boolean).join('\n\n')}}/>`
  去重、收集元信息、尝试取 PDF，全部沿用现有 sources 服务。
- 修改 instructions：允许以"候选线索（未核实、未读）"的形式给出 DOI 或链接，但不得用 [n] 引用它们。
- 收录后，下一轮的 sourceSummary 写明"新加入 X：仅元信息 / 已取全文"。本轮的快照不变，新文献从下一轮起才可读取。

### 后续增强

- **新增服务端工具 `search_literature`**：由服务端调用现有 OpenAlex 服务（固定端点），Codex 沙箱本身仍然不联网。
  - 不逐次审批，但每轮设限额，例如不超过 5 次、每次不超过 10 条，并设超时。
  - 查询词写入执行记录，默认折叠。
- **结果性质**：只含题录和摘要，标记为 `metadata_only`，摘要视为不可信数据。现有 `submit_result` 校验只允许引用实际 `read_page` 过的页，保持不变，因此不会装作已读全文。
- **可追溯收录**：候选以 `candidates` 事件持久化，记录查询词、OpenAlex ID、DOI 和排名。收录仍由用户一键完成（可提供"全部加入"），discovery 记录 requestId 和查询词，支持撤销。不自动收录，也不标记为"已读"。

## 五、修复顺序与可观察验收

1. **统一长度上限，去掉 `maxLength`**
   - 验收：粘贴 10000 字不被截断；超过上限时报错且原文保留。
   - 是否放宽到经典聊天的水平，需要先确认 Codex 的输入预算（目前未知）。
2. **历史预算与授权过滤**
   - 验收：先生成一份超过 20000 字的成果，再问"继续"，请求中的 history 不为空，界面显示带入/省略的轮数。
   - 验收：把某篇论文移出研究后，下一轮的 payload 中不含它的引文。
3. **发送即清空**：在 `:211` 创建请求时清空输入和绘图附件（重试时不清空）；失败或停止时提供"恢复到输入框"。
   - 验收：点击发送的瞬间输入框变空；失败后可一键恢复原文。
4. **正文保留与滚动规则**
   - 验收：上滚 300px 后，生成过程不跳动并出现提醒；停在底部时持续跟随；每次发送都能看到新提问。

   - 验收：含 DOI 的回答出现"回答中的资料"；加入后进入资料库，重复加入会去重，来源可追溯到该轮；下一轮自动获得授权。

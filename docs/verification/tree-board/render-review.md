`npm run check` 通过。`npx playwright test tests/e2e/research-map-probe.spec.ts --reporter=line`：角色图标断言补充后重跑 1 项通过，6.0 秒，并重拍本页 8 张截图。

- 真实原文重新解析的 plan、重新计算的 preview 与真实调用报告完全一致。
- 图标按结构角色区分：1 个根主题用 Target、3 个分支主题用 GitBranch、7 个叶节点用 StickyNote。同类图标一致，折叠后的分支仍保留分支图标。8 张新增卡片虽都以“依据”开头，仍分别保留分支/叶节点图标与独立的“待核查”文字，没有据首句把整张混合内容卡片标为事实。
- 默认显示 11 个节点、10 条父子连接，6 条语义关联默认隐藏。点击“显示关联”后实际生成 6 条语义路径。
- 每个截图状态都测量全部已渲染节点，而非只测可见窗口：卡片重叠为 0；父子路径和语义路径穿越第三张卡片的采样命中均为 0。每条路径采样 799 点，属于近似检测，不证明所有输入或任意大图都无碰撞。
- 收起“已有更新方式”和“已有运行边界”，保留“评估与选择计划”展开。折叠后 6 个节点保留在画面结构中，选中的评估分支突出显示。
- 刷新后，两处分支折叠、节点选中均保留；全部卡片正文、引用 ID、底层摆放层级/顺序/坐标、6 条语义边保持不变。
- 点击“编辑”在右侧读取完整原始正文。没有为了截图删掉长文、改写模型输出或缩至 40%。
- 零浏览器运行错误、零额外后端/模型请求。测试由隔离路由提供数据；本次启动的 Vite 服务已在退出后关闭。

## 实际看图后的判断

参考图与以上 8 张生产截图均已实际打开查看。下面分数是本次单一演示图的主观 UX 验收意见，不是用户研究结论。

- **标题阅读与分支聚焦：8/10。** 根节点、主题、具体计划分三列；父子曲线方向一致。折叠保留主题与子节点数量，没有把所有卡片压成小字。1440 下可以在正常字号读完整评估分支；较小窗口需要少量滚动，仍可辨识标题和操作入口。
- **全部关联同时开启：6/10。** 虚线与主结构已有区分，本例不再穿过无关卡片，但多条关联可能共用相近的绕行走廊。文字说明默认弱化，需要选择或聚焦关系才读得清，因此不能宣称任意复杂图的全局关联已经一眼可读。
- **正文与图面衔接：7/10。** 长内容移到右侧后画面较清楚，完整正文仍可访问；打开右侧会压缩画布，需要平移查看较右列。新卡片正文混合“依据 / 建议 / 待确认”，本轮已改为按根/分支/叶角色使用图标，避免依据首句误标整张卡片。图标不表达事实可靠性，仍需结合正文与“待核查”状态判断。

对本例的判定为：**层级阅读与人工折叠达到可试用水平；全关联密集展示仍有改善空间。** 没有因为测试通过就把整体体验判为完全成熟。

## 边界

演示材料是合成文本，没有原始 PDF。回放只创建元数据文档与摘录，未借用无关 PDF；右侧来源区会如实出现“来源引用已缺失或 PDF 页码无效”的提示，这是 fixture 没有 PDF 的已知边界。本轮未验原文跳转或真实来源文件校验，也未伪造其通过。

本例没有原始文献节点，因此 FileText 图标未由本项真实输出回放覆盖。尚未覆盖 80 节点上限、任意长标题/极长正文组合、所有关系交叉和标签遮挡。没有触碰真实研究资料或已安装应用，也未发起额外真实模型调用。

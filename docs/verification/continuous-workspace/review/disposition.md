# 安装前审查处理

本次在已有七轮设计讨论之后，另实际调用 Claude Code 两轮只读审查。原始输入、回复与 CLI 状态保存在本目录；工具关闭、无 MCP、临时工作目录、无会话持久化，只附送明确源码和设计要求，未提供用户论文或连接设置。审查意见是代码阅读，不能作为模型调用或 UI 验证证明。

| 发现 | 处理 |
| --- | --- |
| PDF 抽取某个 promise 不返回时停止／退出挂住 | PDF加载、取页、取字和背景响应均支持取消等待；迟到结果不能写回，回归覆盖三处挂起 |
| 等待简要时研究目录或连接改变 | 提交时冻结范围，背景模型前、简要落库前和真实问题发送前重新核验，变更保留输入并停止 |
| 首轮重新生成实际材料没有完整落库 | 已有简要材料在请求入库前组装，持久快照与实际发送一致 |
| 未知页数为0、过长错误不能通过自己的恢复校验 | 非ready记录允许0页，错误截4,000字符；恢复时可重建的坏文档缓存剥离，既有问答快照保持严格校验 |
| 退出误把等待简要的问题标为失败 | 先停止问题，再停止共享简要，保持stopped记录 |
| 演示简要可能进入真实缓存 | 读到demoResponder确认条件成立；演示局部问答只按选区，不读取整篇、不创建或改写真实简要缓存 |
| 原生card目的可能污染会话／无法解析／断连不取消 | 对照完整客户端、服务与runtime及3项受控server测试，主要假设不成立，详见[native transport核实](native-transport-check.md) |
| 白板列表→完整聊天→重复点白板后仍隐藏 | 导航显式切回资源侧聊，不只依赖active变化effect |
| 关闭聊天后点“围绕这里追问”看不到输入 | 追问显式重新打开侧聊 |
| 不支持的助手仍能点发送图片 | 保留图片预览、旧回答和草稿，统一禁用发送及白板生成路径，服务边界仍拒绝丢附件 |

第二轮 Claude 回复没有确认的阻断项；其中条件性演示污染问题已按上述修复并追加回归。其余未见源码项已对照实际入口核实：仅选区重试调用ask(...,true)并设置paperBrief:none；局部Codex显式历史遵循现有传输预算；cardResult与context空数组兼容；文档快照保存hash。实际检查结果由本轮README与测试日志提供。

明确保留边界：简要失败显示记录，可重试或仅按选区继续；不会静默把失败当成功。单个问题停止／跳过不会取消其他问题共用的简要。后台作业最久120秒，断流取消未提供前端进程终止ACK，可能短暂占原生全局并发配额。真实模型理解质量本轮未重测；没有因此添加新模型服务、线程架构或OCR。

# AI 阅读与可追溯卡片实现记录

日期：2026-10-16，Asia/Shanghai。测试材料全部为项目自制 PDF；本记录验证产品行为，不将模型输出当作真实研究成果。

## 本轮交付

- 原文拖选菜单支持解释、提问、加入当前会话和人工建卡；区域模式先预览截图，再明确加入。全局阅读时可选目标研究。
- 同一右侧宿主内实现多轮流式消息、Markdown/表格/代码/公式、复制、停止、原范围重试、最新轮重新生成；历史支持新建、搜索、重命名、归档及恢复。
- 回答整条、按段或拖选后生成独立 `CardDraft`。AI 修订先展示建议，按 revision 检测过期；手改不会被迟到结果覆盖。用户确认后幂等入库，草稿放弃不删除聊天。
- 卡片分别保留论文依据与对话来源。原始问题、回答、所选片段、引用顺序、提交材料与历史、整理/修订请求保留；卡片后续编辑不改原问答。原答引用与结论引用分别编号，禁止交叉误认。
- 卡片插入结论时冻结本次使用的来源，导出附相关对话片段及原答引用对照。区域导出保留坐标、hash、页码和说明，不附原 PDF、区域图或完整聊天。

## 实际架构与配置

沿用 React / TypeScript / Vite / PDF.js 和既有共享工作区，没有新增路由、第二侧栏或全局状态库。AI 服务、草稿操作由 `src/services/ai.ts` 统一管理，论文/会话/导航仍由 `workspace.ts` 管理。聊天、历史、来源详情分为已有职责对应的组件；卡片、结论共用来源与引用服务。

用户指定 `glm-5.3-flash`；本轮选用 Chat Completions，服务端固定目标为用户提供的 Coding endpoint。浏览器访问本地 `/api/ai`，本地 Node 服务适配供应商 SSE 为 NDJSON。未额外实现 Responses 协议回退，也不自动切模型、重试或改付费地址。

本地真实验收使用前端 `127.0.0.1:5175`、AI 服务 `127.0.0.1:8787`，配置 `AI_APP_PORT=5175`、`AI_IMAGES=true`。常规启动见[README](../../../README.md)，默认前端端口为 5173。凭据仅保留被忽略的 `.env.local`，文件权限 600；构建产物扫描未发现该凭据。前端不接收 API key。

服务校验 loopback Host/Origin、消息角色和尺寸、图片格式/签名、总输入与并发；不接受客户端供应商地址或密钥。超时和断开传播取消，错误不回传原始供应商响应。没有模型配置时必须明确选择演示模式；阅读器快捷解释遵守当前研究的模式。

业务 schema 升级为 2，IndexedDB 仍为 v1 的 `workspace` / `assets` 两个 store；区域 Blob 不放 localStorage。迁移前在 `workspace/before-schema-2` 保留原数据库与旧恢复缓冲副本，成功落库后才清理旧缓冲。未来版本、损坏记录、备份/读取失败不自动写回样例。工程恢复应先复制当前记录、该备份和原始恢复缓冲，再修复或重新加载；当前没有用户界面的全库备份/还原工具。

流式增量 180ms 合并，1.2s 触发数据库检查点，结束/停止/失败尽快保存。小记录使用 `papertrail-recovery-v2`；大于 1.5M 字符的工作区依赖 IndexedDB，关闭前等待“已保存”。刷新恢复生成中记录为中断；最近检查点之后尚未保存的片段无法保证恢复。

落地时保留最小合同：`AIRequest` 同时承担聊天、整理和修订记录，通过 `purpose` 区分；`generating` 覆盖连接与流式阶段，完成为 `done`，另有 stopped/interrupted/error。`commitCardDraft(draftId)` 使用持久化草稿 ID 本身作为提交身份，不额外引入 submissionKey。来源以冻结文本、`answerEvidenceIds` 和证据/文件 hash 保留，并未为每个回答片段另算 hash。原回答与实际发送历史分别存为 `body` / `sentBody`，引用必须配对应顺序解释。

## 真实模型验证

这些调用均使用上述指定模型和凭据，非演示响应。

| 路径 | 实际结果 |
| --- | --- |
| 接口文字烟测 | 收到文字增量与完成帧，返回“连接成功。”；约 0.83s |
| 接口图片烟测 | 自制红蓝两色图，正确描述左右颜色；约 1.02s |
| PDF 拖选 → 快捷解释 | 主区实际拖选自制论文片段；回答逐步呈现，含可定位的 `[1]` 引用 |
| 第二轮追问 | 显示 1 轮前序历史；真实回答继续讨论可追溯卡片，完成后历史为 2 轮 |
| 按段整理 → AI 修订 | 选择“记录完整链条”段，生成标题/正文/引用；修订为短卡，预览后采用 |
| 手改 → 确认 → 刷新 | 补充个人理解并加入卡片；刷新后正文、论文来源和原问答仍在 |
| 回查 | 卡片与结论打开原问题、原回答、高亮片段和 2 条整理/修订记录；引用可回 PDF，主区保持白板或结论 |
| 区域图像问答 | 实际拖框截取摘要，提交区域图；模型识别为自撰、虚构对比练习，回答完成 |
| 真实停止 | 较长回答生成至中途点击停止；保留部分文字，显示已停止、原范围重试和人工草稿入口，不显示完整整理入口 |

真实烟测没有统计供应商账单或评估模型语义准确率；取消不表示供应商已经撤销已产生费用。

## 剩余边界

- OCR、复杂图表/公式专项解析、跨页框选、跨版本来源迁移、跨设备同步未实现。区域坐标旋转由单测覆盖；尚未做大量真实扫描论文、高 DPI 和多种内嵌旋转文件的人工矩阵。
- 浏览器输入法保护包含 `isComposing` / keyCode 229，尚未做多种系统中文输入法人工验收。历史滚动恢复与跟随输出已实现，长达数百轮的性能和滚动压力未专项测量。
- 单工作区记录适合本轮单用户首版；大量长对话后应实测，再决定拆分请求存储与增量日志。区域预览 URL 会释放，未引用资产的统一垃圾清理尚未实现。
- Markdown 是可读的研究笔记导出，不是全库备份。应用内完整对话仍保存于本地；仅导出被卡片使用的片段。当前不发布公网服务。

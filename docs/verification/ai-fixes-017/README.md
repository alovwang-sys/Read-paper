# v0.1.7 AI 修复验收

日期：2026-10-19。基线：v0.1.6 / `ef5f104`。所有问答均使用项目自制 PDF、合成材料和确定性 HTTP/原生适配器响应；未验证真实模型自动压缩，不外推真实模型的容量或回答质量。

## 修复与证据

1. **Codex 上下文**：原报错发生在前端 `snapshotContext`，先于原生 Codex 调用。Codex 聊天不再套用 16 条/24,000 字材料和 80,000 字历史门槛。服务端先验证完整材料和历史引用，再按可信的原生映射省略已进入同一线程的问答；只补入缺失历史。2.4 MB 历史重启续接、增量历史、129 轮、范围收缩/reset、新会话超限、伪造历史引用均有协议回归。浏览器实际发送 17 条、超过24,000字材料和超过80,000字历史，验证首尾结构化引用、输入清空及刷新恢复；模型连接仍阻止超限且保留草稿。[1440px](context-codex-1440.jpg)
2. **发送后残留**：成功提交原来已会清空；本轮复现的是收到部分回答后断线，又把已发送问题自动回填。仅当没有可见回答时恢复原输入；部分回答保留消息及原范围重试。新增单测及 Codex/model 两条 E2E 在修复前失败、修复后通过，实际验证断流、刷新及点击重试。[1280px](composer-codex-1280.jpg)
3. **原文旁小窗**：标题栏拖移、右下手柄调尺寸，移动和缩放控件均可用方向键/Shift；视口收缩约束、正文选字和滚动、材料展开、最小尺寸、草稿及转右侧均已验证。[1440px](popover-1440.jpg) · [1280px](popover-1280.jpg) · [1024px](popover-1024.jpg)。打包应用也实际拖动标题、键盘调整尺寸并正常退出重启：[桌面截图](desktop-moved-1440.jpg)。位置尺寸仅在当前小窗打开期间保留。

## 明确保留的边界

Codex 单轮实际编译输入最多120,000字符、当前材料最多128条，文本请求传输最多16 MB、历史最多4,096轮；图片仍最多4张且沿用原图片字节限制。新会话、reset或映射缺失需要补入的历史仍受单轮保护，明确报错，不截断证据。其他助手和模型直连保持原容量规则。研究目录既有单归档文件8 MiB / 总文件集256 MiB保护仍存在，不承诺无限历史或无限备份。

安装包继续是未签名技术预览；Windows/Intel 的安装器人工安装、信任提示和升级验收未在本机完成。没有新增自动更新或跨设备同步。

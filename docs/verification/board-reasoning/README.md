# 真实 Agent 从材料形成研究白板的验证

2026-10-20。回应用户要求：AI 不应只搬运已有资料，应能够综合方法、提出评估计划和待验证问题；设计复杂交互前先尝试真实生成。

结论：**明确任务和材料后，一次真实 Codex 调用成功生成有操作细节的研究计划草稿；当前复杂白板的视觉表达不合格。** 不能把前者当成全部产品体验已通过。

## AI 实际提出了什么

- **配对比较**：以参数高效微调和全量更新为比较对象，控制模型、数据、硬件与镜像，登记配置和参数规模，观察得分、吞吐、显存、用时并输出逐运行结果表。种子列表、重复次数和配置可比规则待确认。
- **恢复验证**：设置连续运行和受控中断恢复两个条件，核对检查点、恢复步数、日志及最终测量值；明确中断方式、需要保存的状态和可接受差异尚未确认。
- **升级比较与多机演练**：分别保留升级前后环境记录，检查产物可加载性与指标差异；对多机正常退出和受控异常记录退出码、其他进程状态、日志与残留资源。
- **跨材料综合**：将数据/产物、镜像、运行编号、评测指标和升级追溯需求组合成执行链与运行关联清单。完整方案没有预写在任何单段材料中。

这些是可继续落实的计划草稿，不是已经执行的实验。连线如“提供方法比较结果”脱离正文时可能被误读为已有结果，后续应使用“验证后用于……”等计划语气。架构仍有不少步骤浓缩在一张卡的正文中，节点多不自动代表架构表达完整。

## 视觉失败的实况

未经人工修图，原始 `flow` 方案排成 6 列、最多 7 行，画布 2200×2310。卡片本身没有相互重叠，但 4 个分组背景存在 5 对重叠；通过路径采样发现 18 条连线穿越其他卡片，共 33 个“边—第三卡”命中。该检测不等于完整几何证明，截图已人工核对混乱现象。

在 1440×900 和 1280×800、100% 缩放下，首屏仅完整显示 6/18 张卡。缩至产品当前下限 40%，标题约 6px、正文约 4.8px；1440px 窗口仍只能完整看到 16/18 张。13/18 张卡正文被当前四行摘要截断，完整正文仍能在详情读取。诊断时加高到 1380×1174 的窗口可看到全部节点，但不能据此判定正常桌面窗口可读。

原因与优先修正方向：当前所有语义关系都参与拓扑布局，分组再按散落节点计算包围框，造成大范围重叠。下一步应让父子主干和交叉关系独立，保持分组空间明确，提供紧凑节点、分支收起与详情入口，并处理第三节点避障。不要要求模型删掉有价值的关系来掩盖排版能力不足。

## 固定下来的产品约定

1. 先证明真实 Agent 能生成有意义的内容，再以此检验界面；手工原型只证明交互设想。
2. 将按任务提炼、比较、提出建议、指出缺口的规则写入现有单源 Skill，用户不用每次重复长提示；栏目按任务选择，不能固定套方法/评估模板。本轮仅验证并记录这项要求，未修改生产 Skill。
3. Skill 输出结构，应用校验和排版。Skill 无法提供产品尚未实现的父子、折叠或复杂布局能力。
4. 已有白板需要明确的“允许补充草稿卡”能力，复用来源、版本和预览流程；继续保护用户改过的正文与位置。
5. 资料可见范围要明确：现有编辑快照的文档仅有标题，原文须来自显式材料，不能暗示 Agent 已读过全文。

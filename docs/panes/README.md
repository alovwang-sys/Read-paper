# 多窗格工作区

2026-10-17：用户明确将原先的两窗格范围调整为可递归分屏、可移动标签的工作区。本文件取代早期固定主副区的交互说明；历史验收记录仍保留。

## 使用方式

- 每个窗格有自己的标签栏。点击窗格或标签后，新打开的资料、卡片、白板和文稿进入该窗格。
- 将标签拖到另一窗格中央或标签栏，移动到该组；拖到左、右、上、下边缘，在该方向建立窗格。落下前显示接收位置。
- 按住 Option（Windows/Linux 为 Alt）拖动，复制当前视图。窗格菜单的四个分屏命令同样复制当前视图，便于对照同一篇论文的两处内容。
- 同一个窗格可继续分屏，支持三屏、四屏及不对称布局。拖动分隔线调整比例；分隔线支持方向键、Shift 加速和 Home/End。
- 标签可拖回其他标签栏；关闭某组最后一个标签后，该空窗格自动收回。关闭视图不删除资料。
- 窗格菜单可移动当前标签、放大当前窗格、恢复布局，或将所有标签收拢到一个窗格。收拢保留同一文献的多个视图及各自位置。
- 右侧摘录、卡片与 AI 面板仍然共享。焦点变化不自动把其他窗格或选区加入 AI 材料。

标签栏支持方向键、Home/End 切换焦点，Delete 关闭，Shift+F10 打开操作菜单。窄窗口不擅自改写用户布局；可收起侧栏或放大当前窗格阅读。

## 设计依据与取舍

[Ghostty 的方向分屏与切换动作](https://ghostty.org/docs/config/keybind/reference)适合在局部继续分割；[VS Code 的编辑器分组](https://code.visualstudio.com/docs/configure/custom-layout)与 [Obsidian 的标签拖放](https://obsidian.md/help/drag-and-drop)支持用标签直接组织工作区。本项目结合方向分屏与每组标签栏，保持资料阅读和知识编辑共用一个工作区。

没有新增布局依赖，没有单独开一个“分屏模式”页面。菜单是拖拽的键盘替代入口。分屏只在当前研究的中央工作区内操作；跨研究拖放被拒绝。外部窗口、拖入系统文件形成窗格、触屏手势不属于本次范围。

## 数据与恢复

`Session.layout` 保存二叉布局树，叶节点是带独立活动标签的组。分割节点保存方向和比例；布局保存焦点与可选的放大目标。

每个标签拥有稳定视图 ID，引用共享资源实体。PDF 的页码、缩放和页内偏移属于标签，原文资产、摘录、卡片正文仍共用原实体。移动保留视图 ID，复制产生新 ID；收拢不会按文献 ID 去重。白板沿用现有研究会话中的白板视口，未在本次引入同一白板的独立视口。

关闭、复制、移动、切换研究及离开阅读器前同步最新阅读位置；已关闭视图收到的迟到位置更新不会重新创建标签。已有编辑器继续采用共享实体与原保存机制。

旧 `openItems`、固定两窗格与 `main-secondary` 阅读位置在读取时迁移。旧版收起的副窗格转成普通标签，保留其位置。旧字段仅用于导入兼容，新交互操作统一布局树。备份恢复校验树结构、ID、比例、活动标签、研究归属和阅读位置，失败不覆盖现有数据。`openItems` 仍投影为去重的资源列表，供既有导航和固定项使用。

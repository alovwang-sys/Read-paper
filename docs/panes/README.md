# 多窗格工作区

2026-10-18：中央工作区统一承载主页、列表、来源预览和资源。用户已明确将首版范围扩展为递归分屏与可移动标签。本说明取代早期固定双窗及只有资源能分屏的规则；[设计判断](interaction-redesign-proposal.md)与[本轮验收](../verification/pane-navigation/README.md)分别记录方案和证据。

## 使用方式

- 每个窗格有自己的标签栏。左侧导航在最近聚焦的窗格打开对应页面，其他窗格保留；列表打开资源进入该列表所属组，保留筛选和滚动。卡片普通打开也进入中央；明确的“预览”进入右侧。
- 主页、资料和知识列表、无全文详情、未收录来源预览均可分屏。收录成功留在来源预览，可主动“打开资料”；分屏或预览本身不收录资料。
- 将标签拖到另一窗格中央或标签栏，移动到该组；拖到左、右、上、下边缘，在该方向建立窗格。落下前显示接收位置。
- 按住 Option（Windows/Linux 为 Alt）拖动，复制当前视图。窗格菜单的四个分屏命令同样复制当前视图，便于对照同一篇论文的两处内容。
- 无论一个或多个标签，拖到自身窗格边缘均保留原标签并另开同一内容。跨组拖动默认移动；Option/Alt 保留来源并另开。列表资源也可拖入窗格，边缘另开窗格，中央打开标签，列表及资料归属保留。
- 同一个窗格可继续分屏，支持三屏、四屏及不对称布局。拖动分隔线调整比例；分隔线支持方向键、Shift 加速和 Home/End。
- 标签可拖回其他标签栏；关闭某组最后一个标签后，该空窗格自动收回。关闭视图不删除资料。
- 窗格菜单可移动当前标签、放大当前窗格、恢复布局，或将所有标签收拢到一个窗格。收拢保留同一文献的多个视图及各自位置。
- 关闭窗格和收拢后可撤销最近一次布局操作，保留随后编辑及存活视图的新进度。后续结构、比例、放大操作使旧撤销失效；切换范围、删除资源或移出研究也清除撤销，不能恢复资料关联。
- 右侧摘录、卡片与 AI 面板仍然共享。焦点变化不自动把其他窗格或选区加入 AI 材料。
- 打开中央 PDF 不切换右侧模式或清空输入。右侧可在当前窗格或新分屏打开参考，携带阅读位置并保留右侧内容。引用没有有效目标视图 ID 时另开专用视图，保护已打开的独立阅读位置。
- 返回只回退当前窗格的导航。资料库使用独立会话，“返回研究”恢复离开前的布局；查看全局资料不隐式加入研究。

标签栏支持方向键、Home/End 切换焦点，Delete 关闭，Shift+F10 打开操作菜单。方向菜单可用键盘操作。窄窗口不擅自改写用户布局；窗格最小 320×220，中央画布必要时滚动，列表按容器宽度重排，正文字号不缩小。可收起侧栏或放大当前窗格阅读；原生全屏退出是独立操作。

## 设计依据与取舍

[Ghostty 的方向分屏与切换动作](https://ghostty.org/docs/config/keybind/reference)适合在局部继续分割；[VS Code 的编辑器分组](https://code.visualstudio.com/docs/configure/custom-layout)与 [Obsidian 的标签拖放](https://obsidian.md/help/drag-and-drop)支持用标签直接组织工作区。本项目结合方向分屏与每组标签栏，保持资料阅读和知识编辑共用一个工作区。

没有新增布局依赖，没有单独开一个“分屏模式”页面。菜单是拖拽的键盘替代入口。分屏只在当前研究的中央工作区内操作；跨研究拖放被拒绝。外部窗口、拖入系统文件形成窗格、触屏手势不属于本次范围。

## 数据与恢复

`Session.layout` 保存二叉布局树，叶节点是带独立活动标签的组。分割节点保存方向和比例；布局保存焦点与可选的放大目标。

每个标签拥有稳定视图 ID，引用共享资源实体。PDF 页码、缩放、页内偏移，列表筛选与滚动，编辑光标、选择与滚动，白板平移缩放分别按标签保存；原文资产、摘录、卡片正文、白板摆放和文稿正文共用原实体。共享编辑后不活动编辑器保留自己的光标。移动保留视图 ID，复制产生新 ID；收拢不会按文献 ID 去重。

关闭、复制、移动、切换研究及离开阅读器前同步最新阅读位置；已关闭视图收到的迟到位置更新不会重新创建标签。已有编辑器继续采用共享实体与原保存机制。

`layout.version = 2` 在原布局树上迁移资源、导航和预览，保留旧视图 ID 与位置，全局 schema 仍为 3。旧 `openItems`、固定两窗格与 `main-secondary` 阅读位置在读取时迁移，旧字段仅用于导入兼容。备份校验树结构、ID、比例、活动标签、历史、视图状态及研究归属，拒绝跨范围页面和带凭据的预览 URL；失败不覆盖现有数据。`openItems` 只投影为去重资源列表，兼容固定项等旧调用。旧恢复世代的迟到位置更新不重新创建标签。

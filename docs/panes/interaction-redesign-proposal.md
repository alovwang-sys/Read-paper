# 多窗格工作区交互修订提案

2026 年 10 月 18 日。状态：已实现。本文保留设计判断及验收标准；实际规则见[多窗格说明](README.md)，测试、安装包和本机安装状态见[本轮验收](../verification/pane-navigation/README.md)。

中央工作区应始终保留窗格与标签。研究主页、资料列表、摘录、卡片列表、白板、文稿、文献详情和来源预览，都能在其中打开。打开入口只决定内容从哪里来；用户明确选择的操作决定它去哪里。点击导航不应让其他窗格消失，也不应让相同外观的标签突然失去拖放能力。

## 当前设计的问题

目前的二叉布局树与独立阅读视图可以继续沿用，问题集中在它与导航、预览、资源打开的连接上。

| 问题 | 对研究任务的影响 | 修订方向 |
| --- | --- | --- |
| 只有实际资源进入窗格，列表与来源预览替换整个中央区域 | 已经对照好的论文、卡片、文稿被导航页面遮住，分屏入口随页面出现或消失 | 中央窗格宿主常驻，导航页面也成为标签 |
| 概览页与资源页有两套标签行为 | 用户看到相似的标签，却不能用相同手势组织它们 | 所有中央标签共用一种组件和拖放契约 |
| 资料列表点击进入中央，卡片列表点击进入右侧 | 用户必须先判断资源种类，才能预测打开位置 | 列表中的“打开”统一进入所属窗格；右侧用于明确的参考预览 |
| 自身边缘拖放根据标签数量决定移动或复制 | 多开一个标签，原来能用的手势就改变结果 | 根据来源和落点确定结果，移除标签数量特例 |
| 同一资源的多个视图与全局去重打开项并存 | 全局关闭、复用和返回容易作用于错误位置 | 视图 ID 决定操作对象，资源 ID 决定共享内容 |
| 窄窗只检查控件有没有溢出 | 多屏形式存在，阅读与恢复操作却可能困难 | 保留内容标题、放大和还原入口，验证实际可操作性 |

这些问题来自工作区规则没有贯通。继续在某个页面加一个“分屏”按钮，会留下相同的入口差异。

## 工作区的统一关系

研究保存自己的布局。布局包含窗格，每个窗格包含标签，每个标签显示一个页面或资源视图。

- **资源内容共享。** 同篇论文仍只有一份文献和原 PDF；同一卡片、白板和文稿仍使用同一实体。
- **查看位置独立。** 各标签分别保存阅读位置、缩放、列表筛选、滚动位置、编辑光标或白板视口。
- **操作有明确目标。** 窗格中的操作作用于该窗格；左侧导航和右侧参考操作作用于最近聚焦的中央窗格。
- **右侧参考独立保留。** AI、摘录和临时参考继续使用现有右侧面板，不要求用户管理第二套窗格树。中央焦点变化不扩充 AI 材料。

全局资料库沿用独立会话。进入资料库是明确的范围切换，研究的布局完整保留，返回时恢复。项目切换、设置、导入对话框等全局操作不作为可分屏的正文页面。

## 点击导航后保留其他窗格

点击左侧“资料”，在最近聚焦的窗格打开或激活“资料”标签。这个窗格原有的论文或卡片标签保留，其他窗格完全不变。主页、摘录、卡片、白板列表和文稿列表采用同样规则。

从资料列表打开论文，在列表所属窗格新增或激活论文标签，保留列表的筛选和滚动位置。卡片列表的普通打开也采用此规则；查看相关卡片作为参考时，使用名称明确的“预览”操作进入右侧。

用户可以把资料列表放在左侧，右侧上方读论文、下方写卡片。拖动列表中的另一篇论文到右侧下边缘，即可增加一个阅读位置。查资料不需要先离开已经搭好的工作区。

```text
左侧导航        中央工作区                              右侧参考
              ┌─────────────┬──────────────────────┐
资料          │ 资料  ×  分屏│ 论文 A · 第 8 页  分屏 │ AI 对话
摘录          │             │                      │
卡片          │ 筛选与列表   ├──────────────────────┤ 所选材料
白板          │             │ 卡片 · 方法比较   分屏│
文稿          │             │                      │ 输入草稿
              └─────────────┴──────────────────────┘
```

这是目标布局示意，来源列表、论文和卡片都属于同一个中央工作区。

## 打开位置可以预测

| 操作 | 目标与结果 |
| --- | --- |
| 窗格内列表、搜索结果的“打开” | 在操作所属窗格新增标签；若该窗格已有同一资源，激活最近使用的那个视图 |
| 左侧导航、全局搜索中属于当前研究的“打开” | 在最近聚焦的中央窗格打开；不跳去另一个恰好打开同篇论文的窗格 |
| 搜索到未加入当前研究的全局资料 | 明确提供“在资料库查看”和“加入当前研究并打开”；前者进入资料库独立会话，后者显式建立研究关联 |
| 搜索到其他研究专属的白板或文稿 | 明确提供“切换研究并打开”，不把其他研究的专属视图放进当前布局 |
| “在新分屏打开” | 相对目标窗格选择方向，建立新视图；不复用或挪走另一处视图 |
| “预览原文”“预览相关卡片” | 使用右侧参考，不替换中央任务 |
| 右侧的“在当前窗格打开” | 在最近聚焦的中央窗格打开，右侧参考保留 |
| 右侧的“在新分屏打开” | 相对最近聚焦的中央窗格建立新视图，右侧参考保留 |
| 预览未收录的 AI 文献线索 | 打开来源预览标签，也可分屏；只有“加入当前研究”执行收录 |

方向选择显示一个小型落点示意，提供左、右、上、下；这是同一命令的落点选择，不另外建立“左右分屏模式”和“上下分屏模式”。列表行菜单、搜索结果和右侧参考复用同一动作。

资料库提供单独的“返回研究”入口，恢复离开前的研究布局；它与窗格内回退阅读路径的“返回”区分。搜索结果标明归属，打开和拖放都不能隐式加入研究。旧资料库会话也不迁入某个研究的布局。

来源预览的收录状态和 PDF 获取状态继续分开。收录成功不改变窗格布局、不自动跳走；未取得全文也可以继续对照预览、摘要与笔记。预览和分屏本身不创建文献、不下载或复制原文件。

### 引用定位

引用应先表达“预览原文”还是“在工作区打开”。在工作区定位时，存在明确且仍有效的目标视图 ID，才更新那个阅读位置；没有明确目标时，在操作所属窗格新开引用视图，并记录其目标 ID，供后续相同引用动作复用。引用定位不沿用普通打开按文献 ID 复用最近标签的规则，即使同组已打开同篇论文，也不能改掉那个独立阅读位置。

打开需要异步读取时，先捕获研究、目标窗格和目标标签，立即呈现该标签的加载状态。用户切换焦点后，结果只更新原目标；标签已关闭则不重新打开，目标已消失则提示重试，不擅自占用其他窗格。右侧 AI 的输入草稿和已选材料保留。

## 拖放和分屏使用固定语义

“分屏”提供当前内容的另一个查看位置，适合读同篇两处；跨窗格拖标签用于整理已有位置。标签数不参与判断。

| 手势 | 结果 | 预览文案示例 |
| --- | --- | --- |
| 标签拖到自身窗格四边 | 保留原标签，在该方向另开同一内容；一个或多个标签完全一致 | 保留原标签，在右侧打开 |
| 标签拖到其他窗格四边 | 移动这个视图，在目标方向建立窗格 | 移动到下方新窗格 |
| 标签拖到其他窗格中央或标签栏 | 移入目标标签组，不覆盖或合并已有标签 | 移动到这里 |
| 标签拖到本组标签栏 | 调整排序 | 插入到此位置 |
| 标签拖到本组正文中央 | 保持原位 | 原位置 |
| Option／Alt 拖动标签 | 在有效落点保留来源并另开视图；本组中央也允许另开标签 | 保留原标签，在这里打开 |
| 列表中的资料、卡片等条目拖入窗格 | 在落点打开资源；边缘另开窗格，中央打开标签，列表和资料归属不变 | 在这里打开／在右侧新窗格打开 |
| 点击标签栏“分屏”并选择方向 | 复制该标签的查看状态，立即并排显示；空窗格则建立新的空窗格 | 菜单说明：在新窗格查看当前内容 |

自身边缘与跨组拖动的区别，是为研究对照作出的产品取舍，不能声称完全复刻其他软件。两种结果都要在松手前说清楚；用户不需要记忆修饰键才能查看同篇两处。

预览只在有效区域出现，不提前修改布局。四角一次只选择一个方向，靠近边界时避免反复抖动；标签栏的插入位置优先于正文边缘判定。Escape、移出工作区或取消拖动保持原布局。预览文字、鼠标标记与实际结果必须来自同一份动作判定，不能分别实现。

拖非活动标签时，操作被拖的那个标签。跨组移动最后一个标签后，原空组自动收回；收回只作用于空组。相同文献的多个视图移动到同组后仍分别保留，标签显示 PDF 页码，帮助区分。

## 界面保持克制和可恢复

每个窗格只保留一行标签栏，末尾常显“分屏”入口和可达的“放大／还原”。焦点以细边框或标签栏强调色表达，不常驻显示“窗格 1、窗格 2”等管理信息。菜单中的移动目标用当前内容标题及位置描述，便于辨认。

常用动作是打开、拖放与放大；方向、移动和收拢集中在菜单。阅读工具、卡片编辑和文稿保存继续沿用原组件，不为每个窗格再增加一套页面级导航。空窗格提供搜索、打开资料和最近内容入口，不要求先导入论文才能开始。

- **关闭标签**只关闭该视图；同组回到最近使用的标签。
- **关闭窗格**关闭该组的视图，正文和草稿保留，并提供撤销。最后一组关闭后留下可操作的空工作区。
- **收拢所有标签**保留全部视图和各自位置，当前操作的标签继续选中；提供撤销收拢。
- **放大当前窗格**暂时隐藏其余窗格；还原回到原布局和比例，不使用容易与原生全屏混淆的“退出全屏”文案。
- **返回**只回退当前窗格的导航，不重置整个布局；右侧参考保留自己的返回行为。

关闭与收拢的撤销只恢复摆放及关闭时的查看位置，不回滚随后产生的正文编辑，也不覆盖仍存活视图的新阅读进度。只保留最近一次可撤销的布局动作；后续新增／关闭标签、移动、分屏、收拢、调整比例或放大还原使旧撤销失效，正文编辑、阅读和焦点变化不使其失效。切换范围、删除资源或移出研究时也清除对应撤销，不能借此恢复资料或研究关联。不实现通用编辑撤销系统；编辑器保持原有保存与恢复机制。

三至六窗格下，工具条按宽度收起次要操作，标题、分屏、放大、关闭始终可达；正文维持正常字号。布局达到可操作的最小尺寸后，中央工作区允许滚动以访问完整布局，放大用于专注阅读。最小尺寸以三种窗口宽度的真实页面验证确定，不用缩小全局文字来通过截图验收。

窗口变窄不自动更换分割方向、不关闭窗格、不收拢用户标签。1024px 沿用左侧抽屉；右侧面板沿用收起与调宽行为。原生全屏的退出控制保持独立。

## 技术实现边界

沿用现有窗格树、视图 ID、共享业务实体和持久化服务，不引入布局依赖。需要改的是工作区的承载范围和动作契约。

1. **拓展标签承载的视图。** 标签目标使用可区分的资源、研究页面、资料库集合及来源预览类型。主页和列表不是资料实体，不塞入 `ResourceRef`。旧资源标签按原 ID 和阅读位置迁移；现有导航和预览恢复到对应标签，不能重置旧窗格。
2. **常驻中央宿主。** `App` 在当前会话内始终渲染窗格树，由统一的视图渲染器加载正文或列表。`ResourceTabs` 与 `PaneTabs` 合并为一种交互；去重的 `openItems` 只作为兼容投影，不能再驱动另一套关闭、排序或焦点。
3. **统一打开意图。** 由共享服务处理操作所属窗格、最近中央焦点、打开／预览／另开视图及引用锚点。页面不自己猜打开位置。现有 `openResearchView`、`openCollection`、`openResource` 适配到同一服务，右侧独立目标继续保留。
4. **统一动作判定。** 拖入来源区分已有标签和资源条目；共同计算目标方向、移动或另开、插入位置与提示。预览和提交复用判定结果，并校验研究范围与视图存在性。
5. **视图状态完整。** PDF 页码、偏移和缩放继续按标签保存；列表筛选和滚动、编辑光标、白板平移缩放也按标签保存。当前同一白板共享视口的限制需要补齐。正文编辑缓冲按实体共享，不能让两个标签各自用旧副本自动保存并覆盖对方。
6. **兼容与隔离。** 备份校验同时覆盖新视图类型、研究归属、预览数据、树结构和恢复位置。临时来源预览只保存可恢复信息，凭据不进入会话或备份。切研究后的迟到加载不能更新另一研究或重新创建已关闭标签。

实施顺序是先打通“资料列表＋论文＋卡片”的纵向路径，同时完成统一标签与迁移，再覆盖其余入口和恢复行为。只有全部入口与下面的验收通过后，才把本方案写成已交付能力并生成新的安装包。

## 必须通过的用户路径

| 路径 | 验收要求 |
| --- | --- |
| 论文 A 第 8 页＋卡片＋文稿 → 点击资料 → 筛选 → 打开论文 B | 只改变发起操作的窗格；其他视图、正文草稿和右侧输入保留 |
| 资料、卡片、白板、文稿列表 → 打开／在新分屏打开 | 目标规则一致，任何一种资源都不依赖先打开论文 |
| 空工作区、主页、无全文详情、未收录来源预览 → 分屏 | 控制始终存在；预览、分屏不隐式收录，空态能继续选内容 |
| 同篇 PDF 第 2 页与第 8 页 → 点击引用 → 返回 | 有有效目标 ID 才定位旧视图，否则另开引用视图；已有独立位置和缩放不变，包括同组标签 |
| 当前组分别有一个、两个和多个标签 → 同组边缘拖动 | 都保留原标签并另开；预览与结果一致 |
| 跨组拖边缘／中央、Option 拖动、拖非活动标签、取消 | 移动或另开结果符合表格；取消不变；没有错误资源或空白残组 |
| 拖列表条目到已有组和新窗格、拖标签回组 | 列表和研究关联不变；已有同篇多视图不按实体 ID 被合并 |
| 同一卡片、文稿和白板打开两处并编辑或平移 | 正文共享，查看位置独立；关闭一处不丢另一处的编辑 |
| 关闭标签／窗格、收拢、撤销、放大／还原 | 视图和位置可恢复；撤销不回滚后续正文与仍存活视图的位置 |
| 关闭窗格后再移动标签／调整比例，或删除对应资源 | 旧撤销失效，不恢复旧树覆盖新布局，也不恢复资料关联 |
| 刷新、切换研究、进入资料库再返回、导出恢复备份 | 布局、焦点、列表状态、阅读位置和草稿按范围恢复；旧版本数据保留 |
| 当前研究搜索到全局或其他研究资料 | 范围与动作名称明确；查看不隐式加入研究，返回研究恢复原布局 |
| 请求期间切窗格／研究、关闭目标、原资源被移除 | 加载或错误停留在原目标，不覆盖其他任务，不复活关闭的标签 |
| 1440×900、1280×800、1024px：三至六窗格及右侧展开 | 实际点击、拖放、阅读、放大和恢复可用；保留真实产品截图，不仅检查 DOM 或是否溢出 |

## 参考与设计判断

[VS Code 的编辑器分组](https://code.visualstudio.com/docs/configure/custom-layout)把标签与分组用于并排查看，支持拖动、方向分割和临时放大。[Obsidian 的标签](https://obsidian.md/help/tabs)说明了标签组、落点提示与组间拖放。[Ghostty 的动作参考](https://ghostty.org/docs/config/keybind/reference)提供方向分割和窗格放大的动作。它们分别支持本方案的布局与操作选择，没有替 Papertrail 决定列表导航、资料收录或 AI 上下文规则。

本方案的判断是：研究者需要持续保留对照关系，同时在论文、资料列表与自己的理解之间往返。因此把导航页面纳入同一套中央窗格，把引用与 AI 保留在明确的参考流程，并让自身边缘拖放稳定地表达“并排查看”。不扩展外部浮动窗口、跨研究拖放、AI 多窗格或布局模板市场。

## 第一轮原始意见

**总体判断**：分层思路（附送、查找、实际读取三者分开）是对的。但按我读到的节选，"移除材料"在现有代码里实际不起作用，"默认全部历史"在深度研究里会自己卡死，来源类型也还没落到数据结构上。以下依据是你贴出的节选，我没有读仓库其余部分，`server/agents.mjs:316` 这类行号未核对。

## 一、剩余阻塞项与最小修正

**B1. 历史会把"已移除"的证据带回来（代码事实）。**
`snapshotContext` 先遍历历史轮次，把每轮 `context` 中被引用的证据写进 Map，再叠加 `conversation.contextIds`。用户在 `contextIds` 里取消 E1，只要某个已完成轮次带过 E1，下一次请求仍会带上完整引文快照，而不只是回答文字里的转述。设计文档说"只影响直接附件"，实际连这一点都做不到。
- 最小修正：会话增加 `excludedSourceIds`。历史循环按它过滤 `turn.context`，界面文案写"不再附送依据原文；此前回答文字可能仍含其内容"。
- 同时修正容量归属：历史带回的证据与新选证据分开计数，否则 16 条/24,000 字上限会被旧依据单调占满，新证据加不进来。

**B2. 来源类型还只是文案，没有进入数据结构。**
现有 `ContextSnapshot` 只有 PDF 形态（`evidenceId/pageIndex/quote/hash`）。`snapshotContext` 还强制来源在 `research.documentIds` 内，所以未入库候选的摘要目前根本过不了校验。
- 最小修正：来源改成带 `kind` 的联合类型：`pdf_quote | abstract | card_note | background`。
- 只有 `pdf_quote` 可以拥有 `evidenceId/pageIndex`，引用检查按 `kind` 放行。
- 两类容易被忽略的来源要单独标记。一是卡片里已有的 `[n]` 和引号文字，一律标为"卡片内转述，未核对"，不得升级为 PDF 引文。二是"为何相关"这类模型生成的建议，不得随"加入讨论"进入材料。
- "收为卡片"生成的卡要带"AI 草稿·用户确认"标记，否则后面的干净分支会把旧助手判断通过卡片带回去。

**B3. 三个动作的语义自相矛盾，需要一张判定表。**
文档一处说"不再附送只影响下一轮直接附件"，另一处说"范围缩小后新建原生运行会话并重新组装历史"。到底哪个动作会新建会话，没有写清。
- 最小修正：补一张表，列出动作、应用层上下文变化、原生会话是否重建，三行：
  - 停止附送：过滤附件和历史证据，复用会话，并明示"原生侧可能仍记得"。
  - 缩小历史：重建会话。
  - 干净分支：新会话，只含用户编写或确认的项。
- 每个适配器要声明自己是否支持"重建"。不支持的，界面不得出现"排除"字样。

**B4. 干净分支在原生 Codex 下无法兑现"排除旧回答"。**
你的前提是 Codex 能读整个研究目录，而审阅记录里写到 `project-files.ts` 会导出研究内的其他会话。如果旧会话文件在可读目录里，新分支里的 Codex 可以直接读到旧回答。
- 最小修正：分支能力分两级展示。"应用层干净"（请求体不含旧内容）可以声明。"运行层干净"只有在旧会话导出不在该运行的可读路径、或适配器工具能被应用限制时才能声明。
- 没做到之前，Codex 分支预览固定写"目录内仍有旧会话文件，不保证隔离"。

**B5. 默认"全部历史"配合固定子上限，会形成死路。**
- 子上限相加：问题 4,000 + 原文 24,000 + 历史 80,000 = 108,000 字符，只给背景、卡片、摘要和工具返回留下 120,000 − 108,000 = 12,000 字符。这是算术事实，真实余量以 BR0 核实的格式化开销为准。
- 十条摘要加几张长卡片就可能超出。超限后设计只给"减少历史、减少材料、另开分支"，而历史只有全部/最近一轮/无三档，粒度太粗。
- 最小修正：历史按轮次可勾选；超限提示直接指出最占量的那几轮，让用户逐轮取消。
- 这些数字仍然只是保护阈值，不是质量最优值，这一点文档已经写对。

**B6. 焦点切换的"替换/累加"规则没定义，原型实际是累加。**
`useSelected` 只做 `attachments.add`，从不移除上一个焦点。卡片→论文→回卡片之后，附件只增不减，这与"默认只发必要内容"相反。`cleanBranch` 还会把这些累积项整体复制。
- 最小修正：明确"焦点"和"附件"是两个集合。焦点每次只有一个，切换时旧焦点降为"可选附件，默认不勾"。
- 干净分支只复制用户在预览里确认勾选的项，而不是整个 `attachments`。
- 另外，原型里 `newSession` 会覆盖 `rootSessions` 的映射，之后点原问题进入的是分支而不是原会话，需要明确"原问题下可见哪些会话"。

## 二、默认上下文和数量够不够清楚、可用

- **清楚的部分**：分层表、背景与焦点的区分、"入库不等于入对话"都清楚。
- **不够用的部分**：
  - 输入区上方的一行"材料 N"把卡片、摘要和原文混在一起。N=3 可能是三张短卡，也可能是三份长摘要，用户无法判断容量。应按类型分计（卡/摘要/原文/历史轮），并各自显示字符估计。
  - 深度研究里历史增长是主要压力，而控制手段只有全部/最近一轮/无，缺中间档（B5）。
  - 查找范围每次扩大都要"等待用户选择"，长程研究会很烦。可以让选择在会话内持续有效，但仍只返回候选，不进入证据集合。
  - 字符数与 token 的比例随语言（中英文摘要混合）和模型变化，需要实测，文档的"不伪造精度"做法是对的。

结论：能让用户看懂"发了什么"，还不足以让用户在 20 轮之后控制"发多少"。

## 三、案例走查

问题 Q：检索材料越多越可靠吗？

1. **T1**：焦点 Q，附件为背景和 Q 卡。
2. **T2**：加入 PDF 摘录 E1，提问。
3. **T3**：找文献，批次 B1 读了十条摘要（只在批次里）。对论文 P 点"加入讨论"，P 的摘要 A_P 成为 `abstract` 类型来源，焦点切到 P。
4. **T4**：追问 P。此时 Q 的背景仍在，历史有 T1–T3，T2 的 E1 随历史自动带上。
5. **T5**：回到 Q 提问。当前代码下，旧焦点 P 还留在附件里（B6）。

用户移除 E1：
- **现状**：E1 仍经 T2 到 T4 的 `context` 重新进入请求（B1）。
- **修正后**：E1 被过滤，但 T2 到 T4 的回答文字仍在。界面要说明这一点。

用户点"以当前材料另开干净分支"，预览应列出：
- **保留**：研究目标、Q 卡、当前勾选的 A_P。
- **排除**：T1–T5 的助手回答、E1 以及所有旧摘要。
- **残留警告**：Q 卡或其他卡片若由 T3 回答"收为卡片"而来，会被标注为"AI 草稿·用户确认"（B2）。此外，原生 Codex 可能仍读到旧会话文件（B4）。

在分支里继续提问，请求中历史为零，原生会话新建。回原问题时，原会话和 B1 批次保持不变。分支只能把 B1 的候选当"可再次加入"的候选，不继承其已读内容。

## 四、有没有更简单、更好的设计

有。建议把"附送材料、历史、查找范围"三条轴合并成**一个带类型的"本轮材料篮"**。

- 篮里每一项是一个来源，带 `kind` 标签、字符数和勾选开关，包括卡片、摘要、PDF 摘录，以及每个已完成轮次。
- 轮次的"回答文字"和"该轮带的依据"分开两个开关，回答文字可单独勾选。
- 默认勾选规则：背景、焦点、最近一轮。其余轮次显示出来但不勾，用户可以全选。
- 取消勾选就是移除，不再有"停止附送、缩小范围、排除"三套语义。统一预检也只需要对篮子求和。
- 干净分支 = 新篮子只复制用户编写或确认的项。
- "查找范围"不再是会话状态，改成像"找文献"一样的独立动作，例如"在本研究里找依据"，只返回候选，用户点"加入"才进篮。这样"宽泛查找权限静默扩大答案证据"在结构上无法发生。

代价：多轮默认只带最近一轮，用户需要手动勾选更早轮次，对长程研究多一步操作。这也是对你"默认全部历史"的一个反向建议，我认为值得，因为它同时解决 B1、B3、B5。

# 对折中方案的复核

说明：本轮是只读讨论，我没有使用任何工具，以下依据仍是你们贴出的节选。

## 一、是否覆盖了真实阻塞

(a)–(e) 基本覆盖了 B1–B6，但还有三处缺口。不补上，修正会在别处失效。

**缺口 1：原生会话与按轮选择历史相互冲突（最关键）。**
- 如果适配器在追问时复用 native session（resume 或续接），原生侧已经保有全部先前轮次。此时应用清单写"只带上一轮"，实际并不成立。
- 按轮选择历史要真实生效，只有两种做法：
  - 每次历史选择变窄时，重建原生会话；
  - 适配器明确支持替换历史。
- 两者都做不到时，界面须写"原生会话仍保留先前轮次"，不得显示为已排除。
- 这一点要逐个供应商实测，不能统一假定。

**缺口 2：洞见卡会成为被移除来源的回流通道。**
- 回流路径：T2 回答引用 E1 → 收为洞见卡 → 用户钉住 → 移除 E1 后，内容仍经卡片进入请求。
- 排除集合按来源 ID 拦截，拦不住这条路径。
- 最小修正：
  - 草稿建卡时记录 `derivedFrom`，写入它所依据的来源 ID 和轮次 ID；
  - 钉住的卡若与排除集合相交，在清单中就近警示；
  - 卡片的 kind 标为"AI 草稿·用户确认"，不得记作用户原创笔记。

**缺口 3：历史回答中的引用编号失去对象。**
- "旧原文不隐式重附"是对的，但所选历史回答里仍有 `[2]` 这类编号，其原文已不在本轮清单中。
- 组装时应把这些编号改写为"历史引用（原文未附送）"。
- 本轮回答的引用校验只放行当前清单中的 `pdf_quote`，否则模型会沿用旧编号冒充证据。

## 二、"上一轮 + 钉住卡片"够不够用

它作为保守起点可以接受，但正好在本产品的核心环节最容易出错：**回到原问题**。

典型路径：
1. T2 在 Q 上得出结论；
2. T3、T4 讨论论文 P；
3. T5 回到 Q。

按默认规则，此时历史只有 T4（关于 P），T2 的结论已经不在请求里。

建议的最小补丁：默认历史为"上一轮 + 最近一次焦点为原问题的已完成轮次"。这是一条结构规则，不是数量结论，仍需与其他方案对比验证。

**应当测试的具体失败：** 固定一个 6 轮脚本（Q → E1 → 找文献 → P → P 追问 → 回 Q），第 6 轮提问"结合这篇论文，修正我们之前对 Q 的结论"。对比三组：仅上一轮、上一轮 + 原问题锚点轮、全部历史。在真实模型上记录：
- 第 6 轮是否准确复述 T2 的结论；
- 是否与 T2 自相矛盾；
- 是否声称知道未附送轮次的内容（原生会话残留的信号）；
- 用户为得到可用回答需要手动补勾几次。

## 三、必须现在做单一材料篮吗

不必。两个紧凑入口可以共享一份清单，前提是满足以下三条：
1. 只有一个 manifest 状态。"历史模式"不能作为独立字段存在于清单之外，两个入口只是同一检查器的不同过滤视图。
2. 输入区显示的计数与统一预检都从 manifest 求和得出，任一入口里的取消在另一入口立即可见。
3. 超限提示直接定位到具体的轮次或来源，并能就地取消，不跳转到另一处入口。

缺任何一条，就等于又回到了三套语义。

## 四、动作、原生会话与残留信息

| 动作 | 应用清单变化 | 原生会话 | 仍可能残留 |
|---|---|---|---|
| 切换焦点 | 自动焦点材料被替换，钉住项不变 | 复用 | 旧焦点内容仍在已选历史回答中 |
| 加入讨论 / 钉住 | 加入清单，并从排除集合移除 | 复用 | 无新增 |
| 停止附送来源 | 加入排除集合，历史中的该来源快照也不再附送 | 复用 | 历史回答文字、派生卡片、原生会话记忆 |
| 取消某个历史轮 | 该轮问答移出清单 | 须重建；做不到则标注残留（待实测） | 原生会话中的先前轮次 |
| 找依据（白板 / 研究） | 只产出候选，不进入清单 | 不涉及 | 检索批次的读取记录 |
| 找文献 / 入库 | 不改变清单 | 不涉及 | 批次中已读摘要，仅留在该批次 |
| 干净分支 | 新 conversation；助手消息为零，只保留预览中确认的背景和卡片 | 新建 | 卡片里的转述内容；研究目录内的旧会话文件（Codex 可读） |
| 另开问题 | 新 conversation，以新问题为起点 | 新建 | 研究目录文件 |

补充两点：
- 在 Codex 原生模式下，聊天中模型可能自行读取目录文件。这些读取只能记为"读取记录（未纳入证据）"，不能获得引用资格。
- 以上做法都不是运行时沙箱，文案不应出现"隔离"二字。

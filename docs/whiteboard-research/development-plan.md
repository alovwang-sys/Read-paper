# 白板局部研究的开发计划

日期：2026 年 10 月 20 日。状态：用户确认继续后已实施 BR0–BR3；BR4 的实际运行结果与供应商边界见[实施验收](verification/implementation/README.md)。前两轮原型证据保留，不替代正式功能验收。

第二轮已对照官方资料、实际代码和 Claude Code 两轮讨论核实：[上下文与连续探索](context-design.md)统一默认材料、独立查找、历史收缩和预算；[审阅记录](review/context-audit.md)保留第一版缺口、首次认证失败与随后两轮成功审阅的边界。下面的契约按该设计收敛，不能仅凭第一版可点击就进入完整实现。

## 最小契约

继续使用 `openResearchView / openCollection / openResource / setSelection / addContext`。不新增第二套侧栏、全局资料、卡片正文或研究身份。下述字段是建议，实施时由集成负责人结合当前类型统一落地。

`Conversation` 增加原问题起点和可变焦点：researchId、boardId、rootQuestion 的卡片／摆放与正文快照、focus 的 resourceRefs。论文作为焦点继续使用当前问题会话，明确另开问题才创建另一会话。绘图文字先经预览确认生成问题卡和 Placement，保存原 elementId 与文字快照作为来路，后续统一用 placementId 定位与连线。自动焦点与主动保留的附件分开：换焦点只替换自动项，不不断累加。起点背景按材料清单明确发送；取消背景和根卡后，不能从 originQuestion 元字段绕回正文。每次 `AIRequest` 冻结请求清单、焦点、历史轮次和原生运行身份，检索任务另存允许查找范围。后续选区或正文变化不改写该轮快照。

文献搜索请求至少保存 researchId、conversationId、原问题起点、查询、方向、筛选项、提交时间、状态及结构化候选。候选有 provider/providerId、标题、作者、年份、DOI/arXiv、来源落地页、可选摘要／公开 PDF 链接、检索时间及可选的相关性说明。缺少字段如实表示，不让模型补写 DOI、作者或来源网址。相关性说明保留其使用的是标题、摘要还是原文。

搜索批次独立于当前焦点，完成、结果查看、放置和返回都使用发起时的会话与 rootQuestion，不能读完成时的全局当前选区。切到其他问题不覆盖原批次。首批最多 10 条题录和摘要可用于已说明的相关性分析，但不自动加入后续问答；用户可对尚未入库候选执行“加入讨论”。

候选与文献实体分开：用户收录时返回 `documentId`，候选保存映射；重复请求不能重复建实体。DOI、arXiv 工作标识和来源 ID 精确匹配可复用元信息，模糊标题匹配只提示。文献资产仍使用独立稳定 ID/hash；发现不同 hash 的版本文件时保持独立文档／资产并提示核对，不自动替换或合并，不新增同文档多版本资产模型。

`BoardPlacement` 与 `BoardEdge` 继续作用于 placementId。放置新资料只新增摆放实例和“相关文献 · 待核查”联系，不改变原卡正文；重复点击不重复放置，用户主动在别处复用同一实体仍被允许。原板版本变化、锚点消失或研究关联变化时重新校验，结果不覆盖当前内容。原文证据保存在观点卡片中，Edge 继续只有用户填写的关系标签，不承诺结构化关系证据。

上下文扩展必须显式发生。采用背景、卡片、摘要、PDF 原文、历史轮次的类型化来源；未入库候选使用 provider/providerId、URL、批次和内容版本，不要求已有本地 documentId。来源快照贯穿 `AIHistoryTurn`、草稿、`CardProvenance` 和导出，不给摘要伪造 evidenceId 或 pageIndex。“为何相关”建议不混入作者摘要。AI 收卡记录用户确认状态及 `derivedFrom` 来源／轮次，避免被当作用户原创；派生卡与排除集合相交时提示回流。历史编号没有当前 PDF 原文时降为历史引用说明，不能在本轮借用旧编号。

BR0 同时更新客户端 `src/services/ai.ts` 和服务端 `server/agents.mjs` 的严格请求校验、prompt、类型化材料清单与原生会话范围指纹。普通聊天必须支持局部来源，不能只扩展前端类型。移除来源同时过滤直接附件和历史来源快照的副本，排除集合防止 `snapshotContext` 重新带回完整引文；旧问答文字或派生卡仍可能包含其内容，须提示。干净分支不自动继承旧助手回答，按用户确认的背景和当前材料新建运行会话；目录内旧文件仍可能被读取。各供应商逐一验收，不把应用层新分支说成运行时隔离。

重建会话前重新组装允许的历史与材料；仅换 native ID 再重发旧正文不足以缩小范围。默认历史为上一完成轮加最近一次原问题焦点完成轮，去重，并支持逐轮选择；这是待验证的初始策略。历史范围变窄时适配器必须新建或替换原生历史，做不到则明示残留，不假称排除成功。两个紧凑入口共享一份最终 manifest，预算、预览和发送用同一结果；超限定位具体项，不静默裁剪。模型容量未知时不展示精确 token 剩余量。工具读取记录不完整时如实标明。

## 开发切片与所有权

依赖顺序：BR0 → BR1；BR0 → BR2；BR1 + BR2 → BR3 → BR4。BR1 与 BR2 契约稳定后可以并行，最终由主 agent 集成。

| 切片 | 完整用户行为 | 文件所有权与依赖 | 生产状态 |
| --- | --- | --- | --- |
| BR0 共享契约 | 局部问题、实际发送范围、候选与资料归属明确；旧数据可读 | domain、data、workspace、ai 服务、server/agents、备份、目录和导出 | 已实现；兼容 schema 3 的可选字段与严格校验 |
| BR1 局部提问 | 两种白板模式中选中共享内容后问 Agent；可新建问题；输入和起点可恢复；绘图文字显式转问题 | board 与唯一 AI 面板 | 已实现；多选／分区核对、来源草稿恢复均有验证 |
| BR2 真实找文献 | 用户调整查询后，获得真实结构化结果，能停止、重试及回看前一轮 | `server/literature.mjs`、`src/services/literature.ts`、`BoardLiterature.tsx` | 已实现；OpenAlex 真实查询与年份过滤已验证 |
| BR3 收录与继续 | 候选去重入库、关联当前研究、放回问题旁；可继续追问并确认建卡 | `board-research.ts`、共享资料服务与卡片草稿 | 已实现；收录／附送／摆放分别生效，摆放幂等且保留原问题 |
| BR4 全链路验收 | 真实问答与搜索、PDF 补齐、证据回查、保存恢复、三尺寸和异常均有证据 | 主 agent：tests 与实施验收 | 按证据分项验收；真实供应商、受控 UI 与原型结果分开记录 |

首次完整交付可以通过已有补 PDF 流程进入真实阅读，自动公开 PDF 获取只有在单独完成下载、文件校验、hash 和错误恢复后才标为实现。链接存在不算获取成功。

每次派工需说明负责文件、公共文件禁改边界与验收目标，并告知执行者不是唯一修改代码的人。局部组件完成不代表 BR4 通过。

## 检索服务的边界

优先用 OpenAlex 的单一来源完成查询与文献元信息读取，先做少量真实探针确认当前 API 行为、结果覆盖、额度、摘要与公开链接字段，再实现 UI。查询不得依赖任意模型自行写出一个“看起来像论文”的结果列表。

服务返回的数据按外部文本处理，标题和摘要不执行为 HTML 或指令。请求有时间与页数上限，用户显式继续才扩展。认证失败、限流、超时、部分结果和零结果使用不同状态。若后续接下载，服务端只取允许的公开 HTTPS 来源，校验重定向、文件类型、大小与内容 hash；失败不损坏原资料。当前方案不要求新建微服务或通用检索插件平台。

公开搜索只发送查询与用户明确允许的研究词，不上传整库或未选的全文。模型拿到的候选范围和引用由代码检查；入库及摆放由应用服务执行，不能依赖模型“声称已保存”。

## 验收矩阵

| 编号 | 必须通过的用户路径 |
| --- | --- |
| BV01 | 主区白板选一张卡，点问 Agent，发送快照包含该卡正文和所选证据；普通问句不会丢上下文或触发整板编辑 |
| BV02 | 卡片布局和绘图模式共享卡片/PDF 可使用相同入口；绘图文字预览后转共享问题卡，切模式仍能定位；图形／图片没有可读文本时提示写问题 |
| BV03 | 多选／分区只发送列出的成员；选择另一节点不自动改变待提交或已提交材料 |
| BV04 | 同一问题多轮追问、另一问题新会话、节点继续上次讨论均可返回；共享卡片在不同板上的起点可区分 |
| BV05 | 真实检索结果带可核查标识与来源；查询可编辑；失败、零结果、停止及部分结果各有明确反馈 |
| BV06 | 收录库内、库外及已在当前研究的三种论文，正确复用实体；连点、重试不重复创建；来源 URL 可追踪 |
| BV07 | 加入资料库不改变白板；主动放置后出现在原问题附近；撤销摆放不会删库内实体或他板引用 |
| BV08 | 从候选→入库→补 PDF／实际获取→阅读→保存原文→回问题→收为新卡；新卡引用属于提交范围，页码和 hash 可核查 |
| BV09 | 仅有摘要时问答明确只读过摘要，不能生成原文页码或自动判定支持／反对；摘要来源贯穿追问、草稿、卡片和导出；普通移除提示历史残留，干净分支不自动继承旧助手正文及来源；失效全文链接保留文献记录 |
| BV10 | 检索期间切换研究，迟到结果仍归原研究；原节点删除、白板改动、资料移出研究时保留结果且拒绝错误摆放 |
| BV11 | 收起面板、查看来源、切研究、关闭资源和刷新后恢复输入、结果、滚动与视口；保存失败保留草稿并能重试 |
| BV12 | 新字段经过持久化、ZIP 导入导出和目录输出；旧备份继续可用；旧 PDF 与来源不受替换 |
| BV13 | 1440×900、1280×800、1024px 走通主要操作并存本产品截图；验证白板＋右侧来源、白板＋AI，不用竞品截图代替 |
| BV14 | 同一问题切论文焦点仍保留原问题和多轮历史；明确另开问题才切会话，返回恢复草稿 |
| BV15 | A 问题慢搜索时切 B，A 结果不出现在 B；从旧批次放置仍使用 A 锚点；目标失效要求重选 |
| BV16 | 旧轮提交后修改卡片或查询，旧轮“当时材料”保持原正文／版本；读取记录与直接附送记录分开 |
| BV17 | 不再附送材料的提示涵盖历史残留；干净分支不复制旧助手正文；原问题转述内容在新分支预览可见 |
| BV18 | 单独放大卡片／摘要／历史都能触发最终统一预算检查；缺少 tokenizer 或原生窗口信息时只显示估计与未知项 |
| BV19 | 研究内检索允许返回原文候选，但未明确加入讨论的片段不能成为正式回答依据；查找范围变化不自动扩大问答证据集合 |
| BV20 | 切焦点只替换自动材料，明确保留项才持续附送；取消来源后历史原文快照不再合并回来，派生卡回流有提示 |
| BV21 | 固定六轮“原问题→依据→找论文→论文→追问→回原问题”，真实对比三种历史策略；验证原生续接是否偷偷保留已取消轮次 |

生产验证从真实配置使用 `npm run check`、`npm test`、`npm run test:server`、相关 `npm run test:e2e`；仅改动涉及桌面时再跑相关桌面检查。真实 Agent、演示适配器和文献 API 的结果分别记录。原型通过不能将上述任务标为完成。

## 本轮交付与下一步

用户确认继续后，正式实现已复用统一工作台、Conversation、PDF 原文证据、资料实体及保存服务；未新增依赖或另一套路由。原型证据分别保存在[第一版验证](verification/README.md)与[第二版验证](verification/context-v2/README.md)，实际实现与已知边界以[实施验收](verification/implementation/README.md)为准。未自动推进其他 backlog、打包发布或修改外部研究系统。

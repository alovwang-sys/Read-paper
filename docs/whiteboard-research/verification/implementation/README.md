# 白板局部研究实施与验收

日期：2026 年 10 月 20 日。对象为正式 React 应用，设计原型仍独立保留。本轮未发布、未生成新安装包；没有新增依赖。

## 已接入的用户路径

1. 在卡片布局或绘图白板选中卡片／文献，直接“问 Agent / 找文献”。多选与分区先核对成员，选区变化不自动扩大问答材料。
2. “写问题”原子建立共享卡片、研究关联及摆放；绘图文字经核对后转为问题，保留元素 ID 与文字快照。未完成草稿连同来源按研究保存，关闭、切换和刷新可恢复。
3. 原问题保留在 AI 面板，论文和派生卡片可切为同一探索的焦点。自动材料随焦点替换，明确保留项持续附送；入库、加入讨论及放置分别生效。
4. 材料、原文与所选历史经同一 `buildRequestScope` 组装。默认上一完成轮＋最近一次原问题轮，可改全部／最近／不带／逐轮。旧请求保存正文、来源版本、历史和焦点快照，不随当前卡片编辑改变。
5. “找已有依据”是应用本地文字查找，范围可选已选材料、当前板、本研究；扫描与候选另存快照。候选明确加入后才进入问答，不成为常驻查找授权。
6. “找文献”通过本机服务调用 OpenAlex，发送可编辑的关键词与起止年份，首批最多 10 条。限制／反例及当前论文标题是检索词建议，不自动发送，不推断论文支持或反驳观点。
7. 候选以来源 ID／规范 DOI 去重入库并关联当前研究；放回问题旁使用发起批次的锚点，幂等、不覆盖原布局。迟到结果仍归原研究和会话，锚点已失效时保留候选并拒绝错误摆放。
8. 无全文文献可沿已有详情页补 PDF，保留文献 ID、研究关联和摆放；阅读后选原文回同一讨论，再确认卡片并放回问题旁。

## 来源与运行边界

`ContextSnapshot` 继续仅表示真实 PDF 摘录／区域，不把摘要伪造成 `evidenceId`、hash 或页码。背景、卡片、题录／来源摘要单独建模；历史旧编号没有当轮原文时降为历史引用说明。AI 卡片保留 `derivedFrom`、原始问答及材料快照，摘要来源随 ZIP、研究目录和 Markdown 保留。

停止附送来源会过滤直接附件及历史原文副本；旧问答文字、背景或 AI 派生卡仍可能转述它。新分支从零继承助手消息，并预览其材料。局部研究每轮新建原生运行，只发送所选历史；原生目录工具的访问范围另行保留，新原生 ID 不是文件沙箱。

界面展示字符估计，模型 token 窗口及剩余容量未知时不显示精确百分比。保留现有 4,000 字符问题、16 条／24,000 字符原文、80,000 字符历史、120,000 字符总输入保护，并统一计算非 PDF 材料。当前与所选历史的非 PDF 材料按来源 ID 去重，合计最多 100 项，避免后续卡片来源超过持久化上限。它们是工程边界，不是最佳上下文长度。

## 运行与未建设范围

沿用 `npm run dev` 和 `npm run ai`。可选 `OPENALEX_API_KEY` 只设置在本机服务环境；匿名是否可用、额度与限流以当时服务返回为准。UI 测试可用现有 `npm run test:e2e -- tests/e2e/board-research.spec.ts` 复跑；测试使用隔离浏览器数据。

PDF 通过现有本地补全文流程进入阅读；公开 PDF 链接未自动下载。未增加 OCR、语义检索、相关性模型评分、无限翻页或新的供应商平台；没有构建安装包、发布版本或进行跨系统安装验收。模型质量仍需真实研究任务扩大样本；文件权限及各助手实际状态以本目录探针为准。

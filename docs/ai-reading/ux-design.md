# AI 阅读、对话与知识卡片：交互设计

日期：2026-10-16。状态：待开发设计；[可点击原型](prototype.html)仅使用自制样例和预设回答，不表示真实模型、PDF 框选或数据恢复已经实现。产品范围见[需求规划](requirements.md)，实施拆分见[待开发计划](development-plan.md)。

本文保留该轮设计基线。当前已实现的引用在中央 PDF 打开、1024px 原文与 AI 并排，详见[助手设计](../agents/design.md)；2026-10-17 已接入[研究目录与原生会话 UX 第一版](../agents/project-sessions-ux.md)，实机能力与未验收项见[验证记录](../verification/project-sessions/README.md)，不据此修改旧原型的能力记录。

## 1. 用户要完成的事

用户在阅读中遇到不理解的段落、图表或公式，希望带着这段材料提问；通过追问形成自己的理解，再把其中一个知识点整理成卡片。以后既能核对论文依据，也能回顾当时如何得出理解。

交互围绕“选择 → 明确发送范围 → 连续讨论 → 整理草稿 → 修改确认 → 双来源回查”安排。阅读位置持续留在主区，AI 和卡片草稿使用同一个右侧面板。卡片编辑不改变原始问答。

### 两期范围

| 阶段 | 可设计、开发及验收的行为 |
| --- | --- |
| R1 | 有文本层 PDF 的文字选择；真实多轮流式对话；整条回答或片段整理为独立卡片草稿；AI 修订与人工编辑；确认入库；论文与对话来源；历史、草稿和研究恢复 |
| R2 | 对图表、公式及扫描页作区域框选；预览实际发送图像；使用支持图像的模型提问；保存区域与图像快照。OCR 不作为区域问答的前置条件 |

当前已有应用保留文字选区、演示 AI、卡片编辑与论文来源的基础能力；本文件中“应当”与原型展示的完整闭环均为规划，不能据此标记已完成。

## 2. 信息架构与工作台边界

```text
左侧：全局入口 / 当前研究 / 固定项 / 已打开资源
主区：PDF 阅读、卡片库与卡片正文、白板或结论（沿用现有宿主）
右侧：证据 | 参考 | 信息 | AI（每次一种模式）
  AI 内部：当前会话 ⇄ 会话历史
                    ⇄ 卡片草稿（回到原消息与滚动位置）
                    ⇄ 来源预览（返回原草稿 / 卡片 / 会话）
```

- 不增加第四栏、第二套聊天状态或顶部打开项。
- AI 中生成卡片后，右栏进入草稿子视图；顶部显示“返回对话”，保留尚未发送的输入、消息滚动和来源位置。草稿有自己的 `dirty / saving / saved / error`。
- 在主区打开卡片时，右栏可继续显示其来源；在主区打开论文前保存卡片编辑缓冲。返回主区原任务时恢复原视口。
- 普通来源点击仅更新右侧预览。只有明确点击“在主区打开”才替换主区。主区和右侧各自维护返回路径。
- 右栏切到其他模式、收起或切换研究时不清空卡片草稿、输入或对话。
- 全局资料浏览不默认继承最近研究。第一次“向 AI 提问”先展示研究选择器，确认按钮为“加入所选研究并用于对话”；选定后由共享服务建立资料关联。
- 研究切换后显示目标研究的会话、打开项和草稿；迟到响应留在原研究，可在原研究名旁出现完成标记。

### 入口位置

| 入口 | 布置 | 结果 |
| --- | --- | --- |
| 选中文字 | 选区邻近浮层，避开被选文字 | “向 AI 提问”“创建证据卡片”；前者先产生证据、再加入当前会话 |
| 无法选中文字 | 阅读器状态条 | 解释文本层状态；R2 可切到“区域框选”，R1 提示尚不支持 |
| 对已有证据提问 | 证据条目操作 | 加入指定会话，不重复产生同一条证据 |
| 从卡片继续讨论 | 卡片来源区 | “查看相关对话”，再显式“继续此对话” |
| 找历史 | AI 标题栏“历史” | 仅列当前研究；支持搜索、恢复、归档和查看已归档 |
| 找保存结果 | 当前研究卡片入口与全局卡片库 | 使用同一 Card；“加入研究”仅建立关联 |

## 3. 布局、样式与适配

沿用 Papertrail 的浅色研究工作台：低对比灰绿背景、白色阅读页、深绿主操作，突出原文和内容；不以彩色气泡承载长回答。标题与正文保持紧凑、便于长时间阅读。

| 设计变量 | 规格 |
| --- | --- |
| 左栏 | 1440 宽默认 240px；1280 宽 220px；可折叠为 56px 导航轨 |
| 右栏 | 默认 360px，可拖动 320–520px；同时保证主区约 640px，不能无限挤压主区 |
| 1024px | 默认折叠左栏；AI 作为右侧覆盖抽屉，最大 420px、宽度不超过视口；有遮罩、关闭与焦点约束；不会把正文压到不可读 |
| 更窄屏幕 | 单任务区；AI 抽屉接近全宽，正文不横向溢出。桌面优先，不承诺完整移动端 PDF 编辑 |
| 顶部 / 工具条 | 主区标题 56px；PDF 工具条 44px；右栏标题约 56px |
| 字体 | 应用正文 14px；消息及编辑内容 14–16px、行高 1.65；辅助文字 12px，紧凑标签不低于 11px；中文用系统无衬线，模拟论文用衬线 |
| 间距与圆角 | 4 / 8 / 12 / 16 / 24px；输入与按钮 8px；卡片 12px；轮廓线 1px |
| 交互目标 | 常用按钮至少 32px 高；图标按钮至少 32×32px；主要触屏关闭入口 40px |
| 强调色 | 深绿 #287364；文字 #24352f；低强调 #6e7a75；描边 #dce3de；选区 #dcece4 |
| 焦点与状态 | 2px 高对比焦点环；成功 / 失败同时有文字和图标；不只依赖颜色 |

1440×900 下主区论文与 AI 同时可见；1280×800 下保留输入区完整、长消息独立滚动，不让整个应用上下滚动。正文可滚动区与底部输入区分开；输入多行增长到约 160px，随后内部滚动。右栏调宽保存为应用偏好，模式、固定状态和工作位置按研究恢复。

## 4. 编号页面状态

编号是设计与测试定位点，不意味着创建独立路由。每个状态复用统一宿主。

| 编号 | 状态与核心内容 | 主要动作 | 空、加载、失败、恢复 |
| --- | --- | --- | --- |
| S01 阅读就绪 | 主区 PDF、页码、文本提取状态；右侧 AI 欢迎与当前研究 | 选文字、切换区域模式、打开历史 | 无研究时选择研究；无 PDF 时导入；PDF 加载失败可重试。阅读可就绪而文本仍处理中 |
| S02 选区预览 | 原文高亮与浮层；R2 是矩形、页码、截图预览 | 解释这段、向 AI 提问、取消选区 | 空白区拒绝无效选择；两期均为单页选区，需要多页时逐页添加 |
| S03 提交前 | 本轮证据条目、前序对话范围、问题输入、模型状态 | 查看 / 移除证据、设置范围、发送 | 无模型显示设置入口；超容量可减少范围；输入与证据失败后保留 |
| S04 连续对话 | 用户消息、只读 AI 消息、引用、轮次材料摘要 | 追问、停止、重试、重新生成、整理整条 / 片段 | 生成中仅流式阅读；停止 / 断流保留部分结果并标未完成；完整结果经引用校验后允许整理 |
| S05 卡片草稿 | 标题、正文、来源、待核查状态、AI 修订区；顶部返回 | 人工编辑、AI 修订、应用修改、恢复上一版、保存 | 生成中保留原稿；修订失败可重试；引用校验失败保留正文并指明问题；暂离仍保留草稿 |
| S06 卡片已保存 | 可编辑卡片、所属研究、论文依据与相关对话两个分区 | 查看来源、继续对话、到卡片库 | 保存后给出结果入口；重复点击防止重复卡片；保存失败保留草稿并重试 |
| S07 来源回查 | 论文页 / 摘录或原始问答；“返回”及“在主区打开” | 定位、展开上下文、查看当次范围 | 文件缺失仍显示摘录和来源信息；精确锚点失效回到正确页；会话已归档仍可读快照 |
| S08 会话历史 | 当前研究下按最近活跃排序的会话、日期、预览、草稿数 | 搜索、打开、新建、归档 / 恢复 | 无会话有“开始新对话”；搜索无结果可清除；归档保留卡片已引用记录 |
| S09 异常与恢复 | 与所在任务相邻的错误条、状态、保留内容说明 | 原快照重试、恢复草稿、新会话、设置模型 | 刷新恢复草稿和消息；中断请求不伪装完成；研究切换不会把恢复内容塞进当前研究 |

## 5. 关键流程与文字线框

### 5.1 选择原文并提问（S01 → S02 → S03 → S04，PR01 / PR02 / PR08）

```text
PDF 第 3 页 · 文字可选择
“Retrieval improves factual accuracy when the evidence corpus is relevant.”
                [向 AI 提问] [创建证据卡片]

右侧：AI / 当前研究 / 会话名称                 [历史] [新对话]
┌ 本轮材料 · 1                                         ┐
│ [1] 自制研究材料 · PDF 第 3 页                 查看 × │
│ 前序对话：本会话 2 轮 [调整]                         │
│ 前序消息可能包含此前材料；移除上方证据不会改写历史。 │
│ [输入：为什么证据相关性会影响准确性？]               │
│ 模型 / 文本模式                             [发送 ↑] │
└─────────────────────────────────────────────────────┘
```

1. 点击“向 AI 提问 / 加入当前对话”把选区加入上下文，等待用户发送；只移动选区不发送、不增加范围。操作后保持原文高亮，焦点进入输入框，读屏宣布“已加入 1 条证据，尚未发送”。“解释这段”使用可见默认问题并立即发送；首次使用外部模型前，必须先完成连接设置与发送范围说明，再执行快捷发送。
2. 文本选择保存实际摘录和文档页码；两期均仅支持单页选区，跨页时提示“请逐页选择并加入材料”。双栏选择预览实际阅读顺序，用户可取消误选。R2 图像框选先预览所选页区域及实际发送分辨率；只有文字模型时明确禁用图像发送，保留框选。
3. 提交前始终展示“本轮材料”和“前序对话范围”，用户可展开实际将发送的轮次和旧材料。新会话默认不带旧消息；从原文加入的证据须再显式确认。
4. 范围修改只作用于下一次请求。输入中的“本会话全部 2 轮”是清楚的数量，超容量不能静默截断；让用户选择最近若干轮、指定轮次或新会话。
5. 发送后新建不可变 turn 快照，用户问题显示所用材料与前序轮次数。聊天标题由首个问题派生并可修改。应用不提前声称模型已连通；连接检测和真实请求结果单独呈现。
6. 生成时逐段显示，Markdown / 列表 / 代码 / 公式可读；公式渲染失败时保留原始公式文本。用户向上滚动后不强行拉到底部，出现“有新内容 ↓”。停止按钮替换发送按钮。停止或断流的未完成回答不进入后续默认历史。

### 5.2 从回答到卡片（S04 → S05 → S06，PR04 / PR05）

```text
AI 只读回答：…适用条件需要同时关注证据相关性与覆盖率。[1]
[复制] [重新生成] [整理为卡片 ▾]
                         整理整条回答 / 整理选中的片段

← 返回对话                 卡片草稿             待保存
标题  [相关证据是检索增强有效的前提                  ]
正文  [核心观点、适用条件、限制……                  ]
来源  论文依据：1 条（引用可定位，观点待核查）
      相关对话：问题 + 原始回答 + 片段与上下文
AI 修订 [突出适用条件，压缩到 120 字                ]
        [生成修订建议] → 建议预览 [应用修改] [取消]
                              [保留草稿] [加入卡片]
```

- 整条 / 片段是生成草稿的输入选择。片段保留原始消息 ID、段落、前后文、原引用和所用范围；截取出的片段不能自动获得整条回答全部论文的“直接支持”。
- 原生文本选择后提供“整理所选片段”；键盘入口打开可选择段落的对话框。没有片段时不启用片段动作，并说明“请先选中回答中的文字”。
- 一条草稿聚焦一个观点；默认标题、正文可编辑。AI 自动补出“适用条件 / 限制”是建议结构，不强制复杂表单。无直接论文引用可保存，显著显示“仅对话来源 · 待核查”。
- “AI 修订”不直接覆盖当前稿：先显示独立建议，用户点击“应用修改”后替换正文；保留应用前的本地版本，允许撤销本次应用。生成期间用户如继续编辑，应显示“基于较早版本，正文已变化”，提供比较或重新生成，不能写入陈旧结果。
- 形成草稿、修订建议、正式卡片三者是不同内容；任何编辑都不回写原始 AI 回答。再次整理同一条回答可产生新草稿，入口先提示已有未完成草稿并允许继续或另建。
- 保存前运行引用完整性检查。只检查来源存在、属于该 turn 的允许范围、页码与快照关联正确；不把此检查包装为“AI 观点正确”。含无效结构化引用时阻止 AI 整理入库，展示具体错误。原始回答只读，用户可修复来源后重试；或复制到保留对话来源的人工卡片草稿，明确移除无效引用后作为“仅对话来源 · 待核查”保存，不能静默降级。
- “加入卡片”是确认动作：创建全局卡片、关联当前研究及必要论文，完成后提示“已加入『检索增强，何时有效？』”；链接能立即找到卡片。重复点击同一保存操作只创建一张。
- 放弃草稿需要明确动作；只返回、切模式或关闭面板会保留。关闭浏览器时依赖本地缓冲恢复；草稿持久化失败显示“保存失败，内容已保留”，允许重试 / 复制。

### 5.3 双来源回查（S06 → S07，PR06）

```text
卡片：相关证据是检索增强有效的前提
来源
  论文依据  [1] 自制研究材料 · PDF 第 3 页
             “Retrieval improves…relevant.” [查看原文]
  相关对话  2026-10-16 10:42 · 证据相关性与覆盖率
             从回答第 2 段整理 [查看问答]

右侧来源子视图：
← 返回卡片                         查看当时的问答
当时问题 / 原始回答（高亮整理片段）
[展开前后文] [本次材料与模型] [继续此对话]
```

- 论文入口默认在右侧显示 PDF 对应页、摘录与高亮；卡片留在主区。PDF 已在主区时仍遵守此规则，可通过“在主区定位”显式更新主区。完成后返回恢复原阅读位置。
- 对话入口定位到准确 turn 并高亮被整理的片段；不是仅打开会话首页。用户可展开前后文、当次证据、前序消息范围、模型与时间。
- 论文来源用于核对事实；对话来源用于回顾解释。UI 不把模型自己的话当作论文摘录。卡片正文被人工修改后，来源仍可查，但显示“正文已修改，请核对来源与表述是否一致”。
- 只有对话来源的卡片保留“仅对话来源”标识；用户可以解除“待核查”，但不能通过解除状态移除来源事实标签。它的历史上下文可能包含论文，但间接存在的材料不自动升级为卡片的直接论文依据。
- 原文文件缺失时保留标题、PDF 页码、摘录、hash 与缺失提示；可重新导入原文件匹配 hash。导入另一版本新建资产，不自动覆盖原来源。
- 会话 / turn 归档后，卡片已引用快照仍可读；“继续此对话”先恢复会话再打开输入。卡片来源不能指向后来重生成的回答。
- 结论插入卡片时保存使用时的来源快照，导出不从以后已变化的卡片正文反推依据；外部 Markdown 附必要问答摘录，不默认公开全部对话。

### 5.4 历史、重新生成与异常（S08 / S09，PR03 / PR07）

| 动作或异常 | 反馈与保留 | 下一步 |
| --- | --- | --- |
| 新建对话 | 新会话、无历史；原输入 / 草稿留在原会话。需要彻底排除旧材料时明确推荐此动作 | 用户重新选择本轮证据 |
| 归档会话 | 从默认列表移入已归档；不破坏卡片引用 | 已归档列表查看 / 恢复 |
| 重试失败请求 | 使用原问题、原材料和原前序消息快照；显示“按原提交范围重试” | 保留失败与重试关系；不使用当前面板新材料 |
| 重新生成 | 仅最新一轮提供入口；展示当前范围摘要，用当前范围产生新记录，原问答保留 | 后续默认使用新完成版；旧卡片来源仍指向旧版。更早轮次只可查看或复制到新会话 |
| 用户停止 / 连接中断 | 保留已输出部分、标“未完成”；不允许 AI 整理入库 | 原快照重试；可复制文字后人工新建卡片并标来源 |
| 完成后引用失效 | 原始回答只读，标出失效引用；禁用 AI 整理入库并解释原因 | 修复来源后重试，或复制到保留对话来源的人工草稿，明确移除无效引用后标待核查 |
| 模型未配置 | 不隐藏阅读与手工建卡；保留问题和证据 | 进入待开发的模型连接设置，完成后返回 |
| 保存失败 | 错误贴近保存按钮，保留正文；状态 `error` | 重试；失败也能复制草稿 |
| 刷新 / 恢复 | 恢复研究、阅读位置、会话滚动、输入、草稿；中断生成显示未完成 | 继续编辑或按原快照重试 |
| 切换研究 | 新研究恢复自己的状态；原请求仍归原研究 | 原研究完成标记可返回查看 |

## 6. 键盘、焦点与可访问性

- 发送快捷键 `Ctrl/⌘ + Enter`；默认 Enter 换行。输入法组合输入时不触发发送；不劫持 PDF 文字复制。快捷键提示持续可见。
- Esc 首先关闭最上层菜单 / 选择浮层 / 区域模式，再关闭抽屉；不丢草稿。关闭后焦点返回触发入口。新建会话保留原会话后将焦点置于输入框。
- 框选除鼠标拖动外提供“键盘选区”：当前页按百分比编辑左 / 上 / 宽 / 高、预览及确认。对话片段有按段选择入口，不能只依赖鼠标浮层。
- 面板调宽支持拖动和键盘方向键，标明最小 / 最大值；窄屏覆盖抽屉 `role=dialog`、标题、关闭按钮、焦点约束与背景 inert。
- 消息区是可聚焦的日志；逐字输出不每字播报，按段节流播报，完成 / 停止 / 错误播报一次。到达新回答和返回旧锚点分别有可感知提示。
- 生成、复制、卡片保存等异步动作有 `role=status`；错误用 `role=alert`。图标有文字或 accessible name，引用按钮读出文档与 PDF 页码。
- 内容与边框按 WCAG AA 的普通文字、非文本对比目标验收；缩放 200% 不让保存和关闭入口离开可用区域；减少动态效果偏好下关闭打字动画和滚动动画。

## 8. 原型评审范围与验收对照

[prototype.html](prototype.html) 不请求外部网络、不写生产 localStorage / IndexedDB，仅在内存演示。它是产品设计的交互证据，不能当作生产功能完成证据。直接打开 HTML，或通过项目静态服务器访问 `/docs/ai-reading/prototype.html`。

| 需求 | 原型评审路径 | 生产验收仍需完成 |
| --- | --- | --- |
| PR01 原文选择 | “选取示例段落”或拖选论文文字 → 向 AI 提问 → 看到材料条目 | PDF.js 文本层、双栏顺序、跨页拒绝与逐页添加、真实缩放与证据定位 |
| PR02 多轮聊天 | 输入问题 / 示例提问 → 模拟回答 → 追问；调整历史范围 | 真模型、流式协议、Markdown / 公式渲染、容量控制 |
| PR03 历史 | 历史 → 搜索 / 打开 → 新对话 → 返回历史 | 持久化、排序、归档生命周期 |
| PR04 整理 | 完整回答 → 整条整理；或选片段 / 按段选择 → 整理片段 | 真实模型提炼、片段定位与结构化引用 |
| PR05 编辑确认 | 修改标题 / 正文 → AI 修订建议 → 应用修改 / 恢复上一版 → 加入卡片 | 草稿版本与错误缓冲落库、原子创建 |
| PR06 双来源 | 卡片 → 论文依据 / 相关对话 → 右侧预览 → 返回 | 稳定 ID、hash、当次快照、真实 PDF 高亮 |
| PR07 恢复隔离 | 场景菜单 → 模拟断流 / 保存失败 / 恢复提示；切换会话保留输入 | 真实刷新恢复、研究切换请求隔离、重启恢复 |
| PR08 模型请求 | 固定显示“模拟回答”；无任何真实模型请求 | 真实配置、安全调用边界、模型元数据与实测 |
| PR09 区域框选 | 切换“区域框选 · R2”→ 拖动示例图 / 一键框选 → 加入材料 | 真 PDF 图像截取、图像模型、尺寸容量、坐标持久化 |
| PR10 生命周期 / 导出 | 仅在来源面板说明已引用快照保留，原型不模拟导出 | 归档 / 缺失来源 / Markdown 导出包含来源与必要对话摘录 |

原型简化：论文是项目自制 HTML 样例而非 PDF；只提供预设中文回答和逐段输出；手工选区不代表生产文本层实现；区域图像是页面内示意；引用可定位提示是预设状态，片段的直接引用关联仅按样例段落示意；一次保留一份草稿，已有草稿时引导继续或明确放弃，不静默覆盖。前序对话范围显示计数和选择器，没有完整请求检查器。不包含真实模型设置、完整公式编辑、研究切换、生产持久化、导出、跨页选择和完整归档后台。原型的“模拟恢复”只说明目标体验，真实浏览器刷新会重置。

视觉与可点击检查应分别记录 1440×900、1280×800、1024×800；截图覆盖 S02 选区 / S04 回答、S05 草稿、S07 来源与窄屏抽屉。生产阶段还应补做“主区白板＋右侧原文”“主区结论＋右侧 AI”，原型以当前阅读闭环为主，不把原有白板和结论重复实现一遍。

# 一次性发布 Papertrail v0.1.6

## 决策

用户要求直接完成新版安装包的公开发行。应用来源固定为已合入 main 的 `ef5f104abee792daf836d3e00c411bcb8f035b71`，版本固定为 `v0.1.6`。PR #20 的 CI #46 与该 main 提交的 CI 均已成功；本机 0.1.6 的 16 项打包桌面检查、DMG 校验和 DMG/ZIP 内容比对通过。

只在 `codex/publish-v0.1.6` 临时分支运行一次维护任务。它创建或核对固定 tag，调用 main 上现有的 `release.yml`，等完整发行运行成功后，下载该运行的三个平台产物，复用现有 `prepareAssets` / `updateDraft` 核对八个附件、大小和 SHA-256，最后公开为 Pre-release。main、应用源码和常规发行工作流不修改。

## 理由

当前 GitHub 连接缺少 dispatch / Release 写工具，浏览器的页面读取、导航和截图连续超时。临时分支使用已有仓库权限执行用户明确授权的维护工作，不提取或新增个人凭据。工作流通过显式的 Contents API 写入；若 GitHub App 没有 Workflows 权限则停止，不通过其他接口绕过。

先建立固定来源 tag，再 dispatch main，避免将版本错误地标到维护脚本提交。现有发行流水线仍重跑完整 CI 与三个原生平台的打包应用验证；不复用另一提交的临时产物代替该门槛。父任务使用独立并发组，避免等待中的子任务被同一锁阻塞。

## 但

维护任务需要临时 job 的 `contents:write` 和 `actions:write`。它只接受本仓库、该临时分支的 push，所有发行标识均固定。模型密钥、研究目录及用户 PDF 不参与任务。公开动作必须经过确定性代码校验；任何来源、运行身份、产物或校验和不匹配都会中止。

当前仍是未签名技术预览。新版安装器的人工作业、系统信任提示、干净环境及升级资料保留未作为本次通过项；真实模型成功回答未验证，前次 GLM 冒烟返回 429。

## 评审与验证范围

| 层面 | 核验点 |
| --- | --- |
| 职责 | 只公开固定版本，不建立后续自动发布规则 |
| 工具 | 原发行脚本复用；GitHub API 固定仓库；凭据不写日志 |
| 控制流 | 新运行必须唯一匹配原 workflow、main、固定 SHA 和 dispatch；整条运行成功后才公开 |
| 上下文 | 来源与材料固定；helper 文件不进入应用 tag |
| 可观测性 | Actions 保留子运行 ID、来源、验证结果和公开 URL；凭据不记录 |

新测试覆盖运行匹配/歧义、失败或运行中拒绝公开、错误来源与附件拒绝写入，以及已公开版本不修改。执行命令为 `node --test .github/scripts/release.test.mjs .github/scripts/publish-preview-once.test.mjs`；实际退出码由提交前检查及 Actions 的 Verify release controls 步骤记录。工作流已通过 YAML 解析和分支、权限、固定来源及 checkout 不留凭据的机械检查。

## 撤销与收尾

公开前取消维护任务会停止公开步骤；原发行运行即使继续，也只生成草稿。异常不自动删除 tag、草稿或附件。公开后不自动撤回用户已取得的版本。

GitHub REST 删除分支不支持原子的 SHA 比较与删除，因此采纳独立审查建议，远端维护分支保留供审阅，不自动 DELETE。该任务只在指定分支的维护文件被明确推送时运行，没有定时或常驻任务；既有公开版本的重跑路径只读验证，不再写 Release。

公开 GET 复验后，本地切回 main、确认工作区干净且提交仍为固定来源，再移除本地维护分支；远端提交和 Actions 记录保留核验依据。实际触发与本地撤销凭据由对应 Actions 运行、最终远端查询及本地 Git 输出补充，不将计划写成已经演练。
